## 1. 现有事实与边界（先读这一节，再谈新页）

### F1 玻璃只在「用户设了背景图」时生效

全部玻璃规则挂在 `html[data-bg='image']` 下；没设背景图时 40+ 条规则**一条都不命中**，页面观感逐像素等于改前。新页因此必须保证**两种模式下都可读**，不能只对玻璃模式调样式。

- 事实来源：`redesign.css:7855-7874`（1.30.0 四层）、`redesign.css:7916-7932`（1.30.1 段头「本段不再出现任何透明度百分比」）。
- 背景层链路：`.app-bg-img`（`opacity: var(--bg-opacity, .32)` + `blur(--bg-blur, 8px)`）→ `.app-bg-dim`（`--bg-dim` 默认 0.42，浅色乘 0.67）→ 内容层（`z-index: --z-base-raise`）。见 `redesign.css:7806-7842`。
- 推论（对新一代页面的直接后果）：**文字压在 `.content-area`（玻璃薄底 `--glass-canvas`，仅 10% 不透明）上等同于压在图上**，浅色主题下 `--text-2` 只有 **3.84:1**（见 §1.5），所以页头之外的正文一律进 `.pnl` / `.card2`，不要裸放在内容区。

### F2 玻璃 token 的取值与语义（不新增，只用）

**先纠个数**：`tokens.css` 3b 段实际是 **19 个唯一 `--glass-*` / 25 条声明**（12 个颜色 + 5 个 `--glass-blur-*` + `--glass-saturate` + `--glass-overlay-shadow`；`[data-theme='light']` 再覆盖其中 6 个）。任务书与早期材料写「20 个」是粗算，**以本节清单为准**（`grep -c '^\s*--glass-[a-z-]*:' src/styles/tokens.css` = 25；按唯一名去重 19）。`--bg-opacity` / `--bg-dim` / `--bg-blur` / `--bg-accent` 是背景图本身的可调变量，**不属于**玻璃层，不要混进来。

### F3 容器 + 层叠上下文：门禁的口径，以及门禁管不到的那一半

- **硬规则 R2**（`tokens.css:89-95`）：容器类选择器（类名含 `toolbar` / `sidebar` / `panel` / `card` / `section` / `header` / `rail` / `shell`）**不要**同时出现 `backdrop-filter|filter|transform|contain` 与 `z-index` —— 那几个属性会新建层叠上下文，写在同一选择器上的 `z-index` 变成「容器内部的天花板」。
- **门禁实际判据**（`scripts/check-stacking.js:18-35`）：**同一规则块**里既有 `z-index`（含 `var(--z-*)`）又有四件套之一 → 失败；容器类关键词表 `CONTAINER_WORDS` 在 `check-stacking.js:48`。
- ⚠️ **门禁只拦「同块」**。`redesign.css:7857-7874` 的 1.30.0 规则给 `.sidebar` / `.pnl` / `.entry-card` / `.modal` 加了 `backdrop-filter`（**该块内没有 z-index**，所以门禁放行），而 `.sidebar` / `.main-content` 的 `z-index` 写在另一块（`redesign.css:7845-7846`）。结论：**在背景图模式下，`.pnl` 事实上就是层叠上下文**。后果有两条，写进新页实现约束：
  1. `.pnl` 内部的自定义浮层（绝对定位下拉）层级被关进 `.pnl`，一定低于 `.toolbar`（`--z-toolbar: 20`，`redesign.css:241-258`）→ 表现为「下拉被工具条/表头盖住」；
  2. `.pnl` 基础规则还有 `overflow: hidden`（`pages.css:1534-1537`），浮层**先被裁掉**，根本轮不到层级问题。
  → **新页的下拉浮层一律放在 `.pnl` 之外**（`.pg` 或 `.toolbar` 里），或者直接用原生 `<select>`（浮层由系统绘制，不受 CSS 层叠与裁剪影响，`redesign.css:7989` 只保证 trigger 一致）。
- `.toolbar` 基础规则自带 `position: relative; z-index: var(--z-toolbar)`（`redesign.css:241-258`），**绝不能加 backdrop-filter**（`redesign.css:7947-7954` 的注释就是那次事故的记录）。

### F4 「实底上的 blur 是死效果」——现存一处真实死效果

`.tbl th` 无条件带 `backdrop-filter: blur(6px)`（`pages.css:1630`），而它的底色是 `color-mix(--bg-input 55%, transparent)`；叠加在不透明父级上时 blur 只模糊一层近乎纯色，肉眼无差别 —— 这就是「实底上的 blur 是死效果」。它留着有两个原因：表头是 sticky（需要自己的层，`--z-table-head: 10`），且 1.30.1 段明确「只有 th 与浮层菜单可以加模糊」（`redesign.css:7928-7931`）。

→ 新页**不要**再给任何容器加模糊来「追玻璃感」：背景图的模糊已经在 `.app-bg-img` 上做过一次，容器只负责半透明底色。

**判据（写死，新页照此执行）**

1. 正文（≤15px）压玻璃：**只允许 `--text-1`、`--text-2`**。全表最小值 `--text-2` = 4.62（浅色 `.glass-side`，最暗图）。
2. `--text-3` **禁止**用于玻璃上的正文 / 表格内容 / 说明文字：浅色最差 3.05–3.98，五处不过 4.5。改用 `--text-2` + `--fs-xs(11.5px)` 表达层级，不要靠继续压暗颜色。
3. `--glass-canvas` 上不放正文（浅色 t2 只有 3.84）——正文进 `.pnl`。
4. 大字（≥18px 或 ≥14px 粗体）与图形（图标/色条/边框）按 **3:1**：语义色压 `.pnl` 的实测最差 3.21（浅色 `--warn`）、3.69（深色 `--bad`），可用作图标与色条，**不可**用作 12px 以下文字。
5. 深浅两套都要过；「深色原本就不达标」不能当成放过的理由（`redesign.css:8228-8230` 就是这么处理表头的）。

### F6 三道门禁能证明什么、不能证明什么

| 门禁 | 口径 | 能证明 | **不能证明** |
|---|---|---|---|
| `scripts/ui-glass-opaque-scan.js` | 背景图模式下遍历可见元素，`backgroundColor` 的 **alpha ≥ 0.999 且面积 > 600 px²** 即失败；深浅两套各扫一遍；白名单条目必须写 `why`（`ui-glass-opaque-scan.js:10-31`、`:145-191`） | 新页**没有大块实底** | ① hover / focus / 禁用态（扫描不悬停）；② 没进 `PAGES` 列表的页面 —— **0 违规可能是假绿**（`ui-glass-opaque-scan.js:218-262` 写明了 `min` 自证计数）；③ 对比度（算不出像素） |
| 同脚本的 `TARGETS` | 锚点要求目标元素的 `computed backgroundColor` 与探针解析出的 `var(--glass-*)` **逐字符相等** | 背景**确实来自那条玻璃规则**，而不是「碰巧也半透明」 | 规则是否**正确**（选错 token 也绿） |
| `scripts/check-stacking.js` | 同一规则块里「容器类 + z-index + backdrop-filter/filter/transform/contain」→ 失败；放行需 `stacking-allow:` 注释或 `ALLOW` 数组写理由（`check-stacking.js:18-56`） | 不会写出「下拉被关进容器」这种确定命中的形态 | 跨规则块的同元素组合（F3 的 `.pnl` 就是靠这一点绕过的） |

**因此新增页面时必须同时做三件事**（进验收，不靠肉眼）：① 把新页加进 `PAGES` 并写 `min` 自证计数（否则空页面 0 违规）；② 做一次**变异验证**（注释掉一条玻璃规则 → 扫描必须变红），否则「门禁在跑、一条没拦」（`ui-glass-opaque-scan.js:20-26` 的教训）；③ hover / 焦点 / 禁用态用人工走查（见 §8 走查清单）。

## 3. 页面骨架（4 页统一，逐字照抄结构）

```
<Page>                         → .pg（max-width 1480，padding 22 28 36，gap --d-gap）
  <PageHead icon title desc tools />   → .pg-head / .pg-title / .pg-sub / .pg-tools
  <div className="tabs" role="tablist"> → .tabs（透明底，无玻璃登记）
    <button className="tab2 is-active" role="tab" aria-selected>…</button>
  </div>
  <div className="toolbar">    → .toolbar（内置 --glass-side + --z-toolbar）
     …筛选 / 目录 / 主操作…
  </div>
  <Panel title=… meta=… collapsible> … </Panel>   → .pnl/.pnl-head/.pnl-body
  <Pager … />                  → .pager
</Page>
```

**为什么页签容器不用 `.toolbar`**（三条，任何一条都足够）：
1. `.toolbar` 的 `padding: var(--d-toolbar-py) 24px` + `border-bottom` + `min-height` 是「动作区」的量身尺寸（`redesign.css:241-248`），套在页签上会把 8 个页签撑成一条 60px 高的带子，页签自身的 30px 高度失去意义；
2. `.toolbar` 被赋予 `--z-toolbar: 20`（必须压住吸顶表头 `--z-table-head: 10`，`redesign.css:249-256`）——它就变成了「一个永远压住表格的层」，页签容器不需要这个层级，纯属给后续浮层埋雷；
3. `.pm-main .toolbar` 还有一条卡片化覆盖（`pages.css:1873-1880`：`--bg-card` + 边框 + 阴影），会让页签条看起来像一张卡片。**页签进 `.tabs`，动作进 `.toolbar`，两者不混。**

## 5. 页签形态：复用 `.tabs` + `.tab2`（结论）

**结论：直接复用，不新做、不封装新组件、类名一个都不改。**

理由（四条，按优先级）：
1. **回归脚本按文字点，锚点是 `.tab2`**：`scripts/shots-summary.js:207`（`.tabs .tab2` + `textContent.includes`）、`scripts/shot-audit-ui.js:142`、`scripts/ui-cases-test.js:312`（`.cases-sheet-tabs .tab2`）。换类名 = 这些脚本静默点不到（历史已踩：1.32.3 的 `prep` 点不到按钮但返回值被丢弃）。要新页可回归，**必须**是 `.tab2`。
2. **现有 5 个页面已经这么用**：`PasswordManagerPage.tsx:71`、`NotesAttachments.tsx:80`、`ZentaoPage.tsx:924`、`Cases.tsx:1101`，容器都是 `.tabs` + `role="tablist"`，子项 `.tab2` + `.is-active`。新页跟着走，视觉自动一致。
3. **`.tool-tabs` 是历史遗留**：`grep -r "tool-tabs" src/` 只命中 `pages.css:4817-4842` 四条 CSS，**没有任何 tsx 调用点**（工具箱 1.11.0 后改成了 `.tb-rail` 竖排）。用它等于复活一套死样式。
4. **玻璃是白送的**：`html[data-bg='image'] :is(.btn-secondary, .ibtn, .tab2)`（`redesign.css:7973`）特异性 (0,2,1) 高于 `.tab2`(0,1,0) 与 `.tab2:hover`(0,1,1)，所以背景图模式下所有页签自动拿到 `--glass-control` 药丸底；激活态靠 `color: var(--accent)` + `::after` 下划线 + `font-weight: 620` 区分（`pages.css:1703-1711`），依然成立。

无障碍（照抄既有实现，别只写 `onClick`）：
- 容器 `role="tablist"` + `aria-label`；按钮 `role="tab"` + `aria-selected` + `tabIndex`（选中 0、其余 -1）；面板 `role="tabpanel"` + `aria-labelledby`。
- 方向键 / Home / End 切换（工具箱已有 `onTabKeyDown` 范式，`Toolbox.tsx:1527-1553`）。
- 页签切换**必须保状态**：新页 8 个页签全部用 `useToolState` 同款做法（`sessionStorage` 按页面 + 页签命名空间），否则「切一下页签输入就没了」是必有反馈；契约 §4.3 也把它列进「不改动清单」的复用项。

**页签容器禁止用 `.toolbar`**：理由见 §3（三条）。

## 6. 「确定 / 启发式 / 无法判定」的视觉区分（不靠颜色）

### 6.1 三类（+ 一类反向）的文案与图形

`redesign.css` / `ui.tsx` 只有一个 `Pill`（`ui.tsx:180-191`）与 `.chip`，**都不够用**：`Pill` 的 `pill-*` 是「语义色文字 + 13% 同色底」，压玻璃上对比度不够（见 6.2），`.chip` 没有语义。所以定义 `.dev-tag`，四态各配「图标 + 固定文案 + 语义色条」。

| 语义 | 类 | 图标（`@tabler/icons-react`，已确认存在） | **固定文案**（不可只留颜色） | 颜色落点 | 用在哪 |
|---|---|---|---|---|---|
| 确定（正向） | `.dev-tag.is-ok` | `IconCircleCheck` | `确定` / 矩阵里用 `已覆盖` | 左 3px 条 + 图标 = `--ok` | 覆盖矩阵 covered、规则「确定命中」 |
| 确定（反向/失败） | `.dev-tag.is-fail` | `IconCircleX` | `未覆盖` / 体检里 `命中` | 左条 + 图标 = `--bad` | 覆盖矩阵 missing、体检 blocker |
| **启发式** | `.dev-tag.is-heur` | `IconAlertTriangle` | `启发式命中` | 左条 + 图标 = `--warn` | 体检 findings（全部） |
| **无法判定** | `.dev-tag.is-unknown` | `IconHelpCircle` | `无法判定` | 左条 + 图标 = `--info` | 覆盖矩阵 unknown、Git 非仓库等 |

三条硬约束：
1. **文字色一律 `--text-2`**，不用语义色写文字（6.2 的实测）。语义色只出现在「3px 左边条 + 14px 图标」这两个图形位（3:1 门限）。
2. **图标 `aria-hidden="true"`**，语义由文案承担（读屏不会读「绿色圆圈」）；`title` 只放解释，不放结论。
3. **页面级必须有常驻说明**：CodeAudit 顶部 `.dev-banner.is-info` 写「启发式检查，非语法树分析，可能误报；只在本机展示，不写日志、不进导出」（`[C-17]`、方案 R2）。这句话是「启发式」这个标签能被正确理解的前提。

### 6.2 为什么不用 `.pill-*`（实测/推算数）

`.pill-*` 的底是 `color-mix(in srgb, <语义色> 13~14%, transparent)`、文字是语义色本身（`pages.css:190-208`）；`pill-info` 特殊：字是 `--accent`、底是 `--accent-light`。压 `--glass-card` 上按真实定义算：

| 主题 / 背景图 | `pill-ok` | `pill-warn` | `pill-bad` | `pill-info`（accent 系） |
|---|---|---|---|---|
| 深色 + 白图 | **3.74** | **4.38** | **3.21** | **2.83** |
| 深色 + 黑图 | 4.90 | 5.77 | **4.17** | **3.67** |
| 浅色 + 白图 | **4.17** | **3.73** | **4.36** | **4.41** |
| 浅色 + 黑图 | **3.11** | **2.78** | **3.24** | **3.25** |

12.5px 的标签文字要 4.5:1：**浅色两套背景图下四态全部不达标；深色 + 白图同样全部不达标**，只有「深色 + 黑图」的 ok/warn 两项过线（bad 4.17、info 3.67 仍差）。`pill-info` 还多一层不稳定 —— 它取 `--accent`，而 accent 有 6 套可选档（`redesign.css:967-979`，teal/indigo/blue/green/amber/rose），深色默认是 indigo `#6366f1`，换档就是另一组数。

改用 `.dev-tag`（文字 `--text-2`）后，最差仍为 4.62（浅色 `.glass-side`），四态同一条判据、与 accent 档无关。
另外 `.pill-mute` 是 `--bg-input` **实底**（`pages.css:210-214`），在背景图模式下就是一块实心白片，与扫描门禁直接冲突。

### 6.3 表格 / 列表里的三态怎么排

- 状态列放在**最后一列之前固定位置**（不参与横向滚动），列宽 96–110px，`white-space: nowrap`。
- 同一行有多个结论时（如 covered + 启发式）**只用 `is-ok`**（结论优先），启发式证据放该行的辅助列（`--text-2` 文案「启发式」），避免一行挂两个标签造成"两个结论"的误读。
- 计数条上永远给**分母**：`已覆盖 128 / 400`、`无法判定 12（均附原因）`。禁令（方案 R3）：**禁止只给百分比**。

## 10. token 硬约束与新增样式落点

### 10.1 token：新增 **0** 个

现有 19 个 `--glass-*` 已覆盖 4 个新页的每一类容器（§4 的落点列已逐条对上）。**刻意不用**的 3 个也说明理由：

- `--glass-blur-*`：新页**不加任何 backdrop-filter**（F3/F4）。模糊只在 `.app-bg-img`（背景图本身）与 `.pnl`（1.30.0 既有）上出现。

### 10.2 新增类名：3 个（4 + 3 个修饰，合计 21 条选择器），全部背景 transparent

因此**不进** `html[data-bg='image']` 的 `:is(...)` 登记表 —— 登记表的作用是「把实底换成玻璃底」，而 `.dev-tag` / `.dev-banner` / `.dev-scroll` 没有底可换；硬塞进去反而会引入 40–52% 的底色，把 F5 的对比度结论推翻。**这一条要写进实现任务的验收说明，避免 reviewer 按"新类必须登记"机械打回。**

反过来说，**将来真需要一个带玻璃底的容器类**时（例如某个新页要做自己的侧栏卡），登记方式只有一种，见 §10.6 模板：追加到 `redesign.css` **末尾** 的 `html[data-bg='image'] :is(...)` 新块里，**不改 1.30.1 段的中间列表**（那是历史收敛结果，改动会让 `check-css-dup` 的同名选择器计数与级联同时变化）。

## 11. 验收口径（可直接贴进 W7 的视觉验收）

1. `html[data-bg='image']` 下 4 个新页**无**「alpha ≥ 0.999 且面积 > 600 px²」的块，深浅两套各一遍（`scripts/ui-glass-opaque-scan.js`）；扫描前把 4 页加进 `PAGES` 并写 `min` 自证计数（至少：页签数、表格行数、KPI 卡数各 ≥1）。
2. **变异验证**：注释掉一条玻璃规则（如 `.busy-progress` 的 A2）→ 扫描必须变红。绿了说明门禁没盖到这页。
3. `node scripts/check-stacking.js` 绿（新页不得引入「容器 + z-index + backdrop-filter」同块写法）。
4. 对比度：新页所有正文（≤15px）压玻璃 ≥ 4.5:1，大字/图标/色条 ≥ 3:1；深浅两套各量一次，记录「文字 rect 四周 2–26px 窄带」的最差像素（口径同 1.32.1）。**`--text-3` 出现在玻璃上的正文即判不通过。**
5. 三态标签：抽 3 行截图，去掉颜色（灰度）后**仍能区分**（文案 + 图标在，就说明没只靠颜色）。
6. 帧时间不退化：8 页签逐个切换，`performance` 面板帧时间 ≤17ms（基线 60fps）；玻璃常驻面积不随行数增长（仅容器级玻璃）。
7. 密度档 `compact` / 默认 / `cozy` 各扫一眼：无写死行高导致的错位。
8. 键盘：页签 Tab/方向键/Home/End 可达；`.dev-scroll` 内表格可 Tab 到行内按钮；焦点环 2px 可见（`:focus-visible` 已有全局规则 `redesign.css:53-56`）。

## 12. 附录 A：B / C 案的代价（本期**不做实测**，仅备查）

用户已定 **A 案**。下面两案只在有人重新提「毛玻璃要一直有」时拿出来对照，**本文不为其背书**。

| 案 | 内容 | 代价（按仓库现状推演） | 触发前提 |
|---|---|---|---|
| B | 玻璃**全模式常驻**（不依赖背景图） | ① 40+ 条 `html[data-bg='image']` 规则要改写成无条件规则，与 `pages.css`/`global.css` 的 263 个重复选择器的级联要重新求值（`AGENTS.md` 已记录该级联很脆）；② `.pnl` / `.sidebar` / `.entry-card` / `.modal` 的 `backdrop-filter` 从"偶尔存在"变成"永远存在"，是**大面积常驻 GPU 合成**，必须实测帧时间与显存（基线 60fps/17ms）；③ 无背景图时玻璃底下是纯色，blur 是死效果（F4），等于白付成本；④ 对比度要按"玻璃压在纯色画布上"重算一遍，`--text-3` 的边界可能整体下移 | 先做性能 + 对比度实测，再决策 |
| C | 系统级 acrylic（Win11 `backgroundMaterial`）/ 无边框透明主窗口 | ① 主窗口现在是**标准窗口**（有系统边框、`sandbox: true`），只有搜索小窗与便签是 `transparent: true` + `frame: false`（`electron/main.js:1520-1537` vs `:1079-1086`、`:1187-1194`）；② 改透明要重做拖拽区、标题栏、阴影、最小化到托盘、窗口状态恢复（`docs/agents/window-tray.md` 全篇）；③ Win10 无 acrylic 会退化成半透明，双平台观感分叉；④ 双屏/远程桌面下 acrylic 常见失效 | 仅当明确要「真·系统毛玻璃」 |

**A 案的代价（已接受）**：新页只在用户设了背景图时才有玻璃观感；不设背景图时是实心卡片。换来的是「零新增 token、零新增玻璃规则、两道门禁现成」。

## 13. 附录 B：对比度推算的可复现口径

```
canvas_dark  = #0d0f10 ; canvas_light = #f7f8fa        (tokens.css:15 / :224)
dim_dark     = #05070a @ 0.42                          (redesign.css:7824-7828)
dim_light    = #ffffff @ 0.42*0.67 = 0.2814            (redesign.css:7839-7842)
image        = 0.32 opacity 的纯白 / #808080 / 纯黑      (redesign.css:7819)

backdrop = blend(dim, dimAlpha, blend(image, 0.32, canvas))
comp     = blend(glassBase, glassAlpha, backdrop)      (每个 --glass-* 的 base/alpha 见 §1 的 F2 表)
ratio    = (max(L1,L2)+0.05) / (min(L1,L2)+0.05)       (WCAG 相对亮度, sRGB)
```

说明两点，避免误读：
1. 这是**上界推算**（把整块背景图当成单一纯色）。真实照片在同一页面上有明暗，实测往往好于推算，但仓库两次实测（表头、分页条）都印证了「玻璃 + 背景图会把小字逼到 AA 边缘」这个方向，所以按上界做设计决策是安全的。
2. 实机取证仍以既有脚本为准：`scripts/ui-glass-opaque-scan.js`（结构性）与 `.reviews/**/tools/contrast-tight.js`（像素级，注意它只按十进制三元组解析，`color-mix` 算出的 `color(srgb …)` 会被读成近黑 —— `redesign.css:8240-8244` 记录过这个假红）。
