## 1. 「五处 page key 同步」：规则与判据

### 1.1 事实：4 个文件、5 张注册表

页面 key 在这 5 张表里以**字符串字面量**重复出现，TypeScript **一条都管不到**（`currentPage` 是 `useState('home')`，类型是 `string`），所以拼错/漏删的表现是「点开落到密码库」或「入口永不可达」且**不报错**。这就是必须有机械门的原因。

| # | 文件 | 注册表（符号） | 基线位置 | 抽取规则 | 集合名 |
|---|---|---|---|---|---|
| 1 | `src/components/Sidebar.tsx` | `GROUPS` | `:221-265` | 块 `const GROUPS` … 到 `];` 之间，`/\{\s*id:\s*'([^']+)'/g` | **S**（侧栏入口） |
| 2 | `src/pages/loaders.ts` | `PAGE_LOADERS` | `:12-44` | 块 `export const PAGE_LOADERS = {` … 到 `} as const;`，`/^\s{2}([A-Za-z_$][\w$]*):\s*\(\)\s*=>/gm` | **L**（懒加载器） |
| 3 | `src/pages/loaders.ts` | `PAGE_ALIAS` | `:49-56` | 块 `const PAGE_ALIAS` … 到 `};`，`/^\s{2}([A-Za-z_$][\w$]*):\s*'([^']+)'/gm` | **ALIAS**（旧路由→真页） |
| 4 | `src/App.tsx` | `renderPage()` 的 `switch` | `:484-525` | 块 `const renderPage = () => {` … 到 `default:`，`/^\s*case '([^']+)':/gm` | **A**（可渲染） |
| 5 | `src/components/CommandPalette.tsx` | `PAGES` + `PAGES_MORE` | `:43-53` / `:80-93` | **分别**定位 `export const PAGES: … = [` … `];` 与 `export const PAGES_MORE: … = [` … `];` 两个块，块内 `/\{\s*page:\s*'([^']+)'/g` | **P**（命令面板） |

**第 5 处为什么必须块定位（实测反例）**：该文件 `:38` 的 `KIND_LABEL` 映射里有 `page: '页面'`，对整文件跑 `page:` 正则会多出第 20 个「页面 key」并让 R6 直接变红。基线实测：全文正则得 P=20（含 `页面`），块内得 P=19。

基线实况（供实施者首次自证，已按上表规则实测）：**S=17 / L=20 / A=23 / P=19 / ALIAS=3**（`jsonConverter→toolbox`、`accounts→passwordManager`、`snippets→sqlSnippets`）；R1–R6、R10 全通过，R9 导航字面量 105 处、越界 0 处。
收敛后（B8 完成时）期望：**S=12 / L=16 / A=19 / P=15 / ALIAS=3**（B5 合并侧栏两项为一项但**保留 `codeGen` / `codeAudit` 两个 key 共用一个 chunk**，见 §3.5 与附录 A-7；`PAGE_ALIAS` 不新增）。

### 1.2 另外 3 处「会在别处再长出来」的地方（不属于五处，但必须知道）

| 位置 | 形态 | 由谁兜住 |
|---|---|---|
| `src/App.tsx:23-49` 的 `const X = lazy(PAGE_LOADERS.<key>)` | 依赖 `PAGE_LOADERS` 的**属性名**，是 TS 强类型 | `npm run typecheck`（删 loader 不删 lazy 常量 → TS2339，直接红）。**所以它是第六处，但已被门覆盖，不需要脚本** |
| `src/pages/Home.tsx:746`、`src/components/ZentaoSummary.tsx:489`、`src/App.tsx:445`、`src/components/CommandPalette.tsx:227` 的导航字面量（`go('…')` / `requestNavigate('…')` / `setCurrentPage('…')`） | 纯字符串，TS 不管 | 本文 §2.2 的「追加源」（导航字面量扫描） |
| `scripts/ui-glass-opaque-scan.js` 的 `PAGES[].nav` 与 `label` | 中文**文案**（不是 key），点侧栏按文案 | 该脚本自己的 `min` 自证 + 每批「被删页面的标签命中数 = 0」断言（§3） |

### 1.3 判定规则 R1–R10（每条都是可判真假的集合断言）

记 `aliasKeys = keys(ALIAS)`。

| 编号 | 断言 | 违反后的真实故障 |
|---|---|---|
| R1 | `S ⊆ L` | 侧栏有入口但没有 loader → 无悬停预取（且通常是「页面确实不存在」的第一征兆） |
| R2 | `S ⊆ A` | 点侧栏落到 `default` → 停在密码库，**不报错**（最沉默的缺口） |
| R3 | `L ⊆ A` | 有懒加载器但没有 case → 预取了 chunk，点开仍落 `default` |
| R4 | `A \ L == aliasKeys`（**双向**） | 多一个 case 无 loader 且不在别名表 = 旧路由伪装成真页；**少**一个 case（别名表有键、`A` 里没 case）= 老 `localStorage.currentPage` 不走别名而落 `default`，语义与「别名」承诺不符 |
| R5 | `∀k ∈ aliasKeys: ALIAS[k] ∈ L` | 别名目标不是真页面 → 预取白跑 + 渲染落 `default` |
| R6 | `P ⊆ A` 且 `P ⊆ L` | 命令面板里能搜到、点开是错页 |
| R7 | `P ⊆ S ∪ {home, settings, attachments}`（弱断言，仅作提示，不判红） | 面板里有侧栏没有的入口是既有的（`attachments`），只用于人工复核 |
| R8 | `A` 里必须存在 `default: return <PasswordManagerPage />` | 老用户 `localStorage.currentPage='recorder'` 会白屏（方案 §7 R7） |
| R9 | 导航字面量集合 `N ⊆ A ∪ aliasKeys` | `Home` 快捷入口点开落 `default` |
| R10 | 每张表内部无重复键 | 同名 key 后写覆盖前者，前一条静默失效 |

### 1.4 **明确不检查**的四条（防止实施者「顺手修」出别的问题）

| 编号 | 不检查的关系 | 为什么不检查 |
|---|---|---|
| N1 | `S ⊄ P` | 「录制器不在命令面板列表里」是既定现状（方案 §3.1）；要求 `P ⊇ S` 会逼实施者新增面板条目 |
| N2 | `L` 可以大于 `S` | `home` / `settings` 没有侧栏项；`attachments` 在面板里但不在侧栏 |
| N3 | `aliasKeys ⊄ S` | 旧路由本来就没有入口 |
| N4 | 中文 `label` 与页面 `<PageHead title>` 不必逐字相同 | 除 B5 的「代码工具」外，本文不对文案设门（文案门由玻璃扫描的 `min` 自证负责） |

### 1.5 机械核对命令


## 2. `scripts/check-pages.js` 判据

### 2.1 输入（严格 4 个文件 + 1 个目录级追加源）

| 序 | 输入 | 解析 | 失败即违规 |
|---|---|---|---|
| 1 | `src/components/Sidebar.tsx` | 定位 `const GROUPS` 到其后第一个 `];`，块内取 `id: '…'` | 块找不到（文件被重构）也算违规，不许静默跳过 |
| 2 | `src/pages/loaders.ts` | 定位 `export const PAGE_LOADERS = {` 到 `} as const;`，块内取 `key: () =>` | 同上 |
| 3 | `src/pages/loaders.ts` | 定位 `const PAGE_ALIAS` 到 `};`，块内取 `key: 'target'` | 同上 |
| 4 | `src/App.tsx` | 定位 `const renderPage = () => {` 到 `default:`，取 `case '<key>':` | 同上 |
| 5 | `src/components/CommandPalette.tsx` | 分别定位 `export const PAGES: { page: string; label: string }[] = [` … `];` 与 `export const PAGES_MORE: { page: string; label: string }[] = [` … `];` 两个块，块内取 `{ page: '<key>', label: '…' }`（理由见 §1.1 第 5 处的实测反例） | 同上 |
| 6 | 追加源：`src/**/*.tsx`（排除 `**/__tests__/**`） | 取 `/(?:go|onNavigate|requestNavigate|setCurrentPage)\s*\(\s*'([^']+)'/g` 的字面量 | R9 |

**解析硬要求**（这 4 个文件的注释与映射表里就有 `case '…'`、`page: '页面'` 之类的示例文本，全文正则会误命中）：

- 必须**先定位块、再在块内正则**，不允许对整文件跑 `case '` / `id:` 正则。
- 不允许引入新依赖（只用 Node 内置 `fs` / `path`），不允许起 Electron、不允许 `import` 任何 `src/` 模块。
- 注释剥离不是必须的（块定位已足够），但**如果**实施者选择剥离，需在 `--self-test` 里加一条「含注释示例的 fixture」用例。

### 2.2 判定与退出码

```
exit 0  全部断言通过，stdout 至少两行：
        ✓ page keys  sidebar=12 loaders=16 cases=19 palette=15 aliases=3
        ✓ R1–R10 全通过（导航字面量 105 处，越界 0）

exit 1  任一断言失败，前缀 ✗ 的逐条明细 + 末行：✗ 共 N 处不一致
        示例：✗ R2 sidebar→render  recorder 在 Sidebar 但 App.renderPage 无 case
              ✗ R4 case→loader     assetLedger 有 case、无 loader，且不在 PAGE_ALIAS
```

（上例是 B8 完成后的期望值；基线跑 `--explain` 应得 `sidebar=17 loaders=20 cases=23 palette=19 aliases=3`。计数行必须由脚本自己算出来打印，**不允许**写死在脚本里。）

「非空即 exit 1」的含义：**违规清单非空就 exit 1**；清单为空才是通过。不允许出现「有 ✗ 但 exit 0」，也不允许出现「无输出 exit 1」。

### 2.3 允许的例外（只有一套：旧路由别名）

| 例外 | 允许形态 | 判据 |
|---|---|---|
| E1 | 某个 key 有 `App.renderPage` 的 `case`、**没有** `PAGE_LOADERS` 条目 | 仅当该 key 在 `PAGE_ALIAS` 里；否则 R4 红。**反向也要求**：别名表里的每个 key 都**必须**有 case（R4 双向） |
| E2 | 别名目标 `ALIAS[k]` 只出现在 `PAGE_LOADERS`，没有 `case` | **不允许**（R5 + R3 各红一次），别名目标必须是真页面 |
| E3 | 别名 key 出现在侧栏 / 命令面板 | **不允许**（R2 / R6 会红）——旧路由不得有新入口 |

> 既有代码就是这么做的：`jsonConverter` / `accounts` / `snippets` 三个旧路由在 `App.tsx` 里**都保留了 case**（`:490` / `:494` / `:499`），而 `notes` / `attachments` 两个 key 共用一个 chunk（`loaders.ts:20-23`）。B5 沿用后者：**保留 `codeGen` / `codeAudit` 两个 key 与两个 case，都指向同一页**（§3.5），因此 `PAGE_ALIAS` 一条都不新增。

除 E1 外**不存在其他白名单**。禁止引入 `IGNORE_KEYS`、`LEGACY_ALLOW` 之类的第二张表：第二张表 = 第六处需要同步的注册表，与本文目的冲突。

### 2.4 CLI 与自测

| 参数 | 行为 |
|---|---|

- 判据：`Select-String -Path scripts/check-pages.js -Pattern "recorder|assetLedger|resultHub|weeklyReport|codeGen"` 在自测 fixture 块之外命中数 = 0。
