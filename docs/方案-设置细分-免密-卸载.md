## 2. R1 设置页细分（5 → 7）

现状（`Settings.tsx:54-60`）：`security` / `data` / `appearance` / `tasks` / `about`。
`appearance` 一个 tab 里塞了主题、强调色、密度、自定义背景、不透明度、浏览器路径、快捷键、托盘——一屏十几屏高，是「再细分」的真实痛点。

目标：

| 新 tab id | 名称 | 收纳 |
|---|---|---|
| `security` | 安全 | 主密码、安全词、自动锁定、剪贴板、**启动免密（R2）** |
| `appearance` | 外观 | 主题、强调色、密度、自定义背景、图片不透明度、**玻璃强度/透明度（R4）** |
| `interaction` | 交互 | 浏览器路径、全局快捷键、托盘与窗口、防截屏 |
| `data` | 数据与备份 | 原样 |
| `tasks` | 定时任务 | 原样 |
| `about` | 关于与更新 | 原样 |
| `danger` | 危险区 | **卸载软件（R3）**、清空遗留数据、重置数据目录 |

硬约束：
- `LEGACY_TAB_MAP` 必须补 `general/browser/shortcuts → interaction|appearance` 的落点，且 `normalizeSettingsTab()` 对未知 id 回 `security`；否则历史 `localStorage['pm.settings.tab']` 会让 `switch` 落空 → 白屏（项目已踩过）。
- `SETTINGS_TAB_KEY` 不换名，只扩取值范围。

## 3. R2 启动免密

### 3.1 存储与威胁模型

- 落盘：`<数据目录>/autologin.json`，内容 `{ v:1, blob: base64, updatedAt }`，`blob = safeStorage.encryptString(masterPassword)`。
- Windows 上 `safeStorage` 走 DPAPI，绑定「当前 OS 用户」，拷到别的机器/别的用户下解不开 → 不是明文密码。
- `safeStorage.isEncryptionAvailable() === false` 时**整个开关禁用并说明原因**，不降级成明文。
- 必须在 UI 明写代价：*任何能登录本机该账号的人都能直接打开本应用*。

### 3.2 IPC 契约（新增 4 个，全部 `{ success, data?, error? }`）

| channel | 入参 | 出参 |
|---|---|---|
| `auth:auto-unlock-status` | 无 | `{ enabled: boolean, available: boolean, reason?: string }` |
| `auth:enable-auto-unlock` | `{ password }` | `{ enabled: true }`；密码错 → `{ success:false, error:'主密码不正确' }` |
| `auth:disable-auto-unlock` | 无 | `{ enabled: false }` |
| `auth:auto-unlock` | 无 | `{ unlocked: boolean, password?: never }` — 主进程内部完成 `session:unlock`，**绝不把明文回传渲染层** |

### 3.3 失效时机（必须实现，漏一条就是安全洞）

- `auth:change-password` 成功后 → 删 `autologin.json`
- `auth:reset-password` 成功后 → 删 `autologin.json`
- 数据目录迁移 / `data:reset-location` 后 → 删
- 用户点「锁定」（`session:lock`）→ **本次进程内不再自动解锁**，直到下次启动
- `auth:auto-unlock` 解密失败 → 删文件 + 返回 `unlocked:false`，不得卡在启动态

### 3.4 启动时序

`src/App.tsx` 挂载时：`authIsSetup()` → 若已 setup，先查 `auto-unlock-status`，`enabled` 则调 `auth:auto-unlock`，成功直接进 Dashboard，失败落回 Login。**渲染层拿不到明文密码**。

## 4. R3 卸载软件

### 4.1 IPC 契约（新增 2 个）

| channel | 入参 | 出参 |
|---|---|---|
| `app:uninstall-info` | 无 | `{ supported, mode: 'installed'\|'dev', uninstaller: string\|null, dataDir, dataSize }` |
| `app:uninstall` | `{ removeData: boolean }` | `{ launched: boolean, error?: string }` |

### 4.2 行为

- `mode:'installed'`：从注册表 `HKCU|HKLM\...\Uninstall\*` 里按 `DisplayName`/`InstallLocation` 匹配本应用取 `UninstallString`，spawn 之；`removeData` 为真时先删数据目录再 spawn。
- `mode:'dev'`（开发目录起）：**不 spawn**，只按 `removeData` 清数据目录，返回 `launched:false` 并给出「源码目录需自行删除」的文案——不许在这里递归删源码目录。
- 删数据前必须二次确认，且二次确认文案里带**实际数据目录绝对路径 + 体积**。
- 卸载流程中不做写盘、不做 `app.quit()` 抢先退出（交给卸载器）。

### 4.3 UI

`danger` tab 卡片：
1. 第一层确认：「卸载软件」→ 弹框问「是否同时删除本地缓存数据？」三选：仅卸载程序 / 卸载并删除数据 / 取消。
2. 第二层确认（选删除数据时）：显示数据目录与体积，输入确认。
3. 卸载中禁用按钮，结束后提示。

## 5. R4 玻璃效果与透明度核对（可判定）

三个新界面都要在 `html[data-bg='image']`（自定义背景开启）下核对：

- 只允许 `background: var(--glass-*)`，**禁止**新写死 `rgba()` 半透明值（`tokens.css:96` R3 条）。
- **禁止**给 `.toolbar` / 卡容器加 `backdrop-filter`（会新建层叠上下文把内部下拉关在容器里，`redesign.css:7947` 明确警告）。
- 检查清单：设置 rail（`.set-rail`）、`.set-nav` 选中态、卸载弹窗（`.modal`）、卡片 `.entry-card`、`cred-account` 行，在深色/浅色 × 无背景/有背景 = 4 组下都不出现「文字与背景同色」或「面板边界消失」。
- 量化门：`ui-quality-gate` 的 `ui-geometry`（重叠/溢出/裁切/越界/点击目标/字号）+ `ui-detect`（设计规则）🔴 清零；存量红必须给 `--waive` 三数。

## 6. R5 卡片账号显示不全

现状：`global.css:963` `.cred-account { max-width:120px; overflow:hidden; text-overflow:ellipsis; }`，JSX 侧（`EntryCard.tsx:268-281`）没有 `title`。

改法：
- `.cred-account` 改弹性：`flex: 1 1 auto; min-width: 0; max-width: 60%`（跟 `.cred-password-wrapper` 争宽时不把密码挤没）；保留 ellipsis。
- JSX 补 `title={entry.username || '--'}`，长账号悬停可看全文。
- 验收：40 字符账号（如 `884048177@qq.com` 加长版）下标 ① 卡片不横向溢出、② 密码列仍完整可见、③ `title` 是完整账号、④ 1280/1440/1920 三个断点各看一次。
