**不做什么（写死，后续不得当遗漏补回）**

- ❌ MySQL **直连与执行**（备份、还原、清库、读表结构）：`mysql2` 不引入、不连库、不执行。**2.3 的降级形态在范围内**——只生成 SQL 模板与风险提示，见上表 2.3 行（这也是「13 项」= 12 项落地 + 2.3 降级形态的来历）。

- ❌ SQLite / 独立后端服务 / Faker / FreeMarker·Jinja2（见 §10 ADR）。
- ❌ 静态体检做「提交拦截」：只做手动触发。

## 3. 数据契约（vault 集合）

**新增 5 个集合**，加进 `electron/vault-schema.js` 的 `VAULT_COLLECTIONS`，同步 `src/types.ts` 的 `WorkspaceKey`。

**`VAULT_SCHEMA_VERSION` 从 3 bump 到 4，并新增 `MIGRATIONS[3] = v => v` 恒等迁移**（2026-11-24 修正，原方案写的「不 bump」是错的）：

- 只考虑「新应用读旧库」时确实不用 bump——`normalizeVault` 会给缺失键补 `[]`；
- 但反过来「**旧应用读新库**」会静默丢数据：`vault-schema.js:192-197` 只在 `ver > VAULT_SCHEMA_VERSION` 时才保留未知字段。不 bump 时旧版（3）读到 ver=3 不满足该条件，5 个新键被丢弃并随保存写死；
- bump 到 4 之后，旧版读到 ver=4 会命中 `future` 分支原样保留，这是版本机制本来就要解决的问题；
- 配套单测：断言 `VAULT_SCHEMA_VERSION === 4`、`MIGRATIONS` 有 `3` 这一步、以及「库版本高于当前版本时保留未知键」。

| 集合 | 归属 | 结构（关键字段） |
|---|---|---|
| `pomPages` | 1.2 | `{ id, name, baseUrl, elements: { name, locator, kind: 'css'\|'xpath'\|'text'\|'role', note }[], updatedAt }` |
| `scanRuns` | 3 | `{ id, at, root, pack, files, truncated, counts: { blocker, high, mid, low }, findings: { ruleId, severity, file, line, snippet, message }[] }` |
| `coverageRuns` | 4.1 | `{ id, at, root, total, covered, missing, undetermined, items: { method, path, state: 'covered'\|'missing'\|'unknown', ref? }[] }` |
| `caseMaps` | 4.2 | `{ id, caseNo, caseTitle, target: { kind: 'file'\|'method', ref }, note, updatedAt }` |
| `allureRuns` | 5.1 | `{ id, at, root, total, passed, failed, broken, skipped, clusters: { key, count, sample }[], flaky: { name, runs, pass, fail }[] }` |

**复用不新增**：断言库用户自定义片段进 `codeSnippets`（加 `kind: 'assert'`，与 `notes` 的 `kind='sql'` 同模式）；内置断言种子走静态 TS 常量，不落库；2.1 生成的 `.jmx` 直接进已有脚本库（`jmxlib.json` + `jmxlib:import`/`meta-set`）。

> ⚠️ **键名以本表为准，W1 实现任务的 acceptance 会机械核对这 5 个键**。原因：`ws:get` 对未知键返回空数组、`normalizeVault` 会丢弃未知键，键名写错是**静默失效**而不是报错。现有 15 个集合键全是复数，所以 4.2 用 `caseMaps` 而不是 `caseMap`。

## 4. 接口契约（IPC）

**约定**：一律 `{ success, data?, error? }`；主进程新建 4 个域、扩展 2 个域；每个新通道必须同步 `preload.js` + `src/types.ts` + 通过 `node scripts/check-ipc-contract.js`。

> **契约冻结（2026-11-24）**：`docs/契约-本地测试资产工作站.md` 已到 **v6（805 行 / 108 条款 / 1..108 连续）**，经 5 轮修订收敛（bump 遗漏、键名单复数、parseJtl 结构冲突、错误文案双真源、模块缺行、批次拓扑、历史可观测性）。**W2 起所有实现按 v6 写**；再发现契约不可执行时一律「先改契约再改代码」，不得代码与契约各说一套。

**新增通道合计 15 条**（scan 5 / git 2 / allure 2 / tdg 4 / jmeter 1 / jmxlib 1），契约检查基线最终应从 **206/204/224/224 → 221/219/239/239**（handler / preload 调用 / 暴露方法 / 类型声明），缺少任何一处都会红。

> **分阶段到达（2026-11-24 裁决 A，含 11-24 二次修正）**：W1 只接 **13 条**（scan 5 + git 2 + allure 2 + tdg 4）→ **219/217/237/237**；`jmeter:analyze-jtl` 随 W2-A、`jmxlib:create-batch` 随 W3 在自己的文件里补齐到 221/219/239/239。不授权 W1 去改 `ipc-jmeter.js` / `ipc-jmxlib.js`（契约 C-47：新域文件只注册自己的通道）。

| 通道 | 入参 | data | 性质 |
|---|---|---|---|
| `scan:pick-root` | — | `{ dir }` / `canceled` | dialog 选目录 |
| `scan:rules` | — | `{ packs: { id, label, rules: { id, severity, title, desc }[] }[] }` | 只读，供 UI 列规则 |

**安全边界**：**只读命令白名单**（`rev-parse`/`status --porcelain`/`diff --name-status -U0`/`log -1`），参数由主进程拼装，不接受渲染层传任意参数；`GIT_TERMINAL_PROMPT=0`；超时杀进程；不执行任何写命令（`commit`/`push`/`checkout`/`stash` 一律无通道）。

### 4.4 新域 `electron/ipc-tdg.js`（模块 2.2 流式导出）

| 通道 | 入参 | data | 性质 |
|---|---|---|---|
| `tdg:write-start` | `{ savePath, format: 'csv'\|'json'\|'txt' }` | `{ writerId, path }` | 创建文件（覆盖） |
| `tdg:write-append` | `{ writerId, rows: string[] }` | `{ rows, bytes }` | 追加一批 |
| `tdg:write-finish` | `{ writerId }` | `{ path, rows, bytes, ms }` | 落盘收尾（fsync） |

### 4.6 扩展 `electron/jmx-script.js` + `electron/ipc-jmxlib.js`（模块 2.1）

| 通道 | 入参 | data |
|---|---|---|
| `jmxlib:create-batch` | `{ rel, plan }`（`plan: { name, interfaces: { name, method, url, headers, body }[], threads, loops, thinkTimeMs, csvFile?, csvVars?, assertCode? }`） | `{ rel, path, interfaces, bytes }` |

纯函数 `buildJmxFromPlan(plan)` → `.jmx` 文本；生成后必须过 `inspectJmx` 再落盘（校验失败直接报错，不写半成品）。

**CSV 参数化路径策略（2026-11-24 定）**：写**相对路径**，并把 CSV 在生成时复制进脚本库（与 `.jmx` 同目录）。理由是脚本库会随人换机，绝对路径换个目录就废。配套三条缺一不可：

1. 生成时复制 CSV 进脚本库，JMX 里写相对路径（相对 JMX 所在目录）；
2. 应用内 spawn jmeter 时把 `cwd` 设为 JMX 所在目录（**假设（待确认）**：相对路径按 JMX 目录解析，这条靠验收兜住）；
3. 落盘前校验 CSV 可解析，解析不到直接报错、不写半成品。

**验收方式（可证伪）**：把整个脚本库复制到另一个目录后重跑，仍成功才算通过——不是「文件生成了」。

## 6. 生成器规范（所有 codegen 共用，验收硬要求）

1. **golden 文件比对**：`src/utils/__tests__/__golden__/<generator>/<case>.{java,txt}`，输入固定 → 输出逐字一致。
2. **转义必测**：引号、反斜杠、中文、`${}`、换行、超长标识符 —— 生成的代码必须语法合法。
3. **可验证**：Java 生成物用 CodeLab 的 `javac` 编译一次（无 JDK 时降级为语法自检并在报告里标「未编译验证」）。
4. **不产出半成品**：生成失败 / 校验失败直接报错，不落文件。

### 12.2 因此 4 个新页的硬约束（写进实现与验收）

1. **只用 `--glass-*`**，不新造 token、不写透明度百分比；新类名必须登记进 `redesign.css` 末尾的 `html[data-bg='image'] :is(...)` 列表，样式只在 `redesign.css` 末尾追加。
2. **不给容器加 `backdrop-filter`**（连 `filter`/`transform`/`contain` 一并不加），否则 `check-stacking.js` 红、下拉菜单会被关进容器。
3. 新页面必须过 `ui-glass-opaque-scan.js`（深浅两套），且**必须做一次变异验证**（注释掉一条玻璃规则 → 扫描变红），否则只是「门禁在跑、一条没拦」。
4. 文字压玻璃上仍需 **≥ 4.5:1**（正文）/ 3:1（大字与图形）；「启发式/无法判定」这类结论不能只靠颜色区分。
5. 帧时间不退化：玻璃常驻的面积越大越费 GPU，仓库基线是 60fps / 17ms。
6. **`.pnl` 在背景图模式下已经是层叠上下文**（1.30.0 给它加过 `backdrop-filter`，而 `check-stacking.js` 只判「同一规则块内 容器 + z-index + 四件套」，所以放行），并且它还带 `overflow: hidden`。→ **新页面的下拉浮层/弹层不能放在 `.pnl` 内部**，否则必被裁切或被工具条盖住；要么放到 `.pnl` 之外，要么直接用原生 `<select>`。这条进 W4–W6 实现约束。
7. **三态标签不用 `.pill-*`**：压玻璃实测最差 **2.78:1**（浅色两套背景图 + 深色亮图全部 < 4.5），且 `.pill-mute` 是实底（会直接扫红）。改用 `.dev-tag`：文字用 `--text-2`（实测 ≥ 4.62），语义色只落在 3px 左条与图标上（≥ 3.21）。
8. **页签复用现有 `.tab2` 按钮 + 现有容器类，不要改名**：回归与截图脚本按 `.tab2` 的 textContent 点，改类名会静默点不到；容器不能用 `.toolbar`（尺寸 + 被赋 `--z-toolbar:20` + `.pm-main .toolbar` 卡片化）。
9. **已知瑕疵 K1（不修）**：玻璃模式下激活页签的底不够深。修它要动 5 个既有页面，收益低于回归成本，登记为已知瑕疵，交付说明里写明。
