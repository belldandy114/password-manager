## 三、已知限制

1. **免密依赖 Chromium profile 稳定**：safeStorage 的 key 存在 `%APPDATA%\测试中台\Local State`，不在数据目录里。手动清理应用数据、换 Windows 账号或换机器 → 免密失效，应用会自清凭据并落登录页（表现为需要重新开启，不是报错）。
2. **首次开启后若强杀进程可能失效一次**：`Local State` 尚未落盘时 key 会重生成。正常退出后再强杀不影响已存在的 key。
3. **深色主题 + 接近纯白的背景图存在物理上限**：半透明玻璃底被抬到中灰（约 `#8a8d8f`），此时任何浅色文字都到不了 4.5:1（纯白理论上限约 2.9:1）。这是「深色 + 亮图」的物理上限，不是配色问题；缓解手段是设置里既有的「图片不透明度」「压暗」两个旋钮。
4. **浅色主题 + 极暗图是对称的同类问题**。同理，把「图片不透明度」拉到 0.45 且「压暗」压到 0.1 时，light 副标题实测会掉到 **3.77:1**（低于 4.5）。这同样是物理上限而非配色缺陷——玻璃底被极亮/极暗的背景图推到中灰段时，任何单一方向的文字色都无法同时满足两级文本；此时应回调那两个旋钮，而不是继续改色值。
5. **对比度结论绑定测试基准图**（`buildResources/icon.png`，不透明度 45%、压暗 10%）；换图后需用同一脚本复测。
6. **`ui-detect`（设计门）本次为 ⚪**：它只吃 URL/文件/目录，Electron 渲染层没有 preload 进不了主界面，扫到的登录页是假绿。本次只跑了几何门，未做 mock 预览桩（做桩会让设计门结论本身失真）。
7. **9 条验收项为 ⚪（端到端未覆盖）**：安全词重置、目录迁移、safeStorage 不可用真实分支、`--glass-strength` 单调性、白块扫描、组件级长账号单测等。均在 `docs/验收-设置细分-免密-卸载.md` §10.13.4 逐条写明「为什么没覆盖 / 风险 / 补法」。
8. **3 条为 ⚠️ 部分覆盖**：AU-10（v:2 版本不支持）、AU-11（非法 JSON）已有 4+4 条纯函数单测（含「导出面无 unlink/rm/write」的能力面证明），只缺端到端重启验证。
9. **`glassStrength` 调节器本期未做**（契约 §10 LATER-L1）：用户第 4 条是「检查」不是新增可调项，已拆为后续建议。
10. **自动解锁成功时 `settingsGet`/`applyTheme` 会跑两次**（幂等，代价可忽略），未去重。
