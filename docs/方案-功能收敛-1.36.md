# 功能收敛方案（1.36.0）

> 决策来源：用户 2026-12 裁定。原话要点：**保留压测、周报、SQL 片段、工具箱（24 个）、用例库、代码调试、代码生成、代码体检（去掉 Git 影响面）；结果中心的 `.jtl` 解析转移到压力测试内**；其余（录制器、资产台账、结果中心壳 + Allure 解析）去掉。存量数据按「**删入口不删数据**：集合保留、页面下线、留只读导出」。
>
> 本文只做方案与影响面，**不含任何代码改动**。审批后再分批实施。
>
> **修订记录**：§1–§8 为首版；**§11 是第二次修订定稿**（加入收敛判据、周报下线、代码体检降级、元素库 `kind=pw`，分批重排为 8 批）。**与首版冲突处以 §11 为准**，首版保留供对照。

### 3.6 回归脚本 `scripts/ui-glass-opaque-scan.js`（**不改造就会假绿**）

现状：36 个扫描组合 = 4 个开发辅助页 × 2 页签 + 录制器 × 2 页签，每个组合 4 处登记（`PAGES` / 锚点 `ANCHORS` / `READY_PRED` / `APPLIED_PRED` + 签名），还有录制器专用的 `DROP_LAMPS` hack 与 `devSeed` 写 4 个集合。

改造后应为 **3 个单元**：代码生成 × 2（OpenAPI / 元素库）、代码体检 × 1（单页）。`.jtl` 指标迁到压测页后**不在该脚本的「新页」扫描范围内**（压测页是老页，不在 `DEV_PAGE_LABEL` 里）；若希望它也被覆盖，另开一轮，不在本方案里夹带。

同时删：`devSeed` 对 `coverageRuns` / `caseMaps` / `allureRuns` 的造数、`rec*` 三项自证、`DROP_LAMPS` 整段。

## 4. 数据与存储（删入口不删数据）

| 集合 | 原消费者 | 删后处理 |
|---|---|---|
| `pomPages` | 录制器 + 代码生成（元素库） | **保留且仍有 UI**：代码生成的「元素库 → POM」页签是唯一入口 |
| `uiRecordings` | 录制器 | 保留，无 UI（只读导出，见下） |
| `allureRuns` | 结果中心 | 保留，无 UI |
| `coverageRuns` / `caseMaps` | 资产台账（`caseMaps` 另被 Git 影响面读） | 保留，无 UI |
| `scanRuns` | 代码体检 | 保留且有 UI，不变 |

**关键结论（也是本方案最省事的一点）**：5 个集合键**全部仍在** `VAULT_COLLECTIONS` 里，所以

- **不需要 bump `VAULT_SCHEMA_VERSION`、不需要写迁移**；
- `normalizeVault` 不会把这 4 个集合当未知键丢弃 → 老库打开后数据还在，只是没有页面读；
- 回滚 = `git revert`，数据层零风险（没有「旧版应用把新集合写死成不存在」的坑，因为键本来就在清单里）。

**只读导出（用户已选）**：设置页「数据」tab 加一个「导出遗留数据」按钮 → 把 `uiRecordings / allureRuns / coverageRuns / caseMaps` 四个集合 + `schemaVersion` + 导出时间组成 JSON，走**既有** `file:save-text`（零新 IPC）。实测体积上限合计 ≤ 5.5 MB（`[C-24]` 的单集合上限之和），一次导出可接受。

## 8. 三个默认取值（本方案的假设，可直接推翻）

1. **Allure 解析整块删**（用户只明说了 `.jtl` 转移）。理由：Allure 报告自带 HTML 视图，且它的 flaky 分母 / 聚类口径是长期债。若想留，最小做法是只留「解析 + 计数表」并挂进压测页，代价是 `allureRuns` 与 8 种截断原因得继续养。
2. **`scan` 的 `coverage` 包一起删**（5 条规则）。理由：它是覆盖矩阵的取数端，页面没了就是死代码；不删则代码体检的包列表里会留一个永远没人选的「接口覆盖取数」。代价：`scan-rules.test.ts` 的「两包齐全 / coverage ≤ 8」断言要同步改。
3. **只读导出做成设置页一个按钮**（导出 JSON，走既有 `file:save-text`）。若嫌多，可降级为「不做，靠整库备份」，但那样 4 个集合的数据对用户就是「看不见也拿不出」。

## 9. 替代方案：粘贴导入 + 只读定位（用户 2026-12 提出，已采纳为后续建议）

> 起因：§7 R4 说「录制器删后元素库只剩手填」。用户提出「从外部录制拿到结果后粘贴进输入框 → 识别元素/定位器/样式 → 按页面路径打开网页定位到元素」。
> **结论：可行，且比手填好一个量级。** 它把录制器 11,050 行里真正有价值的那一小块（连页面读 DOM）留下，把贵的部分（事件注入、候选排序、会话状态机、值脱敏、停录触发源）全部扔掉。
>
> **修订（2026-12 用户裁定，覆盖 §9.6）**：① 三种粘贴格式**全支持 + 自动识别**；② 样式**连页面读真样式**（不是粘贴值）。定稿口径见 **§10**。

### 9.1 能力边界（先定死「能识别出什么」，否则就是拿假数据当事实）

| 粘贴来源 | 能拿到 | 拿不到 |
|---|---|---|
| **DevTools Recorder 导出的 JSON**（推荐，Chrome 自带） | `selectors[]`（css / text / role / xpath + offsets）、`target`、动作序列、`assertedEvents` | 样式、元素文本内容 |
| **Playwright `codegen` 生成的脚本** | `getByRole(role, {name})` / `getByText` / `locator(css)` / `fill` 的键名 | 样式；且定位器是 Playwright 语义，要映射到 `kind` 枚举 |
| **Elements 面板复制的 outerHTML** | tag / id / class / aria-* / **内联 `style`** | **computed style**（继承、外部样式表、伪元素都不在 outerHTML 里） |

**所以「样式」有一条硬边界：粘贴文本里没有真样式。** 要真值只有两条路 ——（a）连页面读 `getComputedStyle`（即 §9.3 的只读 CDP），（b）接受粘贴值并在 UI 上**显式标注「来自粘贴文本，未在页面验证」**。不允许把 (b) 渲染成和 (a) 一样的事实。

### 9.2 数据结构代价（**这是本方案唯一的 schema 改动**）

现状 `PomElementRow = { id?, name, locator, kind, role?, note? }`（`src/components/codegen/pomModel.ts:18`）—— **没有样式、没有来源、没有校验信息**。而 `cleanPageForWrite()`（同文件 `:127`）是**逐字段白名单重建**：新字段不加进白名单，保存一次就被静默洗掉（正是它注释里记的 `[C-110]` id 被洗白那次事故的同型问题）。

建议最小增量（全部可选字段，向后兼容）：

```
source?: 'paste' | 'recorder' | 'manual'   // 来源，表格一列
checkedAt?: string                          // 上次定位校验时间
hitCount?: number                           // 上次校验命中数：0 / 1 / n
styleSnapshot?: Record<string, string>      // 只存白名单键（≤8 个），标注来自何处
```

`hitCount` 是这套功能里**唯一有用的信息**：命中 0（选择器已失效）或命中 3（不唯一）都必须看得见，否则「定位」按钮就是安慰剂。

同步要改：`src/components/codegen/pomModel.ts`（类型 + `cleanPageForWrite` 白名单 + `blankElement`）、`ElementTable.tsx`（两列）、`pomModel.test.ts`（锁住「新字段不被洗掉」）。不新增集合、不新增 IPC，写入仍走 `ws:set('pomPages')` + `trimPagesForWrite`。

### 9.3 "按页面路径打开网页定位" 需要什么

| 需要 | 现状 | 增量 |
|---|---|---|
| 页面地址 | `PomPage.baseUrl` 已有（校验 `https?://`、≤500 字符） | 0 |
| 定位器 | `locator + kind` 已有 | 0 |
| 打开页面 + 高亮元素 | **无**（原能力在 `record:validate`，随录制器一起删） | **1 条只读通道** + `cdp-client.js`（保留） |

通道形状（本期只读、不注入、不持会话价值）：

- `el:probe { url, items: [{ kind, locator }] }` → `{ results: [{ kind, locator, hit: number, texts: string[], style?: Record<string,string> }] }`
- 主进程：复用 `cdp-client.js` 连 Chrome → `DOM.getDocument` → `DOM.querySelector` → `DOM.scrollIntoViewIfNeeded` + `Overlay.highlightNode`；`items ≤ 50`、单条 3 s、整次 10 s（沿用录制器算过的那组数字，`[C-114]`）。
- 鉴权：仍过 `pw()`（未解锁不给用），URL 走 `http/https` 白名单。**没有**事件注入、没有值回传，所以录制器那套「明文口令 / `valueMeta` / URL fragment 脱敏」全部不需要。

### 9.4 入口与识别口径

- 入口挂在**代码生成 → 元素库**页签的一个「粘贴导入」按钮上（弹窗：textarea + 识别预览 + 逐条勾选），**不新开一级页面**（那正是本次要收敛的模式）。

- 导入前不写库；预览里就能看到命中选择器与重复项。

## 10. B5 定稿：粘贴导入 + 一键定位 + 真样式

### 10.1 自动识别（三格式，判定顺序固定）

| 序 | 格式 | 判据（命中即停） |
|---|---|---|
| 1 | DevTools Recorder 导出 JSON | 能 `JSON.parse`，且 `Array.isArray(o.steps)`，首个 step 含 `selectors` 或 `type` |
| 2 | Playwright codegen 脚本 | 文本命中 `getByRole(` / `getByText(` / `locator(` / `page.` **任两条**（单条太松，一段注释里写个 `page.` 就会误判） |
| 3 | Elements 复制的 HTML | 含 `<` 且能用 `DOMParser` 解析出至少一个元素 |
| — | 都不命中 | 固定文案：「无法识别：支持 DevTools Recorder 导出的 JSON / Playwright codegen 脚本 / Elements 复制的 HTML」，**不写任何数据** |

- **必须在预览里显示「凭哪条特征认出来的」**：每行带 `confidence`（`exact` / `guess` / `unknown`）+ 一句 `reason`，单独一列、不折叠。
- 三种同时命中时按上表取先，预览顶部给一个下拉**允许手动改选解析器**（改选后只重解析，不重新识别）。
- Playwright → 内部映射：`getByRole('button', { name: '提交' })` → `{ kind:'role', role:'button', locator:'提交' }`（对上 `[C-28]`）；`locator('css')` → `kind:'css'`；`getByText` → `kind:'text'`。**拿不准的（`nth-child` 组合、`filter()`、`or()`）一律标 `guess`，不静默降级**。

### 10.2 样式：连页面读真样式

- 一条 invoke：`el:probe { url, items:[{kind, locator}], withStyle?: boolean }` → `{ results:[{ kind, locator, hit, texts, style? }] }`。
- 主进程链路：`cdp-client.js` 连 Chrome → `DOM.getDocument` → `DOM.querySelector` → `hit` / `texts`（`DOM.getOuterHTML` 截前 80 字符）→ 若 `withStyle`：`CSS.enable` + `CSS.getComputedStyleForNode(nodeId)`。
- **白名单只 6 键**：`display / visibility / opacity / pointer-events / width / height`。不加 `color / background-color`——测试断言很少读颜色，加了体积翻三倍。
- 值处理：`width/height` 取 px 整数；值里出现 `url(`（背景图）直接替换 `<redacted>`（URL 里可能带 token）；单值 ≤ 40 字符。
- 时效：每条写 `checkedAt`，表格显示「抓到 2026-12-01 14:02」，超 7 天标灰提醒重抓——**样式会过期，不标时间就是假数据**。

### 10.3 体积：本次真正的约束（不是代码量）

`pomPages` 单集合上限 **512 KB**（`collectionTrim.ts` 的 `COLLECTION_CAPS.pomPages`），而 `trimPagesForWrite` 超限时**按时间丢最旧的页面**。样式把库撑爆 = 用户的页面整页消失，这是不可接受的失败模式。所以写死预算并进单测：

- 每元素 `styleSnapshot` ≤ 6 键、序列化后 ≤ 600 B；
- **只有用户显式点「抓样式」的元素才写**（粘贴导入默认 `withStyle:false`，不自动抓）；
- 每页带样式的元素 ≤ 16 个 → 单页 ≤ ~10 KB → 512 KB 可容 ~50 页，仍在 200 页上限内可用；
- 兜底：`trimPagesForWrite` 的 `dropped > 0` 时页面必须走既有 `trimNotice` 提示，并追加一句「样式占用较大，可清理样式快照」。**不许静默丢页面。**

> 真超过 50 页带样式再谈把 `pomPages` 提到 2 MB（要同步 `TOTAL_COLLECTION_BYTES` 的 7.5 MB 分配与契约 §1.2）——**本期不动这个数字**。

### 10.5 安全面（比录制器小，但必须写清）

- 通道过 `pw()`（未解锁不给用）；URL 只收 `http/https`。

### 10.7 验收（四条可判定）

1. 三种格式各粘一次 → 预览条数 = 识别出的元素数，每行 `confidence` 与 `reason` 非空。

| `getByPlaceholder("x")` | `.getByPlaceholder("x")`（同名） |
| `getByRole('button', { name: 'x' })` | `.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("x"))` |

| 侧栏一级入口 | 17（4 组） | **12**（1+5+2+4） | −5（删周报/录制器/资产台账/结果中心 + 合并代码生成与代码体检） |
| `src` + `electron` 行数 | 99,700 | ≈ **80,700** | −20,590（删）+ ~1,600（B6/B8）≈ **净 −19,000** |

| 单测文件 | 126 | 114 | −12 |

### 11.7 遗留数据：导出之外还要能清（§4 的补丁）

只读导出只解决“拿得出”，不解决“删得掉”。而 4 个空 UI 集合的真代价是：**每次 `saveVault` 都要全量序列化 + 加解密，备份 7 份 + 异地镜像也一直带着**（上限合计 5.5 MB）。

所以设置页那一处做两个按钮：
1. **导出遗留数据** → 4 个集合 + `schemaVersion` + 时间 → JSON（走既有 `file:save-text`，零新 IPC）；
2. **清理遗留数据** → **必须先导出成功**，再二次确认，只清 `uiRecordings / allureRuns / coverageRuns / caseMaps`；`pomPages` 与 `scanRuns` 有 UI，**永不清**。

### 11.8 这次仍然没解决的问题（诚实留档）

1. **判据只能挡“一级入口”，挡不住“给已有页面加一个页签”**——膨胀会从页面转成页签。防御：一个页面内页签 > 3 时必须写一条理由进 `AGENTS.md`。
2. **`pw` 是半可校验的**（见 §11.4 限制）：它保真、能生成，但应用内验不了命中。这比“降级成 css 假装能验”诚实，但仍是一处缺口。
3. **`caseMaps` 删 UI 后，“改了代码该跑哪些用例”这个答案在本应用里彻底没有了**——如果以后还想要，得连 Git 影响面一起回来，那时应做成独立只读脚本而不是页面。

## 12. 「运行元素库生成的代码」怎么落（B8 范围扩展）

### 12.1 先分清两件事，成本差一个量级

| 想校验什么 | 需要什么 | 应用内可行性 |
|---|---|---|
| **定位器对不对**（这个元素到底存不存在、是不是唯一） | 能连页面（CDP）或能跑 Playwright | **高**，见 12.2 |
| **生成的 Java 代码能不能编译/跑** | Maven 依赖树 + 浏览器驱动 + runner | **低**，见 12.4 |

### 12.2 校验定位器：两层能力

**第一层 `el:probe`（B8 已列）**：只认 `css / xpath / text / role`。`DOM.querySelector` 直接给命中数 + `scrollIntoViewIfNeeded` + `Overlay.highlightNode`。零外部依赖（只要 Chrome）。

**第二层 `el:trial-run`（本方案新增）**：给 `pw` 链用。做法是**产出临时 `.mjs` 并真跑一次**：

```js
// 元素库「试跑」临时产物（跑完即删，不进仓库、不进附件）
import { chromium } from 'playwright';
const browser = await chromium.launch({ headless: false });
const page = await browser.newPage();
await page.goto('<PomPage.baseUrl>');
const el = page.locator('div').filter({ hasText: /^审核结果全部通过不通过$/ }).getByPlaceholder('全部');
console.log('命中数', await el.count());
console.log('可见', await el.first().isVisible());
await el.first().click({ trial: true });   // 只做可操作性检查，不真点
await page.screenshot({ path: 'trial.png' });
await browser.close();
```

- **`trial: true` 是这套能力的关键**：Playwright 对 `click / dblclick / check / uncheck / hover / tap` 支持 `trial`，只跑可操作性检查（可见、稳定、可接收事件、未被遮挡）而**不触发点击**——试用时不会真点掉别人的数据。`fill` 没有 `trial`，只能校验 `count` 与 `isVisible`。
- 命中数、可见性、`trial` 的错误文案、截图一起回显；**截图存临时目录，不自动进加密库**（要留证据必须用户显式点「存到附件」）。
- 依赖：本机 `node` + `playwright` 包 + 浏览器。缺任一项给固定文案（照录制器 probe 的做法，但只需 **2 盏灯**：`node` / `playwright 包`），不静默失败。

**⚠️ 必须新增一个设置：`Playwright 工作目录`**
现在 CodeLab 的 JS 是 `node main.js`，且代码写在**临时目录**里（`codelab-args.js:84` 的 `tempDirName`），那里没有 `node_modules` → 直接跑必报 `Cannot find module 'playwright'`。
所以试跑脚本必须写到**用户指定的目录**（就是他装外部录制软件 / 有 `node_modules/playwright` 的那个目录，或者他自己工程根目录），在该目录下 `node <临时文件>.mjs`，跑完删。交互同「用例库 → 选择目录」：选一次、记住、可在设置里改。**不选就不给试跑**，提示「先指定 Playwright 工作目录」。

### 12.3 为什么不用 CodeLab 跑 Java（硬事实）

`electron/codelab-args.js:59-71` 的 Java 链路是：

```
javac <Main>.java          // 无 -cp
java -cp . <Main>          // 无 -cp
```

**没有 classpath 入口**。所以任何 `import com.microsoft.playwright.*` 的代码必然 `package com.microsoft.playwright does not exist`。要修得给 `buildRunPlan` 加"额外 classpath"参数，而用户还得自己去 `~/.m2` 里凑 playwright 的 jar 依赖树——**把工程依赖塞进单文件执行器，失败信息全是 classpath 噪音，比不跑更难排查**。

### 12.4 校验生成的 Java：不在应用内跑，给可粘的东西

还有一层更根本的问题：**元素库生成的是 Page 类（POM），不是可运行脚本**。`locatorExpr` 返回的是 `page.locator(...)` 表达式（`pageobject.ts:109-133`），要跑必须先有 `Playwright.create()` + `chromium.launch()` + `new XxxPage(page)`。

所以做法是**生成时一并给两段文本**（纯文本，零执行）：

1. **runner 骨架**（约 40 行，进 `GeneratedFiles` 预览）：

```java
// RunXxxPage.java —— 与生成的 XxxPage 同包，用来手工验证定位器
public class RunXxxPage {
    public static void main(String[] args) {
        try (Playwright playwright = Playwright.create()) {
            Browser browser = playwright.chromium().launch(new BrowserType.LaunchOptions().setHeadless(false));
            Page page = browser.newPage();
            page.navigate("<PomPage.baseUrl>");
            XxxPage p = new XxxPage(page);
            System.out.println(p.<元素方法>());   // 或 p.<方法>().count()
            browser.close();
        }
    }
}
```

2. **一行可粘命令**：`mvn -q exec:java -Dexec.mainClass=...RunXxxPage`（或直接告诉他放进工程、IDE 里点运行）。
   前置条件要写死：工程 `pom.xml` 需 `com.microsoft.playwright:playwright`，且首次跑要 `mvn exec:java@playwright-cli-install` 或 `mvn test` 时由 Playwright 下载 Chromium。

### 12.5 结论（B8 最终范围）

| 能力 | 做法 | 依赖 |
|---|---|---|
| 校验 4 种 kind 的定位器 | `el:probe`（CDP，命中数 + 高亮） | 只要 Chrome |
| 校验 `pw` 链 | `el:trial-run`（临时 `.mjs` + `node`，`trial:true` 不真点 + 截图） | node + playwright + 指定的工作目录 |
| 校验生成的 Java | **不在应用内跑**；生成时给 runner 骨架 + `mvn` 命令 | 用户自己的 Maven 工程 |

**不做的**：给 CodeLab 加 classpath、把 Maven 依赖搬进单文件执行器、把截图自动落进加密库。

### 12.6 定稿修订：只走 Playwright（覆盖 12.2 / 12.5）

**裁定**：`el:probe`（裸 CDP）**取消**，定位与试跑合并成**一条** `el:trial-run`，全部走 Playwright。因此 §10.4 的「保留 `cdp-client.js`」「抽 `chromium.js`」两项**撤回**，`record-probe.js` 整删（浏览器由 Playwright 管），`which.js` 仍留（`ipc-codelab.js:24` 在用，且试跑要用它找 `node`）。

**机制（点一次「定位/试跑」发生什么）**：

1. 主进程 `which('node')` 找到 Node → 在**Playwright 工作目录**写一个随机名临时 `.mjs`；
2. `node <临时文件>.mjs` 跑该脚本（`spawn` 不 `shell`，超时/失败杀进程树 `taskkill /PID <pid> /T /F`，复用 `ipc-codelab.js` 的做法）；
3. 脚本内：`launchPersistentContext(<profile 目录>, { headless: false, channel: 'chrome' })` → `goto(baseUrl)` + `waitForLoadState('domcontentloaded')`；
4. 逐个元素取 locator：`css` → `page.locator(sel)`；`xpath` → `locator('xpath='+sel)`；`text` → `locator('text='+sel)`；`role` → `getByRole(...)`；`pw` → **原链**；
5. 逐个算：`count()` / `isVisible()` / `click({ trial: true })`（只做可操作性检查，不真点）/ `screenshot()` / `highlight()`（headed 才有）；结果以 JSON 打到 stdout；
6. 主进程解析 JSON 回渲染层，删临时脚本；**profile 目录保留**（登录态要在）。

**入参/出参**：`el:trial-run { url, items:[{kind, locator, roleName?}], withStyle?, timeoutMs? }` → `{ results:[{ kind, locator, hit, visible, trial: 'ok'|'fail'|'skip', error?, shotPath?, style? }], ms }`。`items ≤ 50`，单条 3 s、整次 20 s。

**两个设置（合成一个）**：设置页「Playwright 工作目录」——必须有 `node_modules/playwright`；其下 `.pm-profile/` 作为持久 profile。写死：**不进 vault、不进备份、不进导出**；目录里有 cookie，界面必须有一句提示。

**登录态（必须显式处理，不许报成 0 命中）**：如果 `goto` 后出现登录页（URL 跳转 / 存在 `input[type=password]`），文案是「页面需要登录：请在弹出的窗口里登录后点『重试』」，**不是**「选择器未命中」。

**依赖检测 2 盏灯**：`node`（`which('node')`）、`playwright 包`（在指定目录 `node -e "require.resolve('playwright')"` 探一次）。缺任一项 → 固定文案 + 禁用按钮，不静默失败。

**验收（5 条）**：

1. css 唯一 → `hit=1`；构造重复 → `hit=3` 且提示「请细化」；不存在的选择器 → `hit=0` 且文案「选择器未命中」（与「页面需要登录」「依赖缺失」三者文案互不混淆）。
2. `pw` 链 trial 成功/失败各一次：失败时原文包含 Playwright 的原因（如 `element is not visible`），**不吞、不改写**。
3. 需登录页面 → 提示登录并提供「重试」，不报 0。
4. 截图落临时目录、界面可预览；未点「存到附件」时库里附件数不变。
5. 跑完 3 s 内无残留 `node` 进程、临时 `.mjs` 已删、profile 目录仍在。

### 12.7 持久化登录（`launchPersistentContext`）的细则与边界

**能解决什么**：`launchPersistentContext(profileDir, { channel: 'chrome', headless: false })` 会把 cookie / localStorage / IndexedDB 写进 `profileDir`。**第二次跑同一个 profile 就不用再登录**，直到服务端 session 失效。

**不能解决的（必须按这个设计，否则会变成“假 0 命中”的第二种来源）**：

| 事实 | 设计后果 |
|---|---|
| cookie 会过期（几小时到几天，公司系统常常更短） | 「重试」是必需品：检测到登录页 → 行状态「需要登录」+ 一键「登录并重试」 |
| 服务端踢人 / 单点登录冲突（同一账号别处登录） | 同上，文案写「登录已失效，请在窗口里重新登录」 |
| profile 不能被两个进程同时用 | 并发保护：已有试跑在跑 → 明确回「正在运行，请稍候」（同录制器 `已有会话在录制` 的语义），不静默排队 |
| 首次跑必定要登录一次 | 空 profile 第一次跑 → 自动弹出窗口并停在登录页，文案「第一次使用请先登录」 |
| profile 会变大（缓存） | 设置里给「清空 profile（= 退出登录）」按钮；清空前二次确认 |

**写死的三条**：① profile 目录**不进 vault、不进备份、不进导出**；② 界面必须提示「这个目录里有登录 cookie，别拷给别人」；③ 不使用 `channel: 'chrome'` 与 Playwright 自带 Chromium 混用——**二选一写死**（建议 `channel: 'chrome'`：贴近他日常浏览器，公司站点兼容性更好），否则两套 profile 的登录态互不相认。

**验收补充（第 6 条）**：登出场景——手动删 profile 后跑一次 → 停在登录页并出「第一次使用请先登录」；登录后点重试 → 通过；同一 profile 关掉应用再开 → 不再要求登录。

## 13. B9 立项备忘：冒烟回放（**不在 1.36 做**，用户 2026-12 裁定）

**为什么先不做**：1.36 的主线是收敛（减入口、减常驻风险），而回放是**会真改数据**的新能力，且要新增"步骤"这一层数据模型——风险等级比"只读校验"高一级，混进收敛批里会把回滚粒度搞乱。

**立项时要带的东西（现在先钉住，免得半年后重新想一遍）**：

1. **数据模型**：新增"步骤"，`{ elementId, action: 'click'|'fill'|'press'|'select', valueRef?, expected? }`，`PomElementRow` 本身**不加**动作字段（元素与步骤两层分开，导出 POM 时才合并）。
2. **输入值**：一律 `${ENV_NAME}` 占位，**不落明文**（沿用录制器 `valueRef` 的约定；界面只显示"已隐藏（N 位）"）。
3. **两档执行**：默认 `trial`（不真点，只做可操作性检查）；真跑必须二次确认，并在结果里标"已真实执行"。
4. **不做**：断言框架、数据驱动、CI 集成、录制采集（采集永远在外部软件里）。
5. **成本**：约 200–300 行（解析器已能抽出 `goto/click/fill/press/select`，不需要事件采集与候选排序）。
6. **验收底线**：失败步骤必须回显 Playwright 原文原因；每步截图；跑完无残留进程。

**与本方案的边界**：B9 不做"录制"。采集在外部（用户自己的录制软件），本应用只做**解析 → 元素库 → 回放**——这样才与"删掉录制器"的裁定一致。
