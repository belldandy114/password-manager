## 0. 结论摘要（先给判定，再给证据）

| # | 问题 | 判定 | 一句话理由 |
|---|---|---|---|
| S1 | 三语言要不要三套解析器？ | **不要。一套扫描 + 每个调用按实参自证语言** | 三语言只在**三处**不同：方法名 `get_by_role`↔`getByRole`、**选项承载方式**（对象字面量 / 关键字参数 / 选项对象构造）、角色常量 `'button'`↔`AriaRole.BUTTON`；其余（字符串引号、动作后缀、`;`）不影响分类（§2、§3） |
| S2 | 映射表能不能做到「10 kind × 3 语言 = 30 格无空缺」？ | **能**，30/30 全部有确定结论 | 10 个 kind 的三语言主形态**全部可识别**；不可识别/要降级的都是**子形态**（正则、iframe 链、内部选择器、附加选项…），另列 12 行 34 格（§4 表 C） |
| S3 | `detect.ts` 的判定顺序要改吗？ | **必须改**（不是"顺序"，是**特征集**）；顺序 ①→②→③ 保持不变 | 现行「任两条 Page 特征」在实测 12 个用例里**漏判 7 个**：`page.getByTestId(...)`、`get_by_role(...)`、`page.getByLabel(...)`、弹窗别名 `page1.` 全部因为只命中 `page.` 一条而降级失败；同时**误判 1 个**（`mypage.locator(...)`）（§5.1） |

| S7 | 跨语言 `pw` 链要不要转成 JS？ | **要转**，且只在**还原白名单**内转；白名单外一律 `unknown` | 元素库的 `pw` 合约写死"一行 Playwright **JS** 链"（`[A0-2]` 第 5 行），生成器 `pwChainToJava` 与 `pwChainPlan` 只吃 JS；实测把 Python/Java 链还原后**与 JS 原文逐字相同**，跨语言去重因此也成立（§3.4） |

## 1. 现状与机械证据

### 1.1 现行解析器的真实能力（逐行实测）

`parsePlaywright.ts` 的判定链是：`line.includes('page.')` → `chainOfLine()`（从 `page.` 切片，按 `TAIL_ACTION` 正则砍掉动作尾巴）→ 门 `/\.(getBy[A-Za-z]+|locator)\(/` → 分类。

对「同一组 12 条真实定位行」分别用 JS / Python / Java 写法喂进去（定位臂文本由 `asLocator` 生成，见 §1.3），实测：

| 语言 | 定位行真值 | 现状可解析 | 丢在哪 |
|---|---|---|---|
| JavaScript | 12 | **12** | 无丢失，但 `getByLabel/getByPlaceholder/getByTestId` 4 条被误判成 `pw`（A₀ 之后它们有专属 kind） |
| Python | 12 | **2** | 只有 `locator(...)` 那 2 条（`css`）。**10 条 `get_by_*(` 全丢**——门正则只认驼峰 `getBy*` |
| Java | 12 | **7** | `getByRole(AriaRole.BUTTON, …)` 丢（`firstArg` 期待引号字面量，实参是 `AriaRole.BUTTON`）；`getByLabel/…/getByTestId` 仍误判成 `pw` |

**结论**：Python 侧基本不可用（10/12 丢），Java 侧丢的是**最该认的 role 行**。这两条不是"要不要支持"的问题，是"现在粘进去得到的元素表是错的"。

## 2. 三语言到底差在哪（三处，不是三十处）

| 差异点 | JS | Python | Java | 对解析器的影响 |
|---|---|---|---|---|
| ① 方法名 | `getByRole` / `locator` | `get_by_role` / `locator` | `getByRole` / `locator` | **只影响归一**：`snake → camel` 一条规则覆盖（`get_by_test_id` → `getByTestId`） |
| ② 选项承载 | **对象字面量实参**：`{ name: '登录', exact: true }` | **关键字参数**：`name="登录", exact=True` | **选项对象构造**：`new Page.GetByRoleOptions().setName("登录").setExact(true)` | **三套读法**，必须分别解析；`clazz` 三种取值（`Page`/`Locator`/`FrameLocator`），**不许写死 `Page.`** |
| ③ 角色常量 | **字符串** `'button'`（ARIA token 原文） | **字符串** `"button"` | **枚举** `AriaRole.BUTTON`（或 `AriaRole.valueOf("FANCYWIDGET")`） | Java 需要**反查**：`AriaRole.X` → `X.toLowerCase()`；`valueOf("X")` → `X` 归一后再小写，且**降 guess**（`[A1-2]` 说它运行期才可能炸） |
| （非差异）引号 | `'` | `"` | `"` | 解析时**统一反转义**，不影响分类；渲染回 JS 时统一用 `'` |
| （非差异）动作后缀 | `.click();` | `.click()` | `.click();` | 都靠**方法名集合**识别，不靠分号/括号 |
| （非差异）索引写法 | `.first()` `.last()` `.nth(2)` | `.first` `.last` `.nth(2)`（**属性，无括号**） | `.first()` `.last()` `.nth(2)` | 扫描器必须允许**无括号 op**（Python 的 `.first` 就是裸属性，否则会把它当语句结束） |
| （非差异）断言壳 | `await expect(page.getByRole(…)).toBeVisible();` | `expect(page.get_by_role(…)).to_be_visible()` | `assertThat(page.getByRole(…)).isVisible();` | 扫描从 `page` 起，**壳不影响**：断言行同样产出候选（它是真的元素引用） |
| （非差异）多页别名 | `page1` `page2`（popup） | `page1` | `page1` | 别名正则 `\bpage\d*\.`，取**首个**；自定义别名（`popup.`）不认（§10 已知限制） |

**一句话**：三语言的差异全部收敛到「② 选项承载」与「③ 角色常量」，①可用一条归一规则抹平。所以**一套扫描器 + 一张 kind 映射表**就够，不需要三份解析器。

**Java 的 `clazz` 必须按链位置取值**（实测）：

```java
page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("登录"))            // 第一跳 → Page
page.locator("form").getByRole(AriaRole.BUTTON, new Locator.GetByRoleOptions().setName("提交"))  // 第二跳 → Locator
page.frameLocator("#f").getByRole(AriaRole.BUTTON, new FrameLocator.GetByRoleOptions().setName("登录"))
```

> 若解析器把 `new Page.GetByRoleOptions()` 写死，链式 Java 行会被判不识别——这是**必须写进单测的格子**。

## 3. 解析器结构（一套扫描 + 每个调用自证语言）

### 3.1 四段流水线

```
文本 ──① 语句切分/续行拼接──▶ 逻辑语句 ──② 链扫描（括号+引号感知）──▶ ops[]
   ──③ 分类（10 kind 映射 + 白名单）──▶ {kind, locator, role?} + confidence
   ──④ 去重/命名/截断──▶ ElementPasteCandidate[]
```

### 3.2 ① 语句切分与续行拼接

- codegen 的输出是**一行一个动作**（三个语言生成器都用 `formatter.add()` 逐行追加，见 §1.3），所以主路径按行处理；
- **但**用户常粘 Prettier 格式化过的脚本。规则：**只有"上一行括号未闭合"才续行**（用一个只计 `(`/`)`、跳过字符串的深度计数器）。防止把两条独立语句拼起来。

### 3.3 ② 链扫描（语言无关，这是本方案的核心件）

Python 的 `.first`（无括号）与 Java 的嵌套 `new Page.GetByRoleOptions()` 用正则都做不对，所以必须扫描：

```ts
// 【新建】src/utils/codegen/elementPaste/scan.ts
export interface Call { name: string; camel: string; argsRaw: string; hadParen: boolean }

/** 从 line[start] === '.' 起，扫出顶层方法链。字符串字面量内的 . ( ) , 一律不算结构。 */
export function scanChain(line: string, start: number): { calls: Call[]; end: number };
/** 把实参串按顶层逗号切开（跳过字符串与嵌套括号） */
export function splitArgs(raw: string): string[];
```

规则（每条都要有单测）：
1. `quote ∈ {' " `}` 内的 `(` `)` `,` `.` **不参与结构判断**；`\` 转义跳过下一个字符；
2. `op` 可以是**无括号属性**（`hadParen = false`）——Python 的 `.first` / `.last` / `.content_frame`；
3. 遇到**未闭合**（扫到行尾 depth>0）→ 整行判 `unknown`（`reason`: 链跨多行，请粘成一行）；
4. `argsRaw` 保留**原文**（不 unescape），仅在取值时对单个字面量反转义（`unescapeLiteral()`），保证 locator 文本与 codegen 原文一致。

### 3.4 ③ 分类：三张表定死

**(a) 方法 → kind（`KIND_OF_METHOD`，10 项，`locator` 特殊处理）**

| 归一后方法（camel） | 三语言写法 | kind |
|---|---|---|
| `locator` | `locator('…')` / `locator("…")` / `locator("…")` | `css` / `xpath`（按 body 判，见 (b)） |
| `getByRole` | `getByRole(…)` / `get_by_role(…)` / `getByRole(AriaRole.…)` | `role` |
| `getByText` | `getByText` / `get_by_text` / `getByText` | `text` |
| `getByLabel` | `getByLabel` / `get_by_label` / `getByLabel` | `label` |
| `getByPlaceholder` | `getByPlaceholder` / `get_by_placeholder` / `getByPlaceholder` | `placeholder` |
| `getByAltText` | `getByAltText` / `get_by_alt_text` / `getByAltText` | `alttext` |
| `getByTitle` | `getByTitle` / `get_by_title` / `getByTitle` | `title` |
| `getByTestId` | `getByTestId` / `get_by_test_id` / `getByTestId` | `testid` |
| （链）`filter(hasText)` / `nth(n)` / `first` / `last` | 三语言同构（`has_text=` / `setHasText(…)`） | `pw` |
| 其它（`goto`/`navigate`/`click`/…） | — | **忽略**（不是定位行） |

**(b) `locator(body)` 的 body → kind（顺序固定，先命中先赢）**

| 序 | body 形态 | 结论 |
|---|---|---|
| 1 | `xpath=…` | `xpath`，**剥掉 `xpath=`**（`[A0-2]` 第 2 行：locator 不得自带前缀） |
| 2 | `css=…` | `css`，剥掉 `css=` |
| 3 | 以 `/` 或 `(` 开头 | `xpath`（CSS 选择器不可能这么开头，故无歧义） |
| 4 | `text=…` | **不识别**：`text=` 与 `getByText` 语义不同，`[A0-6]` 已统一为 `getByText` |
| 5 | `role=…` | **不识别**：字符串角色兜底已作废（`[A1-2]`） |
| 6 | `aria-ref=…` / `internal:…` | **不识别**：Playwright 内部选择器，元素库不存 |
| 7 | 其余 | `css` |

**(c) 选项读取：三套，逐调用自证（不按整行判语言）**

```ts
// 实参串 → { positional: string[], options: Record<string, string> }（key 已归一为小写去下划线）
// JS ：{ name: '登录', exact: true }        → splitArgs 得到对象字面量 → 逐个 key: value
// PY ：name="登录", exact=True              → 顶层 k=v
// JAVA：new Page.GetByRoleOptions().setName("登录").setExact(true) → 末尾 .setXxx(v) 链
```

判定优先级（三语言互斥，且**按实参形态自证**，不看整行）：
1. 实参里出现 `AriaRole.` → 走 Java 读法（`setXxx` 链 + 角色反查）；
2. 实参里出现 `{ … : … }` → 走 JS 读法（对象字面量）；
3. 顶层出现 `ident=` → 走 Python 读法（关键字实参）；
4. 都没有 → 只有**位置实参**：三语言完全同构，无需判语言（`getByText("全部")` 就是 `getByText("全部")`）。

> **为什么不用"整行判语言"**：混粘（JS + Python 同时贴）会立刻破。逐调用自证让混粘天然成立，也让 `page1.`/`assertThat(...)`/`expect(...)` 这些壳一视同仁。

### 3.5 `pw` 链的跨语言还原（白名单，越界即 `unknown`）

`[A0-2]` 第 5 行把 `pw` 的 locator 定义成「一行 Playwright **JS** 链」，所以 Python/Java 的链**必须反向渲染成 JS** 才能入库（否则 `pwChainToJava` / `pwChainPlan` 都吃不下，`[A0-7]` 的白名单也只有 JS 方法名）。

还原白名单（**只有这些 op 能转**，与 `[A0-7]` 的 12 方法一致）：

| op | JS 渲染 |
|---|---|
| `locator(v)` | `locator('v')` |
| `getByRole(role[, name])` | `getByRole('role', { name: 'name' })`（无名时不带 options） |
| `getByText/getByLabel/getByPlaceholder/getByTestId/getByAltText/getByTitle(v[, exact])` | `getByX('v'[, { exact: true }])` |
| `filter(hasText)` / `filter(has_text=)` / `setHasText(…)` | `filter({ hasText: 'v' })` |
| `nth(n)` | `nth(n)` |
| `first` / `first()` | `first()` |
| `last` / `last()` | `last()` |

**白名单外一律 `unknown`**（不猜、不原样存）：`frameLocator` / `frame_locator` / `contentFrame()` / `content_frame` / `or` / `or_` / `and` / `and_` / `has` / `hasNot` / `describe` / 正则实参 / 未知 `setXxx` 选项。
理由两条：① 元素库的 10 种 kind 表达不了它们；② 就算按 `pw` 收下，`pwChainPlan` 白名单里没有这些方法（`[A0-7]`），点验会直接标 `skip`，等于"导入成功但永远不能验"。

**反转义必须成对**：Java/Python 的 `"xpath=//div[@id=\"a\"]"` 要还原成 `//div[@id="a"]`（实测三语言 `asLocator` 对同一选择器输出的 body 一致，只差引号转义）。

### 3.6 实测：还原后**三语言逐字相同**

同一批 12 条夹具（§1.1）跑原型后，Python/Java 产出的 `pw` 链与 JS 原文完全相同：

```
JS   : page.getByRole('listitem', { name: '审核结果' }).nth(2)
PY   : page.getByRole('listitem', { name: '审核结果' }).nth(2)     ← 由 get_by_role("listitem", name="审核结果").nth(2) 还原
JAVA : page.getByRole('listitem', { name: '审核结果' }).nth(2)     ← 由 AriaRole.LISTITEM + setHasText 还原
```

**副作用（好事）**：`pw` 的**跨语言去重也成立**（去重键含 locator 原文，而原文被统一渲染）——不是"只能同语言去重"。

## 5. `detect.ts` 要改吗？

### 5.1 结论：**要改**（改特征集，不改判定顺序）

现行规则与实测已在 §1.2。要点复述：`DATE_HINTS` 把 `getByRole(`/`getByText(` 写成**枚举**，一旦脚本里只有 A₀ 新增的 5 种之一（`getByTestId` 最常见），命中数就只有 `page.` 一条 → 判 `null`。**7 个漏判里 6 个是这个原因**，第 7 个是 `page1.`（弹窗别名，`page.` 里没有 `1`）。

### 5.2 新规则（两条正则的 AND，替掉"任两条"）

```ts
// 【改】src/utils/codegen/elementPaste/detect.ts
/** ① 是不是「页对象上的调用」：允许 page / page0 / page1（弹窗别名），且 page 必须是独立词 */
const PAGE_CALL = /\bpage\d*\s*\./;
/** ② 有没有「任一语言的定位方法」：驼峰（JS/Java）+ 蛇形（Python）各一条 */
const LOCATOR_CALL = /\.(getBy[A-Z][A-Za-z]*|get_by_[a-z_]+|locator|frameLocator|frame_locator)\s*\(/;
// 判定：PAGE_CALL.test(text) && LOCATOR_CALL.test(text) → 'playwright-js'
```

为什么是 **AND** 而不是"任两条"：
1. 单独 `page.` 太松（任何 Electron/Node 脚本都可能出现 `page.`）；单独 `locator(` 更松（`page` 这个词在别处也常见）；
2. `page` 与"定位方法"是**同一条语句里必然共现**的两件事（三个语言生成器都以 `subject = pageAlias` 开头，见 §1.3）；
3. AND 顺带**修掉一个假阳性**：`const mypage = {}; mypage.locator('x')` 现行判 `playwright-js`，新规则 `\bpage` 不匹配 `mypage` → `null`。

**判定顺序完全不变**（① Recorder JSON → ② Playwright → ③ HTML），证据：现有测试 `detectElementPaste` 第 2 条要求"脚本里含 `<` 也判 playwright"，新规则下 ② 仍先于 ③。

### 5.3 兼容性证明（对 `detectElementPaste` 那个 describe 下的**全部 7 条**断言逐条核）

| 现有断言（`elementPaste.test.ts:186-239`） | 新规则下 | 结论 |
|---|---|---|
| Recorder JSON 与 `locator(` 同时命中 → 取 ① | ① 先判，未变 | 通过 |
| `getByRole(…{ name: '<空>' }…)` + `<` → playwright | `PAGE_CALL` ✓ + `LOCATOR_CALL` ✓ | 通过 |
| `<div id="a">x</div>` → html | `PAGE_CALL` ✗ → 落 ③ | 通过 |
| 中文一句 → `null` + 固定文案 | 两条都 ✗ | 通过 |
| 空文本 / 纯空白 → `null` | `trim()` 后空 → 早退 | 通过 |
| 识别出的每行都带 `source/confidence/reason` | 三语言的 `unknown` 行也必填 `reason`（§6.1 第三类） | 通过 |

### 5.4 `PasteSource` 不加值（S8 的具体理由）

- `PasteSource` 是**格式**维度（= 下拉里的"解析器"选项，`PasteImportDialog.tsx:32-36` 的 `SOURCE_LABEL`）。加 `playwright-py`/`playwright-java` 会让下拉出现 3 个 Playwright 选项，用户还得先判"我这段是哪种语言"——而**这件事解析器自己就能判**（§3.4(c)）。
- 手动改选链路必须保持"选 Playwright 就能解析任意语言"：`parseBySource('playwright-js', pyText)` 在同一个解析器里走同一套逐调用自证 → 成立。
- 代价照实写：**字面量 `'playwright-js'` 名不副实**（它现在代表三种语言）。换名要动 `types.ts` + `detect.ts` + 对话框 + 3 处测试断言（5 个文件），功能收益 0，因此本轮**不换名**，只把语言写进 `reason` 前缀：`Playwright codegen（Python）：…` / `（Java）：…` / `（JS）：…`。这条列为已知债（§10-3），换名时机由后续批次决定。

## 6. 动作行忽略规则与去重

### 6.1 三类处置（不是两类）

| 类别 | 判据 | 处置 |
|---|---|---|
| **定位行** | 扫出的链首个 op ∈ `KIND_OF_METHOD` 且链可还原 | 产**候选**（`exact`/`guess`） |
| **非定位行** | 首个 op 是动作，或不是定位方法（`goto`/`navigate`/`reload`/`close`/`newPage`/`setViewportSize`/`route`/`routeFromHAR`/`evaluate`/`waitForTimeout`/`onceDialog`/`on`/`once`/`url`…）；或行内无 `page` 调用（`import`/`class`/`def`/`try (`/`}`/空行） | **静默忽略**（连行都不产） |
| **定位行但表达不了** | 首个 op 是 `frameLocator`/`frame_locator`，或链里含 `contentFrame`/`content_frame`/`or`/`and`/`has`/`hasNot`/`describe`/正则 | 产 **`unknown` 行**（`locator: ''` + `reason`），预览里可见、默认不勾 |

**为什么第三类要产行**（与现行"静默丢弃"不同）：粘贴 15 行只出 14 行、其中 1 行是 `unknown`，用户能**看见**"这行我没认出来，因为 iframe 不支持"；静默丢弃只会让用户以为"我漏选了"。代价：`detectElementPaste` 里「像 Playwright 脚本，但没有可解析的定位行」这条 `reason` 变成**几乎不可达**（只有全是非定位行时才会命中，例如只粘了一行 `await page.goto(...)`）——文案保留不动。

### 6.2 动作方法集（三语言，归一后 camel）

```
click dblclick fill type press pressSequentially hover check uncheck setChecked
selectOption selectText setInputFiles tap focus blur clear dragTo
scrollIntoViewIfNeeded waitFor waitForSelector waitForLoadState screenshot evaluate
count innerText textContent getAttribute dispatchEvent
isVisible isEnabled isChecked isEditable isHidden inputValue
```

- Python 的 `select_option`/`set_input_files`/`is_visible`/`is_checked`/`press_sequentially` 经 `snake→camel` 归一到同一集合；
- **`first`/`last`/`nth`/`filter` 不是动作**（它们是定位链的一部分）——这条必须写单测，否则 `getByRole(…).first()` 会被切掉索引变成 1 条错候选；
- 切分位置：**第一个**动作 op 之前（`getByRole(...).click({ delay: 100 })` → 保留 `getByRole(...)`）。

### 6.3 字符串字面量保护（现行缺陷，实测）

| 写法 | 现行结果 | 新结果 |
|---|---|---|
| `await page.getByText('行内有 .click( 字样').click();` | `chainOfLine` 在字符串内切 → `page.getByText('行内有 ` （引号未闭合）→ `firstArg` 取不到 → **整行丢弃**（实测 `chain=[[page.getByText('行内有]]`） | 扫描器跳过字符串 → `text` · `行内有 .click( 字样`，conf `exact` |

所以动作切分**必须是扫描器的一部分**（§3.3 规则 1），不能是"对整行跑正则"。

### 6.4 去重键（三语言统一）

```
key = `${kind}|${normalize(locator)}|${kind === 'role' ? normalize(role ?? '') : ''}`
normalize(s)：
  - text / label / placeholder / alttext / title → trim + 连续空白折叠成 1 个空格
    （getByText 系列本就"规范化空白"，折叠不改变语义，`[A0-2]` 第 3 行的口径）
  - css / xpath → 只 trim（空白在 css 里可能是后代选择器的一部分，不许折叠）
  - pw → trim + 把 `, ` 之后的空档统一成单空格（因为我们**自己**渲染，格式确定，跨语言才可能逐字相等）
  - role 名 → trim + 折叠空白
```

| 场景 | 期望 | 依据 |
|---|---|---|
| 同一按钮被连点两次（同语言两行） | 1 条 | 键相同 |
| 同一元素用 JS + Python + Java 各粘一次 | **1 条** | 三语言归一后 `kind`/`locator`/`role` 相同（§3.6 实测 pw 链也相同） |
| `getByRole('button',{name:'登录'})` 与 `{name:'取消'}` | **2 条** | 键含 `role`（现行键**丢 roleName** → 会并成 1 条，是现存缺陷） |
| `getByText('全部')` 与 `getByText('  全部 ')` | 1 条 | text 折叠空白 |
| 一条 `exact`（guess）+ 一条不带（exact） | 1 条，**留 exact** | 键相同 → 保留 confidence 高者；同档保留**先出现**的 |
| 两条 `unknown` | **2 条，不去重** | 它们的 `locator` 都是空串，去重会把两个不同元素并成一条，用户就看不出"少了哪个" |

**顺序**：输出顺序 = 首次出现顺序（保持用户粘贴的阅读顺序），被合并的行在 `reason` 末尾追加 `（与第 N 行重复，已合并）`。

## 7. 置信度规则（10 kind × 三语言同一口径）

`exact` 的定义**只有一条**：*元素库存的 `(kind, locator, roleName)` 生成出来 / 试跑出来，与 codegen 那一行**语义逐字等价***。凡有信息在元素库模型里存不下的，一律 `guess` 并给 `reason`。

| kind | `exact` 条件 | `guess` 条件（`reason` 逐字） |
|---|---|---|
| `css` | 复用既有 `cssConfidence`：`#id` / 单属性 `[a="b"]` / 其余"含 id 或属性组合" | `.class` / 只有标签名 / 结构性伪类（`:nth-child` 等）——文案沿用 `parsePlaywright.ts:50-63` 现有 5 条，**不新造第二套** |
| `xpath` | 含 `[@id=` / `[@data-*=` / `[@aria-*=` / `[@name=` / `[@title=` / `[@href=` | 其余（纯结构路径 `/html/body/div[3]`）：`xpath 是纯结构路径，页面改版易失配` |
| `text` | 无 `exact` 选项 | 带 `exact`：`原写法是 exact 匹配，元素库按 getByText 默认（子串、忽略大小写）生成，可能多命中` |
| `role` | 有可访问名 **且** 无附加选项 **且** 不是 `valueOf` | ① 无名：`只有角色名，没有可访问名`（`validatePage` 会拦，先标出来）② 附加选项：`角色带附加选项（level/description 等），元素库只存 name，可能多命中` ③ `valueOf`：`角色来自 AriaRole.valueOf(...)，首次运行可能抛 IllegalArgumentException（[A1-2]）` |
| `pw` | ——（**永不 exact**） | 恒 `guess`：`这是「定位器 + 过滤/索引」的整条链，元素库只能原样存成 Playwright 链`（沿用现行文案） |
| `label` / `placeholder` / `alttext` / `title` / `testid` | 无 `exact` 选项 | 带 `exact`：`原写法是 exact 匹配，元素库按默认（子串、忽略大小写）生成，可能多命中`（`testid` 无模糊匹配，文案改为 `带 exact 选项，元素库不存该选项`） |
| 任意 kind 但**表达不了** | —— | `unknown`：见 §4 表 C 的逐条 `reason` |

**`NAME_HINT_MAX` 与其它上限（三档，别混）**

| 上限 | 值 | 谁负责 | 本方案的动作 |
|---|---|---|---|
| 元素名建议 | `NAME_HINT_MAX = 30`（`types.ts:39`） | 解析器 `nameHint()` | 取到名字源后 `trim + 折叠空白`，超 30 截 30 + `…`；**三语言同一优先级** |
| 元素名字段（落库） | 60（`pomModel.ts:116`） | `validatePage` | 解析器**不截断**到 60（30 已更短，天然满足） |
| `role` 名（落库） | **40**（`pomModel.ts:128`，`[A0-4]` 定 40 为写端上限） | `validatePage` | 解析器**不截断**（截断会改变匹配语义！）；超 40 时 `confidence` 照原判但 `reason` 追加 `可访问名 N 字，超过 40 字上限，保存时会被拦下` |
| `locator` | 500（`pomModel.ts:118`） | `validatePage` | 同上：不截断，`reason` 追加提示 |

**名字建议的取值优先级（三语言必须一致，否则同一行 JS/PY 得到不同名字）**：
`hasText/has_text/setHasText` → `placeholder` → 可见文本（`getByText`）→ 角色可访问名（`name:` / `name=` / `setName(…)`）→ `locator` 的 body → `未命名元素`（沿用 `suggestName()` 现有顺序，只把三语言的取值点补齐）。
