## 3. 选型取舍（三维打分 + 结论）

### 3.1 录制链路形态（沿用上游 ADR-1，我复核后维持）

| 维度 | A 外部真 Chrome + 原生 CDP | B 应用内 BrowserWindow + 最小 preload | C 引入 playwright-core | D 自研 Chrome 扩展 |
|---|---|---|---|---|
| 团队能力 | **5**（`browser:detect` 与 `taskkill /T /F` 先例已有，`scripts/lib/cdp.js` 269 行现成） | 4 | 2（仓内零依赖，团队未用过） | 3 |
| 生态成熟度 | 4（CDP 是 Chromium 官方协议） | 4 | 5 | 2（要上架审核） |
| 维护成本 | **4**（零依赖、零体积、零新打包面） | 3（内核不等于用户环境） | **1**（~50 MB + 浏览器下载 + 打包/CI 全改） | 1 |
| 结论 | **✅ 选 A** | ❌ | ❌ | ❌ |

**放弃 B 的硬理由**：应用内内核不是用户真实浏览器，录制结果与实际执行环境不一致；且主 `preload` 挂 219 个 invoke，等于把密码库操作面交给被测页面。
**放弃 C 的硬理由**：ADR-2——Playwright 只应出现在**产物**里，不进应用依赖；生成不需要它，只有执行需要。
**代价（写进交付说明）**：只支持 Chromium 系；CDP 版本漂移要自己盯（本机 152 与上游 157 两点验证通过，非分布）。

### 3.2 `uiRecordings` 落库 vs 不落库（用户已拍板：落库 + bump）

不落库（只导出文件）能省掉迁移，但历史录制不可回溯、元素与步骤关联会丢，且「三产物」每次都要重录。**用户已授权 bump 4→5**，走 P-1 契约修订留裁决记录。回滚语义按契约 C-43（`:337`）：**bump 后降级不丢数据，不 bump 才丢**——上游原报告此处说反，已在本期修正。

### 3.3 产物形态（用户已拍板：三选一次做全）

三份产物共用同一份 `UiRecording.steps`，模板差异只是字符串拼接。三者的**生成**全部零依赖；差异只在**执行**前置，故验收按环境分档（AC-10a/b/c）。

## 5. 数据与接口契约

### 5.1 数据模型（`src/utils/record/recorderModel.ts`）

```ts
export interface UiRecording {
  id: string; name: string;
  pageId?: string;          // 关联 pomPages 页面，关联后 baseUrl 以页面为准
  baseUrl: string;
  startedAt: string; updatedAt: string;
  steps: UiStep[];
  check?: { at: string; total: number; passed: number; failed: number; approx: number };
}

export interface UiStep {
  id: string;
  index: number;                                   // 显式存，不靠数组下标
  action: 'navigate' | 'click' | 'fill' | 'select' | 'press' | 'assert';
  locator?: { kind: 'css' | 'xpath' | 'text' | 'role'; value: string; roleName?: string };
  elementId?: string;                              // 指向 PomElementRow.id（S1 补齐该字段）
  valueMeta?: { length: number; redacted: true };  // fill/select 只存这个
  valueRef?: string;                               // 生成脚本时的环境变量名，如 'ACCOUNT'
  note?: string;
  assert?: { kind: 'url' | 'text' | 'title'; contains: string };
}
```

**上限（算过，不是拍脑袋）**：一步 JSON ≈ 180–250 B → 300 步 ≈ 54–75 KB；`COLLECTION_CAPS.uiRecordings = { maxItems: 20, maxBytes: 1536 * KB }`（不是 100 份——那会到 6 MB，超 `TOTAL_COLLECTION_BYTES`）。

### 5.3 IPC 契约（5 条 invoke + 1 条推送）

> **v18 按契约 `[C-114]` 同步：出参一律包 `[C-01]` envelope `{ success: true, data }`，错误文案一律固定中文串（`[C-02]`），英文伪码仅可放 `data.code` 且前端不得作主判据。** 下表「错误文案」列与契约 §9.2 逐字一致，改一处必须两处同改。

| 通道 | 入参 | 出参（`data`） | 错误文案（`error`） | 鉴权/幂等 |
|---|---|---|---|---|
| `record:probe` | `{ workspaceDir?, force? }` | `{ abilities:[{id,state,label,detail,evidence:[{cmd,out}],fixHint?}], probedAt }`；`id` 固定 `chrome`/`node`/`jdk-jar`/`playwright`/`workspace` | `未解锁` | 只读；前置 `pw()`；缓存 60 s |
| `record:start` | `{ url, pageId? }` | `{ sessionId, browser, port }` | `未解锁` / `URL 不合法` / `已有会话在录制`（`data.sessionId` 带现有会话） / `未检测到 Chromium 系浏览器` / `浏览器启动被拦截` / `启动失败` / `启动进行中，请稍候重试` | 必须已解锁；单会话单例 + in-flight 互斥；总超时 15 s |
| `record:stop` | `{ sessionId }` | `{ ok:true, received, pushed, dropped, truncated, cleaned:{killed,profileRemoved} }` | `未解锁` / `会话已结束` | 幂等：同 id 重复 stop 回 `ok:true` 且计数为 0；`会话已结束` 只用于 id 不存在/不属当前会话 |
| `record:validate` | `{ sessionId, items:[{strategy,selector}] }`，`items ≤ 50` | `{ results:[{strategy,selector,count,precise,ms,invalid?,error?}] }` | `未解锁` / `会话已结束` / `校验超时` / `入参不合法` | 纯读；单条 3 s、整次 10 s |
| `record:status` | `{}` | `{ sessionId, state, startedAt, url } \| null` | `未解锁` | 只读幂等无副作用；`url` 只回脱敏后的 origin+path |
| `record:event`（主→渲染） | — | `{ sessionId, seq, action, target, candidates, ms }`（字段结构见契约 `[C-114]`） | —（推送不带 envelope） | 16 ms 合批、单批 ≤20；`on` 返回退订函数；`seq` 单调；单会话上限 5000（到顶 `truncated:true` 且显式告警） |

**鉴权口径**：全部 `record:*` 先过 `pw()`，未解锁一律回 `未解锁`。`pw()` 是**会话前置检查**，不属 `[C-05]` 所指的「额外密码校验」（契约 `[C-114]` 已定性，`code R-C18`）。
**URL / flag 白名单**：URL 只接受 `http`/`https`、拒 `-` 开头、≤500 字、`file://`/`chrome://`/`devtools://`/`javascript:` 拒；**入库前剥 userinfo + query 白名单**（契约 `[C-119]` 第 5 款）；flag 走**正向枚举**、args 数组 + `shell:false`（契约 `[C-114]` flag 条）。
**防伪**：`nonce = sha256(sessionId).slice(0,12)`，binding 名 `__dsh_<nonce>`；主进程只收 name 与当前会话 nonce 相符的 `bindingCalled`，未知键丢弃，`seq` 单调；单会话事件上限 5000（**到顶置 `truncated` 并告警，不得静默**）。
**校验注入面**：`items[].selector` 只经 `Runtime.callFunctionOn` 的 `arguments` 传入，**禁止拼进任何 JS 表达式**（契约 `[C-114]` validate 条）。

## 8. ADR（本期新增/修订，4 行式）

**ADR-5 vault bump 4→5（本期新裁决）**
决策：bump 到 5，新增 `MIGRATIONS[4]`（补空数组 + 元素 id 幂等回填）。
背景：产物②③需要动作序列，`pomPages` 只有元素；契约 `:325`/`:1045` 禁止再次 bump，故须先做 P-1 契约修订。
备选与放弃：不落库只导出文件（历史不可回溯、每次重录）；步骤塞进 `pomPages`（每次录制重写整张元素表，与 `pomModel` 整表写回旧坑叠加）。
后果：违反既有禁令，代价是必须留裁决记录并改写 5 条既有断言；收益是降级不丢数据（C-43），**不 bump 才丢**（C-42）。

**ADR-6 产物三选（对 C-82 的边界澄清）**
决策：POM 生成器仍只出 Java（C-82 不变）；`.mjs` 与 `*.spec.ts` 归为「录制产物」，不是 POM 语言选项。
背景：C-82 管的是 `pageobject.ts` 的 `lang` 参数；录制产物是第三种物，契约既未允许也未禁止。
备选与放弃：只出 `.mjs`（上游可行性报告 A-01 主张，判过重）；出 Python（被 `:1056` 明确禁止）。
后果：契约须新增「录制产物」豁免条款与三种产物的执行前置说明。

**ADR-7 只做 L1、不做应用内正式回归（沿用 ADR-4）**
决策：应用内只做元素级命中数校验；正式回归走外部脚本进 CI。
背景：CDP 直点与 Playwright auto-wait 是两套语义，「本地绿、CI 红」会成常态。
备选与放弃：自研完整 runner（重写 Playwright 最值钱的部分）。
后果：界面必须写明「应用内通过 ≠ CI 通过」。

**ADR-8 代码着色复用既有高亮器（不引依赖、不新写）**
决策：产物预览直接用 `src/utils/codeHighlight.ts` + `ui.tsx` 的 `<CodeBlock>`；**不新写 tokenizer**。
背景：该模块已存在（513 行、零依赖、7 个 `tok-*` 语义类），第 1 条设计约束就是「逐字符无损」；契约 `[C-99]`（`:851`）要求展示与复制逐字符相同。
备选与放弃：新写录制专用 tokenizer（重复已有能力，且会引入第二套配色结论）；引 `highlight.js`/`prism`（G6 禁止，且主题体系与仓库 token 冲突）。
后果：着色覆盖面受既有 7 类限制，换来「已有的不变量可直接断言」——AC-16 钉在纯函数层（`tokens` 拼接还原原文），比 DOM 判据更强。

**ADR-9 视觉一律复用既有玻璃体系（不新造）**
决策：录制页全部复用已登记类与 19 个 `--glass-*` token；只向 `redesign.css` **末尾**追加录制页专属**透明背景**排版类。
背景：玻璃体系只在 `html[data-bg='image']` 生效；容器加 `backdrop-filter` 会新建层叠上下文并把内部下拉关进容器（`.toolbar` 踩过）。
备选与放弃：给录制页做独立玻璃皮肤（会引入新 token 与第二套对比度结论）；自绘下拉（层叠与裁剪风险）。
后果：视觉自动与既有 8 页面一致、两道门禁即绿；代价是自定义浮层必须挂在 `.pnl` 之外，优先用原生 `select`。
