## 1. 三态布局骨架（①）

### 1.1 统一骨架（三态逐字同一张骨架，只换面板内容）

```text
<Page>                                           .pg（max-width 1480 / padding 22 28 36 / gap --d-gap）
  <PageHead icon title desc tools />             .pg-head / .pg-title / .pg-sub / .pg-tools
    desc   : 「对被测系统点一遍，把点过的地方变成带唯一性证明的定位器。
              应用内只做『录 + 验 + 落 + 生成』，不做正式回归；应用内通过 ≠ CI 通过。」
    tools  : 无（动作一律进 .toolbar，页头只留说明）
  <div className="toolbar">                      .toolbar（--glass-side / --z-toolbar:20；禁 backdrop-filter）
    <div className="rec-row">                    ① 目标页址 input（.field + .field-label）
      ① 页面关联 select（原生，pomPages 列表）  ② 关联页面：一份录制只挂一个页面，可在产物里改
      ③ 主操作 .btn-primary                      录制态文案「停止录制」，其余「开始录制」
    </div>
    <div className="rec-row">                    （第二行：次操作，永远不与主操作同行抢宽度）
      .btn-secondary「保存到元素库」 / .ibtn「↻ 重新探测」（可选，与 §4 面板级 ↻ 二选一，见 §4.3）
    </div>
  </div>
  <div className="dev-banner is-error" id="rec-block-reason" />   仅灯 1 红时出现（§5）
  <div className="tabs" role="tablist" aria-label="UI 录制器">  .tabs（透明底、1px 底边、无玻璃登记）
    <button className="tab2 is-active" role="tab" aria-selected>录制</button>
    <button className="tab2" role="tab">校验报告</button>
    <button className="tab2" role="tab">产物</button>
  </div>
  <Panel title="本机能力" meta="探测于 14:22:31" tools={<IconBtn ↻ />} collapsible>   .pnl（常驻，三页签共用）
    5 盏灯（§3）+ 展开态（§4）
  </Panel>
  <div role="tabpanel"> …按激活页签渲染：§1.2 / §1.3 / §1.4 … </div>
</Page>
```

**为什么「本机能力」常驻在页签之外**：灯 1 决定「开始录制」能不能点，而主按钮在 `.toolbar`（页签之外）——灯放在页签里会让「为什么按钮是灰的」和「证据在哪」分处两个页签。它一个 `.pnl` 高度约 `--d-panel-py`×2 + 1 行灯，紧凑档约 40px、cozy 约 76px，值得常驻。

### 1.3 录制中（左候选列表 + 右详情）

```text
<Panel title="录制会话" meta="已录 12 步 · 14:22:31 开始" tools={.btn-secondary「停止并校验」}>
  <div className="split">                        ← 复用 pages.css:520-531（248px + minmax(0,1fr)，≤1100 单列）
    <div className="dev-list" role="listbox">    ← 左：候选列表（已有类，透明底）
      <button className="dev-list-item is-on" role="option" aria-selected>
        <span className="dev-list-name">③ 点击「登录」</span>   ← 动作序号 + 元素名，单行省略
        <span className="dev-list-count">1</span>                ← 命中数（=1 才绿；分母永远可见）
        <span className="dev-list-del" />                        ← 删除步骤（hover/focus 显形，已有规则 9181-9190）
      </button>
      …
    </div>
    <div>                                        ← 右：详情
      <Panel title="定位器候选" meta="证据：3 个候选，推荐 1 个">
        <table className="tbl"> … 策略 / 定位器 / 命中数 / 结论(.dev-tag) … </table>
        <div className="rec-row">                ← 底部动作行（保存 / 换推荐 / 复制）
          .btn-secondary「保存到元素库」 / .ibtn「复制定位器」
        </div>
      </Panel>
    </div>
  </div>
</Panel>
```

**右栏必须是 `minmax(0, 1fr)`（R2-6）**：定位器与 CSS 路径是**等宽长串**，`1fr` 的默认最小尺寸是 `auto`（= min-content = 长串不换行时的宽度），会把右栏顶宽、把左列表挤成 0。`.split` 已写死 `minmax(0, 1fr)`（`pages.css:522`），**不要自己另写一套 grid**。

`.split` 在 ≤1100px 自动降为单列（`pages.css:527-531`）——这正好是窗口下限 900 档：**两栏变上下两段**，此时 R2-6 的断言改为「左列表底边 ≤ 右详情顶边」（见 §9 几何表 G-6）。

### 1.4 校验报告

```text
<div className="dev-banner is-warn">
  <IconAlertTriangle/> role / text 定位器一律「近似」，不参与「已通过」判定；应用内通过 ≠ CI 通过。
  <span className="dev-banner-act"><button className="btn-secondary">重新校验</button></span>
</div>
<Panel title="校验报告" meta="12 步 · 唯一命中 9 · 多命中 1 · 命中 0 1 · 近似 1">
  <div className="dev-scroll">                   ← 大表必须自带滚动容器（.pnl 是 overflow:hidden）
    <table className="tbl">                      ← 列：步骤 / 动作 / 定位器 / 命中数 / 毫秒 / 结论 / 操作
      … 结论列 = .dev-tag（四态见 §3.1 的结论口径）…
      … 操作列 = .dev-tag + 「仍要保存」.btn-secondary（count=0 默认不可落库，AC-3）…
    </table>
  </div>
</Panel>
```

**报告的四种结论**（灰度可辨，AC-18 的另一半分母）：

| 结论 | 类 | 符号 + 图标 | 文案 | 依据 |
|---|---|---|---|---|
| 唯一命中 | `.dev-tag.is-ok` | `● ✓` + `IconCircleCheck` | `唯一命中` | AC-1（`precise:true` 且 `count===1`） |
| 多命中 | `.dev-tag.is-heur` | `● ⚠` + `IconAlertTriangle` | `命中 3 个（不唯一）` | AC-4（`count>1` 标黄、不可作推荐） |
| 命中 0 | `.dev-tag.is-fail` | `● ✗` + `IconCircleX` | `命中 0（不可落库）` | AC-3 |
| 近似 | `.dev-tag.is-unknown` | `● ~` + `IconHelpCircle` | `近似，不参与通过` | 方案 §6 R2（`precise:false` 一律不计入通过） |

> 「近似」用的是 `.is-unknown`（`--info`）而不是 `.is-unverified`：它不是「没测」，而是「测了但结论只有近似值」。**灰 `.is-unverified` 在本页只留给灯态的「未探测」与产物的「未验证」**，两者语义分开，不要混用（混用后灰度下 `○ —` 会同时表示三件事）。

## 2. 表单行布局骨架 —— 「输入框不重叠」的核心（②）

### 2.1 先纠一个分母：三档「可用宽度」是多少（实测口径）

主窗口 `minWidth: 900 / minHeight: 600`（`electron/main.js:1524-1525`），所以 **320px / 768px 在主窗口内不可达**；`docs/视觉-开发辅助.md` §9 已定「不承诺这两档的专用布局，只保证不塌」。AC-15 的三档按**视口宽** 900 / 1280 / 1480 测，对应容器可用宽度如下（按现值推算，**实测以 QA 的 `clientWidth` 为准**）：

| 档 | 视口宽 | 侧栏（`redesign.css:153/598-604`） | `.content-area` 可用 | `.pg` 内容盒（`padding-inline` 18 / 28） | `.pnl-body` 内容盒（`--d-panel-px` 14 / 18 / 24） |
|---|---|---|---|---|---|
| A | 900 | 60（≤900 图标态） | ≈ 840 − 15（`scrollbar-gutter:stable`，`redesign.css:7065`） | ≈ 789 | **759 / 751 / 739** |
| B | 1280 | 232（>1180） | ≈ 1033 | ≈ 977 | **947 / 939 / 927** |
| C | 1480 | 232 | ≈ 1233 | ≈ 1177 | **1149 / 1139 / 1129** |

> ⚠️ **给 QA 的一条硬提醒（别把分母算错）**：`.pg` 的 `max-width: 1480px`（`redesign.css:567`）**在 1480 视口下根本没触顶** —— 触顶需要视口 ≈ 1480 + 232 + 15 ≈ **1727px**。所以「1480 档」测到的是 `.pg` 只有 1177px 内容宽。若断言里写「`.pg` 宽 = 1480」，那条断言必然假红。

### 2.2 `.rec-row` —— 唯一新增的表单行类（透明、不登记玻璃）

属性级规格（**不是** CSS 块；实现批按此形状落到 `redesign.css` 末尾并注明原因）：

| 选择器 | 属性 | 值 | 为什么 |
|---|---|---|---|
| `.rec-row` | `display` | `flex` | R2-1：同一行控件必须走 flex，不许 `position:absolute` 叠 |
| | `flex-wrap` | `wrap` | R2-1：窄档换行而不是互相压盖 |
| | `align-items` | `flex-end` | 换行后各行控件底边对齐（按钮无 label、输入框有 label） |
| | `gap` | `var(--d-gap)` | R2-2：走密度 token，不写 `12px` |
| | `min-width` | `0` | 防 flex/grid 父级把行顶宽（`.pnl-body` 是 `.pnl` 的子级，`.pnl` 有 `overflow:hidden`） |
| `.rec-row > .field` | `flex` | `1 1 220px` | 弹性字段的**基宽**（不是宽度）：≥220px 才有意义，不足就换行 |
| | `min-width` | `0` | 同上，且让内部 `input` 能收缩到 100% |
| `.rec-row > .field.is-grow` | `flex` | `2 1 320px` | 目标页址是长串，给它双倍权重与更大基宽 |
| `.rec-row > .field.is-fixed` | `flex` | `0 0 auto` | 关联页面下拉：由内容定宽，不参与拉伸 |
| `.rec-row input, .rec-row select, .rec-row textarea` | `width` | `100%` | **这是 R2-1 的根因修法**：全仓 0 条规则给 `.tbl` 内的 input 声明宽度，导致取 UA 固有宽（`size=20` → 168/175/181px，三密度各一档）而溢出格子（`redesign.css:9222-9240` 记录了同一根因与实测数据） |
| | `min-width` | `0` | 允许收缩，不撑破 field |
| `.rec-row > .btn, .rec-row > .ibtn` | `flex` | `0 0 auto` | R2-4：按钮永不被压扁（1.9.2「半截字」事故的同类） |
| | `white-space` | `nowrap` | 同上 |
| `.rec-row` 内禁止 | — | `position:absolute`、负 `margin`、`transform` | R2-1 明令；且 `transform` 会被 `check-stacking.js` 判违规（`scripts/check-stacking.js:43`） |

**`.rec-row` 刻意不进玻璃登记表**：背景 `transparent`，没有底可换；登记会引入 40–52% 底色并推翻既有对比度结论（`视觉-开发辅助.md` §10.2 的同一条判据）。

### 2.3 三档的换行/收缩行为（不新增媒体查询）

| 档 | 目标页址（`.is-grow`） | 关联页面（`.is-fixed`） | 主按钮 + 次按钮 | 期望形态 |
|---|---|---|---|---|
| **A：不足 900（窗口下限，内容盒 739–759）** | 基宽 320，`flex-grow:2` → 独占第一行（余量 < 关联页面 + 两个按钮的固有宽） | `0 0 auto`（原生 `<select>` 固有宽 ≈ 120–180，随选项文案变） | `0 0 auto` | **允许 2 行**：第 1 行 URL + 关联页面，第 2 行按钮组；或 3 段各占一行。**「必须一行」不是断言** —— 断言只有「不重叠 + 不溢出 + 底边对齐」 |
| **B：900–1280（内容盒 927–947）** | 与关联页面、按钮组同排一行 | 同排 | 同排 | 1 行：URL 拉伸吸收余量 |
| **C：≥1480（内容盒 1129–1149）** | `flex: 1 1 auto`，吸收全部余量 | 同排 | `margin-left: auto` 贴右 | 1 行 + 动作组右对齐（右侧间距 ≤ 14px，沿用 r9 既有几何断言口径） |

三条通用规则：
1. **换行不是缺陷**：`flex-wrap` 生效即视为合规；判失败的只有「重叠面积 > 0」「`scrollWidth > clientWidth + 1`」（AC-15 原文）。
2. **密度档不改行为、只改尺寸**：`--d-control-h` 28/34/40、`--d-gap` 8/12/16、`--d-panel-px` 14/18/24 会改变固有宽度，所以**三密度各测一次**，但**不允许为某个密度档写特例**（`AGENTS.md` 密度收编口径）。
3. **不新增媒体查询**：A/B/C 三档的差异全部来自 flex 基宽 + 既有 1180/900 媒体查询 + 密度 token。加第四条断点等于再造一套断点表。

### 2.4 会被自动化几何断言的元素清单（AC-15 的分母）

扫描范围：录制页 `[role=tabpanel]` 内 + `.toolbar` 内，**可见**（`getClientRects().length > 0`）且 `clientWidth > 0`：

|---|---|---|---|
| 1 | `.rec-row input:not([type=checkbox]):not([type=radio])` | 空态 / 录制中 / 校验报告 | 目标页址；`readonly` 也算（目录选择行） |
| 2 | `.rec-row select` | 三态 | 关联页面 / 定位策略（**原生 select**） |
| 3 | `.rec-row textarea` | 录制中（手工输入定位器） | 若实现批不用 textarea 则该行判 N/A，不计入分母 |
| 4 | `.rec-row .btn-primary` | 三态 | 「开始录制」/「停止录制」（同一位置） |

> **为什么黄用 `.is-heur`**：`.dev-tag` 现成修饰只有 ok/heur/fail/unknown/unverified 五个（`redesign.css:8818-8832`），`--warn` 档只有 `.is-heur`。零新增选择器、零新增 token 是硬约束（S7），所以复用 `.is-heur`，并在表头注明「类名是历史语义（启发式命中），本页读作『降级可用』」。

**灰度可区分性（AC-18 的机械判法）**：`filter: grayscale(1)` 截图后，四种灯态的两两差异必须同时满足两条：
1. **填充不同**：绿/黄/红是实心 `●`，灰是空心 `○`；
2. **字形不同**：`✓` / `⚠` / `✗` / `—` 四个字形互不相同（三者组合下，任一态都能在「只看形状」时被唯一认出）；
3. **文案不同**：`可用` / `降级可用` / `不可用` / `未探测`（读屏与纯文本日志里也成立）。

`aria` 约定：`.dev-tag` 内符号 span `aria-hidden="true"`；灯行可点元素 `aria-label="浏览器：降级可用，仅检出 Edge；Chrome 未安装"`；`title` 只放解释，**不放结论**（结论必须在可见文本里）。

### 4.2 三条硬规则

1. **原始输出只读、不落盘**：`pre.tb-pre` 内只放 `evidence[].out` 原文，**不追加时间戳**（时间戳进 `.pnl-meta` 的 `探测于 HH:MM:SS`）。理由：[C-99] 同类思路——证据要被复制到 Issue 里，任何二次加工都会让人怀疑「这行原本是什么」。

3. **一块证据区 ≤ 20 行输出**：超出部分写「已省略 N 行（点「复制命令」拿到完整输出）」。不允许静默截断（`[C-09]` 同源要求）。

### 4.3 `↻` 位只做一处

- **面板级**：`Panel tools={<IconBtn title="重新探测本机能力">↻</IconBtn>}` → `.pnl-tools` 内 `.ibtn`，点击 `record:probe({ force: true })`，按钮进入 `disabled` + `.busy-progress` 出现（`<BusyProgress active label="正在重新探测…" />`）。
- **不做逐灯 `↻`**：逐灯刷新会让「5 盏灯是不是同一时刻的快照」这件事无法回答（用户会看到灯 1 是 10:01 的结论、灯 3 是 10:05 的）。缓存 60s 的语义也只有一个 `probedAt`（`01-方案` §5.3）。
- `↻` 位的可访问性：`title` + `aria-label` 同文案；刷新中 `aria-busy="true"`；**不加 `transform: rotate` 动画到容器上**（`check-stacking.js` 的 `transform` 会被判容器级违规），要转就转 `svg` 本身且只在 `.ibtn` 内部。

### 6.4 AC-16 的可执行判据（替换原文写法，实现批与 QA 都按这条）

```js
// 1) 逐行取「代码列」，用 \n 拼回原文
const lines = [...pre.querySelectorAll('.dev-code-line')]
  .map(line => line.lastElementChild.textContent);
const rebuilt = lines.join('\n');
assert(rebuilt === source);                    // 逐字符相等（含缩进/空格）

// 2) 空白双保险（去掉所有空白后仍相等 —— 说明没有把空白搬来搬去）
assert(rebuilt.replace(/\s/g, '') === source.replace(/\s/g, ''));

// 3) 无丢失/无重复：每个 tok-* span 的 textContent 之和 + 未包裹文本 = 该行
for (const line of pre.querySelectorAll('.dev-code-line')) {
  const code = line.lastElementChild;
  const all = [...code.childNodes].map(n => n.textContent).join('');
  assert(all === code.textContent);
}

// 4) 复制值 === 展示值（走真实复制按钮后读剪贴板）
assert(await readClipboard() === source);

// 5) 行号槽不参与（它是装饰位）
assert(pre.querySelectorAll('.dev-code-ln').length === lines.length);
```

### 6.5 >200 行的退化样式（性能保护 + 不牺牲第一眼）

| 行数 N | 渲染 | 着色 | 提示位 |
|---|---|---|---|
| N ≤ 200 | 全量 | 逐 token | 无 |
| 200 < N ≤ 400 | 前 200 行（`maxLines={200}`）+ 折叠条 | 逐 token（**这是用户第一眼看到的，必须着色**） | `.dev-banner.is-info`：「已显示前 200 行（共 N 行）」+「展开全部」`.btn-secondary`（`CodeBlock` 现成行为） |
| N > 200 且点了「展开全部」 | 全量行结构（`.dev-code-line` 保留、行号槽保留） | **退化为纯文本**（不再包 `tok-*`，整块 `--text-1`） | 块顶常驻 `.dev-banner.is-info`：「已展开全部 N 行；超过 200 行不再着色（避免长块卡帧）」。**必须写明这句**，否则用户会以为「产物没着色」是 bug |

> 为什么录制裁到 200 而不是组件默认的 `HIGHLIGHT_FOLD_LINES = 400`（`codeHighlight.ts:74`）：录制产物是「每步 3–6 行」，300 步 ≈ 900–1800 行，400 行档在录制产物上基本等于「没有折叠」；而 400 那个数字是为元素库 ≤200 元素（`pomModel.ts` 的 `MAX_ELEMENTS`）算的。**传参不改默认值**，其它页不受影响。
