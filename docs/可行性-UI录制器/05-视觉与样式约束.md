## 1. 毛玻璃：**接进既有体系，一行都不新写**

| 项 | 规则 | 依据 |
|---|---|---|
| 生效条件 | 玻璃只在 `html[data-bg='image']`（用户设了背景图）下生效；没设背景图时 40+ 条规则一条不命中。**两种模式都必须可读**，不能只对玻璃模式调样式 | 视觉文档 F1（`redesign.css:7855-7874`） |
| token | **新增 0 个**。页面骨架/卡片/表头/输入/下拉/页签/次级按钮/分页/胶囊/空态/统计卡全部已登记，复用即自动玻璃化 | 视觉文档 §10.1、M-01–M-60 |
| 容器禁止模糊 | **容器类不加 `backdrop-filter` / `filter` / `transform` / `contain`**（会新建层叠上下文，把内部下拉关进容器 → 「下拉被表头盖住 / 被 `.pnl` 的 `overflow:hidden` 裁掉」）。只有 `th` 与浮层菜单可以加模糊 | 视觉文档 F3/F4；拆分-渲染层 **G8**；`check-stacking.js:18-56` |
| 不要再"追玻璃感" | 背景图的模糊已在 `.app-bg-img` 上做过一次；容器只负责半透明底色。**实底上的 blur 是死效果**（`.tbl th` 就是现存的那处） | 视觉文档 F4 |
| 新类不登记 | 若录制页要加新类且**背景透明**（如 `.rec-*` 纯排版类），**刻意不进** `:is(...)` 登记表——登记表的作用是把实底换玻璃底，硬塞会引入 40–52% 底色并推翻对比度结论 | 视觉文档 §10.2 |
| 下拉浮层 | 优先用**原生 `<select>`**（浮层由系统画，不受层叠与裁剪影响）；非要用自定义浮层，**必须挂在 `.pnl` 之外**（`.pg` 或 `.toolbar` 内） | 视觉文档 F3、M-17/M-27 |
| 样式落点 | 追加到 `src/styles/redesign.css` **末尾**并注原因；**不改** `global.css` / `pages.css` 的中间段落（三份 CSS 有 253 处声明冲突，改前两份等于猜级联） | `AGENTS.md` 样式条；拆分-渲染层 **G7** |

## 2. 输入框与表单：**不许重叠、不许被裁、不许写死尺寸**

这条是我对「输入框重叠」的理解：**表单控件不得相互压盖，也不得被父容器裁掉或遮挡浮层**。如果你指的是别的（例如允许嵌套叠放），告诉我一处反例，我改判据。

| # | 硬约束 | 为什么 | 判据（可机械判定） |
|---|---|---|---|
| R2-1 | 同一行的控件用 **`flex` + `flex-wrap: wrap`**，禁止用 `position:absolute` 把输入框叠在一起；禁止负 `margin` 做"贴边" | 窄容器（900px 窗口下限 + 侧栏 60px 图标态）下 `nowrap` 会把控件挤到互相压盖 | 页面内所有 `input/select/textarea/button` 的 `getBoundingClientRect()` **两两不相交**（允许 0px 相邻，不允许重叠面积 > 0） |
| R2-2 | 控件宽度**不许写死 px**，走 `--d-*` 与 `.field` 的既有 flex 基线 | 密度档（`compact`/默认/`cozy`）会改 `--d-*`，写死就错位 | 三个密度档各扫一次无错位（截图 + 几何断言） |
| R2-3 | 内容不得溢出被裁：容器 `scrollWidth ≤ clientWidth`；表格类必须 `table-layout: fixed` | `.pnl` 有 `overflow:hidden`，1280 下表格取到 816px 会被裁掉操作列（1.30.2 实测过） | 对每个 `.pnl-body` 断言 `scrollWidth <= clientWidth + 1`；对表格断言列宽合计 ≤ 面板宽 |
| R2-4 | 按钮文字不许被挤成半截 | 1.9.2 踩过：登录页提示条按钮被挤成半截字 | 按钮 `scrollWidth <= clientWidth`；动作组右边缘与标题行右边缘间距 ≤ 14px（r9 既有几何断言口径） |
| R2-5 | 输入框走已登记规则 `input/select/textarea → --glass-input`，**不要自己给输入框加底色** | 已登记即自动玻璃化；自己加会与扫描门禁冲突 | 背景图模式下输入框 `computed backgroundColor` 必须**逐字符相等**于 `--glass-input` 解析值（`ui-glass-opaque-scan.js` 的 `TARGETS` 判据） |
| R2-6 | 录制过程中的**候选卡片**（左列表 + 右详情）是两栏布局，用 `grid` + `minmax(0, 1fr)`，右栏必须 `minmax(0, …)` | 不加 `minmax(0,…)` 时等宽文本（定位器、CSS 路径）会把右栏顶宽，导致左右互相挤压 | 窄/中/宽三档各断言一次两栏不重叠、长定位器换行不撑破 |

## 3. 代码着色：**要有颜色，但一个依赖都不许加**

产物预览（`.mjs` / `*.spec.ts` / Java POM）与实际生成的代码块要有着色——但仓库硬约束是「零新增依赖」（契约 §5.2-1；视觉文档 §10.1 同口径），且 **[C-99]（`:851`）要求展示与复制逐字符相同，"不得在展示层做语法高亮时的空白重排"**。

> ⚠️ **本节已按 J-3/J-4/J-5 裁定重写**：仓库里**已经有**零依赖高亮器，不要新写。

| 项 | 决定 | 依据 |
|---|---|---|
| 实现方式 | **复用** `src/utils/codeHighlight.ts`（513 行，7 个语义类 `tok-kw/ann/type/str/num/cmt/fn`）+ `src/components/ui.tsx` 的 `<CodeBlock>`（`.tb-pre.dev-code`） | 该文件第 1 条设计约束就是「**逐字符无损**：`lines[i].tokens` 拼起来必须还原该行原文（含空白）」（`:8-11`）；零依赖（`:14-15` 明确拒绝 highlight.js/prism） |
| 判据（**纯函数层，不碰 DOM**） | `highlightCode(src, lang).lines.flatMap(l => l.tokens.map(t => t.text))` 逐行拼接 **等于** 原文对应行；`totalLines` 与真实行数一致 | 裁定 J-4。`.dev-code-line` 内含 `.dev-code-ln`（行号），`<pre>.textContent` 必然混入行号数字 ⇒ 原文那个判据 100% 假红 |
| 复制 | 复制走既有 `copyPlain`，复制**原文**而不是 `innerHTML`；不走剪贴板自动清空链路 | `[C-99]` `:851` |
| 折叠阈值 | **不覆写**，用既有 `HIGHLIGHT_FOLD_LINES = 400`（`folded` 是「折叠可展开」，不是「退化纯文本」） | `codeHighlight.ts:66-74`；裁定 J-3 |
| 着色来源 | 颜色由 `redesign.css` §1.34.0 段的 `tok-*` 段定；**不在页面里覆写**，不新增色值字面量（`check-debt` 的 colorLiterals 只许降） | 裁定 J-5；`--warn`/`--accent` 在代码块内实测 4.27 / 3.51–8.24 不可用 |
| 语言参数 | 产物按类型传 `'java'` / `'ts'` / `'js'`；不认识的名称由既有实现回退 `'text'` 并置 `detected:false` | `codeHighlight.ts:49-63` |
| 禁用 | `.code2`（实底未登记，视觉文档 F7）；`.codelab-editor`（刻意不玻璃的深色区，本期不引） | 视觉文档 F7 |


**代码区容器**：一律 `.tb-pre` → `--glass-input-soft`（视觉文档 M-26 / 拆分-渲染层 §5）；`snippet` 类短片段用 `<code>` + 单行省略。

## 4. 文字与对比度（照既有判据，不自己发明）

1. 玻璃上正文（≤15px）**只允许 `--text-1` / `--text-2`**；`--text-3` **禁止**用于玻璃上的正文 / 表格内容 / 说明（浅色 + 深色背景图最差 3.05–3.98，五处不过 4.5）。
2. `.pg-sub` / `.pnl-meta` / `.empty-desc` / `.empty-hint` / `.home-stat i` / `.tbl .cell-mono` 这 6 个类靠既有 A1 规则提档到 `--text-2`——录制页只要用了它们就自动合规，**不要自己在页面里覆写颜色**。
3. 语义色只允许落在 **3px 左边条 + 14px 图标**（图形门限 3:1，实测最差 3.21）；**禁止**用 `.pill-*`（实测最差 2.78–4.41，全部不达标），三态结论一律 `.dev-tag`（文案 + 图标 + 色条，不靠颜色单独传达）。
4. 深浅两套都要过；「深色原本就不达标」不是放过的理由。

| # | 断言 | 分母 | 证伪形态（判失败） |
