## 0. 口径总则（先立规矩，再逐条判）

**[V-01] 二值判定，没有中间档。** 每条结论只允许三种：**通过 / 失败 / 未验证**。
「基本可用」「大体一致」「大部分命中」「看着没问题」一律不算通过；出现这类词即按失败处理（判定形态不成立）。
`未验证` 必须在同一条里写清缺什么（缺 JDK / 缺真实数据 / 缺工具 / 缺环境），**不得**写成通过。

**[V-02] 每条必须给分母。** 判据一律写成「实测数 / 分母 数 与 阈值 的关系」。
- 只给比例判失败：写「命中率 92%」而无 `TP=23 / 总数 25` 的计数，**直接判该条失败**。
- 分母必须是**独立于被测实现**数出来的（例：`samples` 的期望值由 `接口数×线程×循环` 手算，不许调用被测代码去算），否则「两边同错」会双绿。

**[V-03] 阈值只能来自三处：方案原文 / 契约条文 / 本文显式标注的「项目自定」。**
本文凡属项目自定的数字都带 `（项目自定）` 标记并写理由；执行阶段**不得**临时改这三个来源之一去凑一个通过。

**[V-04] 证据分两栏，不许混。**
- **前置证据**：开发自测、联调截图、golden 首跑结果 —— 只能证明「有人跑过」。
- **验收证据**：验收执行方在**指定环境**按本文命令跑出的原始输出（含 exit code、计数行、失败清单）。
只有验收证据能进结论栏。**开发自测通过 ≠ 验收通过**。

**[V-05] 原始输出不转述。** 每条证据文件必须贴：①命令原文；②原始输出的**首行 + 关键计数行 + 结果行**（不许只贴「通过」）；③exit code。
原始日志整份放 `scripts/.tmp-shots/acceptance-<yyyyMMdd-HHmm>/`（该目录已在 `.gitignore`，脚本可随时重生成）；**入库的只有摘要 + 摘录**，因为整份日志里有本机临时目录（`…\Temp\pm-ui-ud-*`）与盘符路径，会被 `AGENTS.md` 的提交前自查规则命中。

**[V-06] 每条都要回答「怎么假绿」。** 每节的「证伪形态」列写的是**这次改动最可能的假绿形态**；执行时必须至少主动构造 1 次证伪（例：把一条玻璃规则注释掉，看门禁是否真红），否则「门禁在跑、一条没拦」无法排除。

**[V-07] 门后编辑必须复跑门。** 任意门（§6 的 G-01–G-08）通过之后再改任何被它覆盖的文件，该门证据即失效。
版本锚点：证据首行必须写 `git rev-parse HEAD` 的值 + `git status --porcelain` 的条数；交付前核对：**当前工作树与证据里记录的版本一致**，不一致的证据记 `未验证`。

规则：
- 文件前缀固定 `AC-<两位序号>-` / `G-<两位序号>-`，与本文编号一一对应；**缺文件 = 该条未验证**，不得在 `INDEX.md` 里记通过。

## 3. 生成器专项（1.1 / 1.2 / 1.3 共用硬要求）

### 3.1 golden 目录与命名（照契约 C-100–C-105，不另立一套）

```
src/utils/__tests__/
  __golden__/
    restassured/<case>.java            单文件输出
    restassured/<case>/<Name>.java + <case>/__manifest.json    多文件输出
    pojo/<case>.java
    pageobject/<case>.java
  __fixtures__/
    restassured/<case>.in.json         与 golden 一一对应的输入（YAML 用 .in.yaml）
    pojo/<case>.in.json
    pageobject/<case>.in.json
```

- `<case>` 命名：小写 kebab-case，**描述输入特征**（`oas3-petstore`、`swagger2-ref-loop`、`oas31-nullable`、`json-nested-array`、`json-type-conflict`、`pom-role-locator`）。禁止 `case1`/`test2` 这类编号名（编号名无法从名字看出测的是什么，评审时只能逐个打开）。
- 写入规范：UTF-8 无 BOM、LF、末尾**恰好一个**换行、行尾无空格；比对前 `replace(/\r\n/g,'\n')` 归一后 `toBe`（**禁止** `toMatch`/`toContain` 宽松断言，契约 C-102）。
- 多文件输出：比 `path` 与 `content` **两样**（`__manifest.json` 结构见 C-103）。只比内容不比路径 → 包名/目录写错也全绿。
- golden 数量下限（分母）：`restassured` ≥ 4、`pojo` ≥ 5、`pageobject` ≥ 3，**合计 ≥ 12**（契约 C-105）。判据：`Get-ChildItem -Recurse src/utils/__tests__/__golden__ -Filter *.java | Measure-Object` 的计数 ≥ 12，且三类各自的子目录计数达下限。
- 更新口径：`UPDATE_GOLDEN=1 npx vitest run <file>` 才写。**CI 与 `npm run test:unit` 默认不设该变量**；用 `UPDATE_GOLDEN` 刷 golden 必须在交付说明里列出改了哪几个 golden 文件（契约 C-104）。执行时若发现有人用 `UPDATE_GOLDEN` 让红变绿而没说明 → 该条判失败。

### 3.2 转义专项（6 类，两类落端到端 golden，四类落内联断言）

契约 C-86 的 6 类必测（分母 = **6 类 × 每类 ≥ 1 条断言 = ≥ 6 条**，其中 2 类再各落 1 个 golden）：

| # | 输入特征 | 期望（`javaStringLiteral` 的返回体） | 落在哪 |
|---|---|---|---|
| E1 | `he said "hi"` | `he said \"hi\"` | 内联断言 + 端到端 golden `restassured-escape-quotes` |

### 3.3 `javac` 编译验证的降级口径（**关键：不许把「没编译」写成「通过」**）

- **有 JDK 时（唯一可判「编译通过」的形态）**：把生成物全部写到临时目录（`scripts/.tmp-shots/acceptance-<ts>/javac/`），执行
  `javac -encoding UTF-8 -d <out> <files...>`，**退出码 0** 才算通过；把 stderr（若为空就写「空」）与 `java -version` 首行抄进证据。
  依赖 Lombok 的 POJO 若因缺 `lombok.jar` 报 `package lombok does not exist`，**不算编译失败**，改判：去掉 `@Data` 等注解后再编一次，并在证据里写明「已剔除 Lombok 注解」（这是环境限制，不是生成物缺陷）。
- **无 JDK 时（降级）**：该条结论写 **`未验证（缺 JDK，未编译验证）`**，并补做两项语法自检：①大括号/引号配平脚本检查；②生成文本与 golden 逐字符一致。
  两项自检通过只能写「**语法自检通过，未编译验证**」——这七个字必须原样出现在证据文件与验收总表里。
- **禁止**：用「golden 比对通过」替代编译验证（契约 C-106：两者是两道门）；用 `javac` 失败的 stderr 里「只有 warning」来解释成通过（退出码非 0 即失败）。
- 计数：本批受影响条目 3 条（AC-01 / AC-02 / AC-03），每条各自记编译状态；不允许在总表里只写一个「编译：通过」覆盖三条。

### 5.3 AC-16 对比度：文字/背景实测 ≥ 4.5:1（正文）/ 3:1（大字号与图形）

**判定对象**：4 个新页在 `html[data-bg='image']`（玻璃生效）下的**合成后**对比度——不是 token 的名义色值。

**测量方法（合成法，可机器复算）**：
1. 把背景层**钉成确定的极端值**（否则对比度依赖背景图某个像素，无法复现）：用运行时注入（不改仓库字节）
   `PM_SCAN_INJECT_CSS="html[data-bg='image'] .app-bg-img{background-image:none!important;background-color:#000!important}"`，再跑一遍换成 `#fff`。
   两遍覆盖「最亮背景 / 最暗背景」两个极端；`.app-bg-dim` 压暗层**保留真实值**（浅色 = 设置值 × 0.67、深色 = 设置值，脚本已按此口径量过 opacity）。
2. 对每个取样元素：读 `getComputedStyle(el).color`（RGBA，含 `opacity < 1` 时先 `finish()` 动画，与玻璃扫描同口径）→ 从该元素向上逐层合成祖先 `backgroundColor`（RGBA over）→ 最后 over 注入的基色（`#000`/`#fff`）。
3. 用 WCAG 2.1 相对亮度公式算对比度：`(L1+0.05)/(L2+0.05)`，`L` 按 sRGB 线性化（`c ≤ 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4`）。
4. 文字取 **`color` 的 RGBA 与合成底色**；大字号判定：`fontSize ≥ 24px`，或 `fontSize ≥ 18.66px 且 fontWeight ≥ 700` → 阈值为 **3:1**；其余正文 **4.5:1**。

**取样点（每页固定 7 点，分母 = 4 页 × 2 主题 × 2 基色 × 7 点 = 112 点）**：

| # | 取样点 | 选择器（按序取第一个可见命中） | 阈值 |
|---|---|---|---|
| P1 | 页面标题 | `.pg-title, .page-title, h2` | 4.5:1（大字号时 3:1） |
| P2 | 页签文案 | `.tabs .tab2:not([disabled])` | 4.5:1 |
| P3 | 表头单元格 | `th` | 4.5:1 |
| P4 | 表格正文单元格 | `tbody td` | 4.5:1 |
| P5 | 次要/说明文案 | `.hint, .muted, .sub, small` | 4.5:1 |
| P6 | 图形：数据可视化填充块 | `.bar-fill, .chart-fill, .progress-fill, .stat-bar-fill` | 3:1（图形） |
| P7 | 图形：键盘焦点环 | 对任一按钮 `focus()` 后量 `outline-color` vs 相邻底色 | 3:1（图形） |

- 某页缺某一类（例：无 `th`）→ 该点记「该页无此样式」，**从分母显式扣除并列出扣除清单**（例：分母 112 → 实到 108，扣 P3×4）。不允许「缺失即视为通过」。
- 判据：**任一点低于阈值即失败**，且必须报出最差点（page/theme/基色/selector/ratio/文字色/底色的 RGBA 全值）。
- **大字号与图形不得只靠颜色区分含义**（方案 §12.2-4：「启发式/无法判定」这类结论不能只靠颜色）——P6/P7 另加一条人工检查：`unknown` 态除了颜色还有文字标记（截图 1 张，肉眼确认）。
- 取证：`scripts/` 下暂无对比度工具 → 用一次性脚本 `.tmp-contrast-audit.js`（`.tmp-*.js` 已在 `.gitignore`，跑完删；长期化另立 `scripts/` 任务）。脚本内用 `scripts/lib/app.js` 的 `launch`/`waitForWindow`/`ensureUnlocked`/`applyBackground`/`navTo`/`setTheme` 起窗口，逐页逐点算比值并打 CSV 到 `scripts/.tmp-shots/acceptance-<ts>/contrast.csv`。
- 降级：无 Electron 图形环境（无 GPU 的容器）时无法真实渲染 → 该条记 `未验证（无图形环境）`（§7 D-10）。

### 5.4 AC-17 帧时间：玻璃常驻后不得退化（基线 60fps / 17ms）
