## 1. 代码高亮组件契约

### 1.1 为什么自己做（三维取舍，结论：自研）

| 维度 | highlight.js / prism | 自研 `codeHighlight.ts`（≈120 行） | 判定 |
|---|---|---|---|
| **团队可修** | 主题是它自己的 CSS 变量体系；要落到 `--info/--ok/--bad` 就得覆盖它 20~40 条主题规则（不可枚举），且与 `check-debt-budget`（202/64/15 顶格）和 `ui-glass-opaque-scan` 的判据互相打架 | 7 个类名 + 7 条已落 CSS（`redesign.css:9088-9101`），配色口径单一真源；tokenizer 是纯函数，能断言「逐字符无损（round-trip）」这类不变量 | **自研** |
| **生态** | 每语言 `registerLanguage`，关键字表随语言版本更新 → 升级即扩大回归面；四页只需要「能读」级别（关键字/字符串/注释/数字），不需要完整语法 | 6 种语言共用一套线性扫描状态机；语言差异只是"关键字集合 + 注释/字符串定界符"三个配置 | **自研** |
| **体积/依赖卫生** | 引一个 6 语言的 bundle；而 `docs/agents/code-conventions.md`「依赖卫生」要求加依赖前先证明真的用得上（`react-router-dom` 就是这么删掉的）。本项目 `dependencies` 只有 12 个，最近新增 `qrcode`/`js-yaml` 都附了明确理由 + `React.lazy` 约束（AGENTS.md 1.11.0） | 零新依赖；`package.json` 不动 | **自研** |

> 反面意见（照实写）：自研必然**不如 hljs 准**——它不识别用户自定义类型、泛型嵌套、Java 文本块 `"""`（本契约按普通字符串处理）。
> 这是有意的取舍：四页代码块的作用是「读生成物 / 看命中原文」，不是编辑器；错标的代价是颜色不对，不是信息丢失。

### 1.3 API（`src/utils/codeHighlight.ts`，纯函数、零依赖、不 import React）

```ts
export type CodeLang = 'java' | 'json' | 'js' | 'ts' | 'sql' | 'xml' | 'text';
export type TokClass = '' | 'tok-kw' | 'tok-ann' | 'tok-type' | 'tok-str' | 'tok-num' | 'tok-cmt' | 'tok-fn';

export interface CodeToken { text: string; cls: TokClass }
export interface CodeLine { no: number; tokens: CodeToken[] }

export interface HighlightResult {
  lang: CodeLang;      // 实际生效的语言（回退后是 'text'）
  detected: boolean;   // false = 语言无法识别 / 传了不认识的值，已回退为纯文本
  lines: CodeLine[];   // 已按 maxLines 截断
  totalLines: number;  // 原文真实行数（不受 maxLines 影响）
  folded: boolean;     // === totalLines > lines.length，渲染层据此出「展开全部」
}

/** 默认折叠阈值：超过它的内容只 tokenize 前 maxLines 行 */
export const HIGHLIGHT_FOLD_LINES = 400;

export function langFromPath(path: string): CodeLang;   // 扩展名映射；认不出 → 'text'（detected=false 由 highlightCode 给）
export function highlightCode(
  code: string,
  lang?: CodeLang | string,          // 省略 = 'text'；传不认识的值 → 回退 'text'（不抛错）
  opts?: { maxLines?: number },      // 缺省 HIGHLIGHT_FOLD_LINES；展开全部时传 Number.POSITIVE_INFINITY
): HighlightResult;
```

**支持语言与判定依据**（`langFromPath` 的扩展名表）

| 语言 | 扩展名 | 注释定界 | 字符串定界 | 备注 |
|---|---|---|---|---|
| `java` | `.java` | `//`、`/* */` | `"` `'` | **本期唯一真正会走到的语言**：生成物只有 `.java`（`pageobject.ts:250`、`restassured.ts:255/261`、`pojo.ts:337`） |
| `json` | `.json` | 无 | `"` | 键名按 `tok-str`，`true/false/null` 按 `tok-kw` |
| `js` / `ts` | `.js` `.jsx` `.mjs` `.cjs` `.ts` `.tsx` | `//`、`/* */` | `"` `'` `` ` `` | 模板串整段 `tok-str`（不做 `${}` 内层高亮，明写为已知简化） |
| `sql` | `.sql` | `--`、`/* */` | `'` | 关键字大小写不敏感 |
| `xml` | `.xml` `.html` `.xsd` | `<!-- -->` | `"` `'`（属性值） | 标签名 `tok-type`，属性名 `tok-kw` |
| `text` | 其它 / 未知 | — | — | 不扫描：整行 1 个 `cls:''` token（O(1)/行，成本可预测） |

**未知语言回退**：`highlightCode(code, 'kotlin')` → `{ lang:'text', detected:false }`，**逐行原样返回、不丢字符、不抛错**。页面上不提示"不支持"（噪声），但 `detected` 供单测与将来调试。

**超长内容折叠阈值 = 400 行**，依据：单页元素上限 `MAX_ELEMENTS = 200`（`pomModel.ts:46`）。~~契约初稿按「每元素 5 行 + 1 空行」估成 200 元素 ≈ 1,230 行~~ —— **实现期实测（t6，两条样本）修正为：3 个元素 = 44 行、120 个元素 = 629 行，即每条目 5 行 + 文件头固定 29 行（5n + 29）⇒ 200 元素 ≈ 1,029 行**；400 行 ≈ **74 个元素**（`(400 − 29) / 5`）。结论不变（200 元素的生成物仍远超 400 行，默认折叠是对的），错的只是算术。超过 400 行的生成物默认折叠，用户点一次「展开全部」再全量 tokenize + 渲染。

**5 条可断言不变量**（单测直接锁，见 §1.7）

1. **无损（仅在未折叠时断言，`maxLines ≥ totalLines`）**：`lines.map(l => l.tokens.map(t => t.text).join('')).join('\n') === code.replace(/\r\n?/g, '\n')`（CRLF 归一后逐字符相等）。折叠时该式只对前 `lines.length` 行成立。
2. **无空 token、无相邻同类**：每行至少 1 个 token；相邻 token 的 `cls` 必不相同（合并过）。
3. **行号连续**：`lines[i].no === i + 1`；`lines.length === Math.min(totalLines, maxLines)`。
4. **纯函数**：同输入两次调用深度相等（无时间/随机/全局状态）。
5. **零侧写**：模块内不出现 `document`/`window`/`React`（保证能在 node 环境跑 vitest）。

### 1.5 是否 `dangerouslySetInnerHTML`：**不用，用 span 渲染**

| 理由 | 证据 |
|---|---|
| ① 全仓库 **0 处**使用，引入它就是给唯一一条代码渲染路径开一个新面 | `grep dangerouslySetInnerHTML src/` → 0 命中 |
| ② 用 span 渲染，转义点归 React（`&`/`<`/`>` 自动转义）；innerHTML 版本得自己维护一份 HTML 转义，任何语言分支漏一处就是 XSS 面 —— 而这里渲染的是**用户本机项目里的代码**（不可信输入），不是我们自己写的常量 | `GeneratedFiles.tsx:92` 现在就是 `{file.content}` 文本节点，无转义逻辑 |
| ③ 折叠/展开/切页签时 React 只改局部；innerHTML 每次整块替换，长文件上等于每次重建整棵树 | §1.6 折叠交互 |

代价（照实写）：span 渲染的 DOM 节点数 ≈ token 数（400 行 × 8 ≈ 3,200 个），比 innerHTML 多；这也是把默认折叠压到 400 行的原因。

### 1.6 渲染组件契约：`CodeBlock`（加进 `src/components/ui.tsx`，与 `Panel/Empty/Field` 同一入口）

```tsx
export function CodeBlock({ code, lang, showLineNumbers = true, maxLines = HIGHLIGHT_FOLD_LINES }:
  { code: string; lang?: CodeLang | string; showLineNumbers?: boolean; maxLines?: number }) { ... }
```

- **DOM 结构**（`class` 全部来自已落 CSS，0 内联样式；**用 `<span>` 不用 `<div>`**：`<pre>` 的内容模型是 phrasing content，`<div>` 塞进 `<pre>` 是非法 HTML——浏览器能渲染，但别把 validator / SSR 的坑留给下一批）：
  ```html
  <pre class="tb-pre dev-code">
    <span class="dev-code-line"><span class="dev-code-ln">1</span><span>…tokens…</span></span>
    …
  </pre>
  ```
- **行号可选中性**：`.dev-code-ln` 已带 `user-select:none`（`redesign.css:9084`）→ 用户拖选复制只拿到代码、不会把行号抄进剪贴板；「复制此文件」走 `copyPlain(file.content)`（`GeneratedFiles.tsx:104`），不读 DOM。两条路径都不依赖行号，所以行号是**纯装饰**，`showLineNumbers={false}` 可以随时关掉。
- **折叠**：**显隐条件用 `totalLines > maxLines`，不要用 `hl.folded`**（t6 实现期修正：展开后 `folded` 立刻变 `false`，用它当条件会让按钮在展开那一刻消失、用户收不回去。契约初稿写 `folded === true` 是漏了这个边界）。满足条件时默认只渲染前 `maxLines` 行，`<pre>` 之后追加一条常驻说明 + 一个按钮（视觉口径 §4.3「可展开只给长内容」）：
  `已显示前 400 行（共 {totalLines} 行）` + `展开全部`（点击后以 `maxLines = Infinity` 重新 `highlightCode`，并置 `aria-expanded`；展开后文案改「已全部展开（共 M 行）」+ `收起`，要能点回去）。
  **不许静默截断**（`[C-09]` 的同源要求）：折叠必须写清「显示了多少 / 一共多少」。
- **`showLineNumbers={false}` 时保留空的左列槽**（t6 实现期修正）：`.dev-code-line` 是 `grid-template-columns: 4ch 1fr`，少一个子元素会把代码文本挤进 4ch 那一列。关行号只隐藏 `dev-code-ln` 的**内容**，槽位仍占位（不新增类名、不写内联样式）。
- **`useMemo`**：`useMemo(() => highlightCode(code, lang, { maxLines }), [code, lang, maxLines])`，切页签不重算。
- **语言来源**：调用方传 `langFromPath(file.path)`，不要在新的地方手写扩展名判断。

**CSS 欠账：2 条，归 ui，不改就没有对应效果**（都不新增 token、不写字面量色值、无 `!important`）

| # | 规则 | 为什么少不了 | 不加的后果 |
|---|---|---|---|
| 1 | `.dev-code-line { display: grid; grid-template-columns: 4ch 1fr; gap: 8px; }` | `.dev-code-ln`（`redesign.css:9080-9086`）只有颜色/字号/右对齐，在 `<pre>` 里作为 inline span 无法形成「槽」；`4ch` 固定列宽（数字是 `tabular-nums`，`ch` 即数字宽）保证**跨行对齐**。**不能用 `auto`**：每行各自成一个 grid，`auto` 会按本行位数取值 → `9` 与 `100` 两行的代码起点不同，越往下越参差。`4ch` 覆盖到 9,999 行（本批最大 ≈1,230 行，§1.3），超出时数字会溢出 1 列（可接受，调用方也可关行号） | 行号与代码同流、随行宽漂移；此时只能 `showLineNumbers={false}` |
