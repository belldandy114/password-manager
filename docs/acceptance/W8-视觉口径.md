## 2. 代码块视觉口径（C3）：`.dev-code`

**三条结论**：① 代码区**不玻璃**，底色 `var(--surface-inset)`（深 `#0f1213` / 浅 `#f8f9fb`），玻璃模式同一实底，覆盖 `redesign.css:8060-8065` 给 `.tb-pre` 的 `--glass-input-soft`；写法必须是 `html[data-bg='image'] .dev-code{background-color:var(--surface-inset)}`（(0,2,1) 同特异性靠末尾胜出，只写 `.dev-code` 会被 8060 压掉 = 改了没效果）。② 容器与排版复用 `.tb-pre`，只加 `.dev-code` 修饰 → `class="tb-pre dev-code"`（现状 `GeneratedFiles.tsx:92`、`Toolbox.tsx:1475` 就是 `.tb-pre`）。③ `--accent`/`--warn` 块内禁用（§2.3）。

**2.2 语义分类 → 落点**（深浅各自实底；玻璃模式收敛为同一实底）

| 语义 | 深色 | 浅色 | 玻璃 | 形式通道 | 为什么这样定 |
|---|---|---|---|---|---|
| 默认（标识符/括号/操作符） | `--text-1` | `--text-1` | 同实底 | 400 | — |
| 关键字 / 注解（`@Test`） | `--info` | `--info` | 同实底 | 600 | 蓝=最主流关键字色；Java 里注解属修饰符，`@` 前缀够区分，**同族合并**（4 色相不够分 7 类） |
| 类型（String/int/By/Response） | `--ok` | `--ok` | 同实底 | — | 青绿，接近 IntelliJ 类型色 |
| 字符串 / 数字 | `--bad` | `--bad` | 同实底 | 数字加 `tabular-nums` | 红=Xcode 系字面量色，两者**同族合并**。**代价：块内 `--bad` 不再表示错误**（错误只走 `.dev-banner`/`.dev-tag`） |
| 注释（`//`、`/** */`） | `--text-2` | `--text-2` | 同实底 | italic | **禁用 `--text-3`**（弱化文字，与「正文 ≥4.5」口径混淆） |
| 方法调用（`driver.findElement`） | `--text-1` | `--text-1` | 同实底 | 600 | 4 色相已用尽；加粗 + 其后必跟 `(` |
| 行号槽 | `--text-3` | `--text-3` | 同实底 | 右对齐 `--fs-2xs` | 行号是装饰位，非正文（实测 ≥4.93，见 §2.3） |

**2.3 对比度依据**（实测；底色 = `--surface-inset`，`tokens.css:19`/`:228`）

| token | 深 `#0f1213` | 浅 `#f8f9fb` | 判定 |
|---|---|---|---|
| `--text-1` / `--text-2` / `--text-3` | 15.42 / 7.87 / 6.16 | 16.75 / 6.20 / 4.93 | 正文·注释·行号 ✓（最差 4.93） |
| `--info` / `--ok` / `--bad` | 5.38 / 5.78 / 4.75 | 5.14 / 4.77 / 5.06 | 关键字·类型·字面量 ✓（最差 4.75） |
| `--warn` | 7.09 | **4.27** | ✗ 禁用（浅色 <4.5） |
| `--accent`（6 档） | 3.51（indigo）–8.24（amber） | 3.46–4.89 | ✗ 禁用（跨档不稳定 + 取色可变） |

**反证（为什么不能保留玻璃底）**：`--glass-input-soft` 合成底 深 `#212425` / 浅 `#dbdbdc`，四色相实测 `--ok` 4.82/3.63、`--warn` 5.91/**3.25**、`--bad` 3.96/3.85、`--info` 4.48/3.91 —— 浅色全部 <4.5，与 `.pill-*` 不能用是同一判据（视觉doc §6.2）。复现：`ratio=(L1+.05)/(L2+.05)`，玻璃底按 `tokens.css:177`（深 54% / 浅 42%）叠纯白/纯黑背景图取最差。

**4.2 三态写法**

| 态 | 承载 | 硬要求 |
|---|---|---|
| 空（未开始 / 有输入无结果） | `<Empty icon title desc hint action>` / `<Empty compact>` | 现在是什么 / 下一步做什么 / 边界说明三件齐，`action` ≤1 个主按钮；**有输入无结果时必须回答「为什么是 0」**（正例 `AssetLedger.tsx:341-349`） |
| 加载（长任务 / 局部刷新） | `<BusyProgress>` | `role=status` 在组件内（`ui.tsx:170-177`）；玻璃登记为 `--glass-input-soft`（`redesign.css:8774-8778`）；局部刷新保留旧结果 + 顶部进度条，**不清空、不丢滚动位置** |
| 错误 | `.dev-banner.is-warn` + 重试次按钮 / `.dev-banner.is-error[role=alert]` | 阻断类**必须写「有没有落盘」**（正例 `AuditTab.tsx:300-309`）；截断类走 `.dev-banner.is-info`，常驻结果表上方、不进折叠 |

**4.3 代码体检「结论说明」区：提示条，不是可展开面板**

现状 `AuditTab.tsx` 结果表上方可同时叠 9 个渲染点的 `.dev-banner`（`:170/:195/:229/:230/:261/:271/:278/:289/:300`），表格被推到折线以下。定稿：

| 位次 | 内容 | 形态 |
|---|---|---|
| 1 | 口径句「启发式检查，非语法树分析，可能误报/漏报，只在本机展示」（`AuditTab.tsx:170-175`） | `.dev-banner.is-info`，**常驻不可折叠**（用户能否读懂「启发式」标签全靠它） |
| 2 | 阻断（后端计数不一致、扫描失败） | `.dev-banner.is-error[role=alert]` 置顶 + 说明是否落盘 |
| 3 | 本次运行条件（truncated / suppressed / 跳过符号链接） | **合并成一条** `.dev-banner.is-warn`，用「；」连接、数字一个不少（`[C-30]`/`[C-54]` 口径不变），位置在 `.dev-tag` 汇总行之下、表格之上 |
| 4 | 命中原文 / 规则说明等长文本 | 可展开（`<details>` 或 `<Panel collapsible>`，默认收起），不占常驻高度 |

判据：常驻区 ≤4 行文本；同档（warn/info）≥2 条即合并。**「可展开」只给证据原文，不给结论与运行条件** —— 把截断/跳过折叠起来等于隐藏「这次扫描不完整」，与视觉doc §7「截断必须常驻」冲突。
