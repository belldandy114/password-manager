### 0.1 全局不变量（违反即判契约不通过）

1. **信封唯一**：所有新增 channel 一律 `{ success: boolean, data?: T, error?: string, code?: string, retryAfterMs?: number }`，禁止裸返回数组/字符串。
2. **明文禁令**：主密码明文**永不**出现在任何 IPC 返回值、preload 暴露面、渲染层内存之外的位置、日志、审计 detail、错误信息里。渲染层拿不到它，也就无法把它写进 localStorage / sessionStorage。
3. **三方同步**：每个新 channel 必须在 **4 处**同时存在——① `electron/ipc-*.js` 里 `ipcMain.handle`；② `electron/preload.js` 里 `ipcRenderer.invoke` + 暴露方法名；③ `src/types.ts` 的 `ElectronAPI` 同名方法声明；④ 渲染层调用方。缺任一处 `npm run check:ipc` 报 error（`scripts/check-ipc-contract.js:5` 的口径）。
4. **拆分守卫**：新增的 `electron/ipc-*.js` 模块**不得**裸用 `DATA_DIR / DATA_FILE / mainWindow / loadVault / writeFileAtomic …`，必须从 `deps` 解构（`scripts/check-ipc-contract.js:87-92` 的 `MAIN_ONLY_STATE`）。裸用会 `ReferenceError` 被 handler 的 try/catch 吞掉，表现成「点按钮没反应」。
5. **写盘只走既有工具**：新增落盘一律 `writeFileAtomic`；vault/trash 读写只走 `loadVault/saveVault/loadTrash/saveTrash`（AGENTS.md「性能约束」）。
6. **纯函数可单测**：新增的判定逻辑（tab 归一化 / autologin 解析 / 卸载信息）必须落在不 `require('electron')` 的模块里，`safeStorage`、`isPackaged`、`execPath` 一律**由调用方注入**作为参数。

## 1. R1 设置页 7 tab 契约

### 1.1 tab id 全集（唯一真源）

`SettingsTab` 联合类型 = 下列 7 个字面量的并集，**不得**出现第 8 个 id：

| 顺序 | id | 名称 | hint（rail 副标题） | 收纳（内容归属，供归属争议时裁决） |
|---|---|---|---|---|
| 1 | `security` | 安全 | 主密码 / 锁定 / 剪贴板 | 修改主密码、安全词、自动锁定、剪贴板清空延迟、剪贴板历史、**启动免密（R2）** |
| 2 | `appearance` | 外观 | 主题 / 背景 / 玻璃 | 主题、强调色、密度、自定义背景图、图片不透明度、模糊、压暗、**玻璃强度（R4）** |
| 3 | `interaction` | 交互 | 浏览器 / 快捷键 / 托盘 | 浏览器路径、三个全局快捷键、托盘与窗口行为、防截屏、开机自启 |
| 4 | `data` | 数据与备份 | 备份 / 目录 / 自检 | 原 `data` tab 内容原样 |
| 5 | `tasks` | 定时任务 | 巡检 / 禅道 / 回归 | 原 `tasks` tab 内容原样 |
| 6 | `about` | 关于与更新 | 版本 / 更新 / 日志 | 原 `about` tab 内容原样 |
| 7 | `danger` | 危险区 | 卸载 / 清空 / 重置 | **卸载软件（R3）**、清空遗留数据（`LEGACY_KEYS`）、重置数据目录 |

- 顺序即 rail 渲染顺序（`src/pages/Settings.tsx:2389` 的 `TABS.map`）。
- tab 集合必须与 nav 渲染同源：nav 与内容区都从同一份 `TABS` 派生，禁止两处各写一份。

### 1.3 `normalizeSettingsTab(raw)` 算法（逐字实现）

```ts
// src/utils/settingsTab.ts —— 纯 TS，禁止 import React / JSX（否则单测与 build 都变味）
export type SettingsTab = 'security' | 'appearance' | 'interaction' | 'data' | 'tasks' | 'about' | 'danger';
/** 图标只存 Icons 的键名（src/components/ui.tsx:29 的 Icons），节点由 Settings.tsx 渲染 */
export type SettingsTabIcon = 'lock' | 'tool' | 'key' | 'db' | 'clock' | 'note' | 'trash';
export const SETTINGS_TAB_KEY = 'pm.settings.tab';   // 键名不换，只扩取值范围
export const SETTINGS_TABS: readonly { id: SettingsTab; label: string; hint: string; icon: SettingsTabIcon }[];
export const SETTINGS_TAB_IDS: readonly SettingsTab[];
export const LEGACY_TAB_MAP: Record<string, SettingsTab>;
export function normalizeSettingsTab(raw: string | null | undefined): SettingsTab;
```

`Settings.tsx` 侧只保留一层映射：`<Icons[t.icon] size={14} />`（7 个键都已存在于 `Icons`），**不得**把图标节点塞回 `settingsTab.ts`。

判定顺序（**短路，不可重排**）：

1. `raw` 为 `null` / `undefined` / `''` / 非字符串（防御 `localStorage` 被塞对象后 `toString` 出 `[object Object]`）→ `'security'`
2. `raw` 去首尾空白、转小写（`'  Appearance '` → `appearance`；大小写敏感差异不得导致回落）
3. `LEGACY_TAB_MAP[normalized]` 命中 → 用映射值作为候选
4. 否则候选 = `normalized` 本身
5. 候选 ∈ `SETTINGS_TAB_IDS` → 返回候选；否则 → `'security'`（**未知 id 兜底，唯一兜底值**）

- 幂等性：`normalize(normalize(x)) === normalize(x)`（对任意输入成立，必须进单测）。
- 副作用：**无**。不读不写 localStorage（读写在调用方 `useState` 初始化与 `useEffect`）。
- 存储：`localStorage['pm.settings.tab']` 只写归一化后的值（`Settings.tsx:480` 现状已如此，保持）。

**单测必测输入（qa 按此写 `src/utils/__tests__/settingsTab.test.ts`，≥ 24 条）**：
`null` / `undefined` / `''` / `'   '` / `'general'` / `'browser'` / `'shortcuts'` / `'security'` / `'data'` / `'appearance'` / `'tasks'` / `'about'` / `'interaction'` / `'danger'` / `'update'` / `'backup'` / `'password'` / `'hotkey'` / `'tray'` / `'theme'` / `'uninstall'` / `'Appearance'` / `'  DANGER '` / `'unknown-xyz'` / `'__proto__'` / `'constructor'` / `'0'` / `'[object Object]'`。
其中 `__proto__` 与 `constructor` 必须回 `security`（用 `Object.create(null)` 或 `hasOwnProperty` 判定，防止原型链命中）。

### 1.4 `renderTabContent()` 的 switch 兜底（禁止落空路径）

`src/pages/Settings.tsx:974` 的 `switch (activeTab)` 必须满足：

1. 7 个 `case` 齐全，每个都 `return` 出内容。
2. **必须有 `default:`**，`return` 与 `security` 分支**完全相同**的内容（用同一段 JSX/同一子组件渲染，禁止复制粘贴导致漂移），并在开发期 `console.warn('[settings] 未知 tab 已回落 security:', activeTab)`。
3. 归一化保证 `activeTab` 只可能是 7 个合法值；`default:` 是二道保险，**不可**简化成 `default: return null`（那就是白屏）。
4. `TABS.find(t => t.id === activeTab)` 为 `undefined` 时，rail 的选中态不得导致 nav 高度塌陷（`is-active` 只是类名，不参与布局）。

验收：用 DevTools 把 `localStorage['pm.settings.tab']` 依次写成 §1.3 全部历史 id → 刷新 → 每次都能进到对应 tab 且**不出现空内容区**。

## 2. R2 启动免密：4 个 channel 契约

### 2.1 共同约定

| 项 | 约定 |
|---|---|
| 传输 | `ipcRenderer.invoke`（请求/响应），不用 `send` |
| 暴露方法名 | `authAutoUnlockStatus` / `authEnableAutoUnlock` / `authDisableAutoUnlock` / `authAutoUnlock`（与既有 `authXxx` 命名一致，`preload.js:14-22` 同区） |
| 注册模块 | `electron/ipc-auth.js`（`registerAuthIpc(deps)` 内，已持有 `loadVault` / `setPassword` / `setUnlocked` / `clearCaches`） |
| 信封 | `{ success, data?, error?, code?, retryAfterMs? }` |
| 加密 | `safeStorage.encryptString(masterPassword)` → base64 落盘；**不使用** `encrypt()`（那是 AES-256-GCM + 主密码自派生，解决不了「启动时还没有主密码」的问题） |
| 状态真源 | **只有 `<DATA_DIR>/autologin.json` 是否存在 + 能否解析**。见 D2：**不写进 AppSettings** |
| 进程级抑制位 | `autoUnlockSuppressed: boolean`，模块作用域（`electron/main.js`），进程重启自动归零 |

### 2.2 `auth:auto-unlock-status`

| 项 | 内容 |
|---|---|
| 入参 | 无（`() => …`，不传参） |
| 出参 `data` | `AutoUnlockStatus = { enabled: boolean; available: boolean; reasonCode?: AutoUnlockReasonCode; reason?: string; updatedAt?: string }` |
| `enabled` 语义 | `autologin.json` 存在 **且** 可解析 **且** `v===1` **且** `blob` 为非空 base64 字符串。**不解密**（启动期每多一次 DPAPI 调用就多一段黑屏） |
| `available` 语义 | `safeStorage.isEncryptionAvailable()` 的当前值 |
| `reasonCode` 枚举 | `'safe-storage-unavailable'` \| `'autologin-corrupt'` \| `'autologin-version-unsupported'` \| `'not-setup'`（未初始化时可选返回） |
| `reason` | 中文人话，与 `reasonCode` 一一对应，例：`'系统未提供安全存储（DPAPI 不可用），启动免密不可用'` / `'启动免密配置文件已损坏，已停用'` |
| 错误码 | **无**。任何读取异常都必须归成 `success:true` + `enabled:false` + `reasonCode:'autologin-corrupt'`。**禁止** `success:false`（会让启动态卡在错误弹窗） |
| 鉴权 | 无（必须在**未解锁**状态下也能调；这是启动时序的第一步） |
| 幂等 / 并发 | 纯读，幂等；并发调用安全（只读） |
| 限流 | 无（渲染层启动时只调 1 次；不排除设置页再调 1 次） |

示例（成功）：
```json
{ "success": true, "data": { "enabled": true, "available": true, "updatedAt": "2026-12-01T02:03:04.000Z" } }
```
示例（safeStorage 不可用）：
```json
{ "success": true, "data": { "enabled": false, "available": false, "reasonCode": "safe-storage-unavailable", "reason": "系统未提供安全存储（DPAPI 不可用），启动免密不可用" } }
```

### 2.3 `auth:enable-auto-unlock`

| 项 | 内容 |
|---|---|
| 入参 | `{ password: string }` |
| 入参边界 | 必填；必须是 `string`；`trim()` 后长度 ∈ [1, 256]；超长/空/非字符串 → `code:'invalid-argument'` |
| 出参 `data` | `{ enabled: true; updatedAt: string }`（ISO 8601） |
| 错误码表 | 见下 |
| 鉴权 | ①**前置**：`appUnlocked === true`（`getPassword() !== null`），否则 `code:'locked'`；②**再验一次主密码**：`pbkdf2Sync(password, settings.salt, KEY_ITERATIONS, 64, 'sha512')` 与 `settings.masterPasswordHash` 比对，**且** `loadVault(password)` 非 null（与 `auth:verify` 同口径，防止 settings 与库不同源时把错密码加密进去） |
| 幂等 | 幂等：重复调用 = 用新 blob 覆写同一文件，不累加、不改语义。文件已存在时**直接覆写**（`updatedAt` 更新） |
| 限流 | 独立计数：`enableFailures` / `enableLockedUntil`，阈值 `5 次 → 30s`（复用 `LOGIN_MAX_FAILURES` / `LOGIN_LOCK_MS` 常量值，但**计数器与登录失败分开**，避免「设置页输错密码把登录锁了」）。冷却期内返回 `code:'rate-limited'` + `retryAfterMs` |
| 明文 | `password` 只在 handler 栈上使用；禁止 `console.log`、禁止进 `appendAudit.detail`（审计只记 `{ action:'auto-unlock-enable' }`） |

错误码表：

| code | `success` | `error`（用户可读） | 客户端处置 |
|---|---|---|---|
| `locked` | false | `请先解锁应用再开启启动免密` | 不弹错误，回登录态 |
| `not-setup` | false | `尚未初始化主密码` | 引导去初始化 |
| `invalid-argument` | false | `请先输入主密码` | focus 密码框 |
| `wrong-password` | false | `主密码不正确`（附剩余次数提示可选） | 清空密码框，留在原地 |
| `rate-limited` | false | `尝试次数过多，请 30 秒后再试` | 按钮置灰倒计时 |
| `safe-storage-unavailable` | false | `系统未提供安全存储（DPAPI 不可用），无法安全保存主密码` | 开关保持禁用 |
| `write-failed` | false | `写入启动免密配置失败：<原因>` | 开关回退到关闭态 |

示例（成功）：
```json
{ "success": true, "data": { "enabled": true, "updatedAt": "2026-12-01T02:03:04.000Z" } }
```
示例（密码错）：
```json
{ "success": false, "code": "wrong-password", "error": "主密码不正确" }
```

### 2.4 `auth:disable-auto-unlock`

| 项 | 内容 |
|---|---|
| 入参 | 无 |
| 出参 `data` | `{ enabled: false }` |
| 错误码 | `locked`（`请先解锁应用再修改启动免密`）／`delete-failed`（`关闭启动免密失败：<原因>`） |
| 鉴权 | `appUnlocked === true`（降低风险方向的操作用户已确认；但未解锁时不允许碰文件，防止锁屏态被其它本地进程驱动） |
| 幂等 | **强幂等**：文件不存在也返回 `success:true, data:{enabled:false}`（不报错） |
| 限流 | 无（无密码校验） |

### 2.5 `auth:auto-unlock`

| 项 | 内容 |
|---|---|
| 入参 | 无 |
| 出参 `data` | `AutoUnlockResult = { unlocked: boolean; vault?: VaultData; reasonCode?: AutoUnlockReasonCode \| 'session-locked' \| 'no-credential' \| 'decrypt-failed'; reason?: string }` |
| 成功语义 | `unlocked: true` + `vault`（= `loadVault(password)`，与 `session:unlock` 的 `data` 同形，渲染层可直接 `setVaultData(vault)`） |
| 主进程内部动作（顺序固定） | ①读 `autologin.json` → ②`safeStorage.decryptString` 得密码 → ③执行与 `session:unlock` **完全相同的副作用**：`clearCaches()` → `loadVault(pw)` → `setPassword(pw)` / `setUnlocked(true)` / `bumpEpoch()` / `touchActivity()` → 定时器补跑（`ztRestartNotify` / `ztLoadSeen` / `backupVaultOncePerDay` / `loadClipHistory`）→ ④返回 `{ unlocked:true, vault }` |
| `unlocked:false` 是**正常态** | 一律 `success: true`（不弹错误、不阻断启动），由渲染层落回登录页。**只有** handler 自身抛未预期异常才 `success:false, code:'internal'` |
| reasonCode 枚举与触发 | `'not-setup'`（无 vault 文件）／`'no-credential'`（`autologin.json` 不存在或空 blob）／`'safe-storage-unavailable'`／`'session-locked'`（本次进程内已手动锁定，抑制位为 true）／`'decrypt-failed'`（DPAPI 解不开，**并自清文件**）／`'vault-corrupt'`（密码解开了但库解不开，文件保留但本次不重试） |
| 鉴权 | 无（启动期）——**凭据来自 DPAPI 解密结果，不接受任何渲染层传入的密码**。入参必须为空，多传的参数一律忽略 |
| 幂等 / 并发 | 幂等（再次调用结果相同：已解锁则直接返回当前会话的 vault，不重复 bumpEpoch）／需串行化：进程内 `autoUnlockInFlight` 守卫，并发第二次直接返回当前结果，避免两次 `loadVault` + 两次备份定时器 |
| 限流 | 启动期只调 1 次；主进程侧加 `autoUnlockAttempts`：同一进程内 `decrypt-failed` 连续 ≥ 3 次后不再尝试（返回 `decrypt-failed`），防止渲染层重试循环疯狂打 DPAPI |
| 明文 | **返回值禁止含 password**。`vault` 是库数据（含条目密码，属于业务数据，与 `session:unlock` 现状一致），但**主密码本身绝不出现** |

示例（成功，字段省略）：
```json
{ "success": true, "data": { "unlocked": true, "vault": { "entries": [], "tags": [] } } }
```
示例（本次进程内已锁定）：
```json
{ "success": true, "data": { "unlocked": false, "reasonCode": "session-locked", "reason": "本次已手动锁定，需输入主密码" } }
```

### 2.6 明文禁令落地检查点（5 条，qa 逐条断言）

1. `preload.js` 中 4 个新方法均不含把参数回传的写法（`(data) => ipcRenderer.invoke(...)` 只在启用接口出现，且 `data` 只进不出）。
2. `grep -n "password" electron/preload.js` 结果里，新方法块不得出现 `password` 之外的返回值拼装。
3. `auth:auto-unlock` 的返回对象里不含 `password` / `blob` / `masterPassword` 键（跑一次真实调用，断言 `Object.keys(data)` 白名单 ⊆ `{unlocked, vault, reasonCode, reason}`）。
4. `autologin.json` 落盘内容中 `blob` 必须是 `safeStorage` 密文（手动用 `type` 打开文件，肉眼不得出现可读主密码；`blob` 长度随密码变化但内容为二进制 base64）。
5. 渲染层 `localStorage` / `sessionStorage` 快照里不得出现主密码（DevTools → Application → 全量 dump 比对）。

### 2.7 `autologin.json` 落盘格式

路径：`<DATA_DIR>/autologin.json`（`DATA_DIR = resolveDataDir()`，与 `vault.enc` 同目录；**不**进 `settings.json`，**不**进 vault 集合，**不**进备份）。

```json
{
  "v": 1,
  "blob": "AQAAANCMnd8BFdERjHoAwE/Cl+sBAAAA...(base64)",
  "updatedAt": "2026-12-01T02:03:04.000Z"
}
```

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `v` | number | 是 | 固定 `1`；读到其它值 → `reasonCode:'autologin-version-unsupported'` + 停用（**不删**，留待升级迁移） |
| `blob` | string | 是 | `safeStorage.encryptString(masterPassword).toString('base64')`；非空；非 base64 或解不开 → `decrypt-failed` + **自清** |
| `updatedAt` | string | 是 | ISO 8601（`new Date().toISOString()`） |

写入规则：
- 必须 `writeFileAtomic(autologinFile, Buffer.from(json, 'utf8'))`（临时文件 → fsync → rename），避免半截文件被读成「损坏」而误清。
- 写入前 `mkdirSync(path.dirname(file), { recursive: true })`。
- 单文件体积上限：`blob` ≤ 64 KB，超限视为 `write-failed`。
- **禁止**写入的字段：`password`、`masterPassword`、`hint`、`salt`、`hash`、用户名、机器名（DPAPI 已绑定，不需要任何额外标识）。
- 纯函数模块 `electron/autologin.js`（**不 require('electron')**）导出：
  `autologinPath(dataDir)`、`parseAutologin(raw)`、`serializeAutologin(blobBase64, nowISO)`、`isAutoUnlockUsable({ available, suppressed })`。
  上述 4 个函数是 qa 的单测靶点（存/取/清、损坏、版本不支持、抑制位）。

### 2.8 6 个失效时机（漏一条即安全洞，逐条给落点与断言）

| # | 触发点 | 动作 | 必须改的落点 | qa 断言 |
|---|---|---|---|---|
| E1 | `auth:change-password` **成功**（已 `saveVault` 新密码后） | `unlink(autologin.json)`（忽略 ENOENT） | `electron/ipc-auth.js`（`clearCaches()` / `setPassword(newPassword)` 附近） | 改密前 `enabled:true`，改密后 `status.enabled === false`、文件不存在；重启后需登录 |
| E2 | `auth:reset-password` **成功** | `unlink(autologin.json)` | 同上（与 `setPassword(null)` / `setUnlocked(false)` 同一段） | 重置后 `enabled:false`，重启需登录 |
| E3 | `data:migrate` 成功 / `data:reset-location` 成功 | 删**两处**：旧 `DATA_DIR` 与目标目录下的 `autologin.json`（`data:migrate` 只复制白名单文件，`autologin.json` 本就不在复制清单里，但**旧目录那一份必须删**，否则把数据目录改回来就复活） | `electron/ipc-data.js`（`data:migrate` 写 `LOCATION_FILE` 之后；`data:reset-location` 删 `LOCATION_FILE` 之后） | 迁移后 `status.enabled === false`；旧目录里 `autologin.json` 不存在；改回默认目录后仍 `enabled:false` |

| E5 | `auth:auto-unlock` 解密失败（DPAPI 解不开 / blob 非 base64 / `vault` 用解出的密码打不开且非 `vault-corrupt`） | **自清** `unlink(autologin.json)` + 返回 `unlocked:false, reasonCode:'decrypt-failed'`；**不得**卡在启动态 | `electron/ipc-auth.js` + `electron/autologin.js` | 手工把 `autologin.json` 的 `blob` 改成随机 base64 → 重启 → 落到登录页、无错误弹窗、文件被删除 |
| E6 | `safeStorage.isEncryptionAvailable() === false` | 开关**禁用并说明原因**；`enable` 直接 `safe-storage-unavailable`；`auto-unlock` 不执行解密（返回同 code）；**不删**已存在的文件（环境恢复后仍可用）；**绝不**降级成明文 | `electron/ipc-auth.js` 4 处（status / enable / disable 不动 / auto-unlock） | 用 `--disable-features=…` 或桩把 `isEncryptionAvailable` 打成 false → 设置页开关置灰且有原因文案；开启接口返回 `safe-storage-unavailable` |

补充（不属于「6 个必然失效时机」，但必须有明确行为）：

| 场景 | 行为 |
|---|---|
| `auth:is-setup` 返回 false（全新安装） | `auto-unlock` → `not-setup`，无副作用 |
| 用户手工删除 `autologin.json` | `status.enabled:false`，开关显示关闭（无报错） |
| `settings.json` 损坏但 vault 还在（走「解密即验证 + 重建 settings」路径） | 若 `autologin.json` 可解，自动解锁**允许成功**（它能解开 vault 即证明密码对），不强制失效 |
| 应用升级（版本变化） | 不失效（DPAPI 绑定 OS 用户，不绑定应用版本） |

### 2.9 启动时序（`src/App.tsx`）

```
挂载（现 :304-323 的 useEffect 内，在 settingsGet 之前串进来）
 ├─ authIsSetup()
 │   ├─ false → setIsSetup(false) → 登录/初始化页（不查免密）
 │   └─ true  → authAutoUnlockStatus()

 │             └─ unlocked === false    → setLocked(true)（登录页），不弹 toast
```

## 3. R3 卸载入口：2 个 channel 契约

### 3.1 类型定义（写进 `src/types.ts`，命名固定）

```ts
export type UninstallMode = 'installed' | 'dev';
export type UninstallerSource = 'registry-hkcu' | 'registry-hklm' | 'exe-sibling';

export interface UninstallInfo {
  supported: boolean;                       // mode==='installed' 且 uninstaller 可用
  mode: UninstallMode;
  uninstaller: string | null;               // 绝对路径，.exe，已 existsSync 校验
  uninstallerSource: UninstallerSource | null;
  regKey: string | null;                    // 命中的注册表键全路径（供日志/排错，不含用户信息）
  dataDir: string;                          // 绝对路径（resolveDataDir()）
  dataSize: number;                         // 字节；统计失败时为已统计到的部分
  dataBreakdown: { dir: string; size: number }[];  // DATA_DIR 直属子项体积，按 size 降序，最多 8 条
  dataSizeError?: string;                   // 统计超时/权限不足的原因（存在时 dataSize 为下限值）
  productName: string;                      // '测试中台'
  appVersion: string;                       // app.getVersion()
  exePath: string;                          // process.execPath
}

export interface UninstallResult {
  launched: boolean;
  removedData: boolean;
  mode: UninstallMode;
  dataDir: string;
  dataSizeBefore: number;
  removedPaths?: string[];                  // 受管清单里实际删掉的绝对路径
  code?: string;
  error?: string;
  message?: string;                         // dev 模式的「源码目录需自行删除」等提示
}
```

### 3.2 `app:uninstall-info`

| 七要素 | 内容 |
|---|---|
| 方法/通道 | `ipcRenderer.invoke('app:uninstall-info')` → 暴露 `appUninstallInfo: () => Promise<{ success: boolean; data?: UninstallInfo; error?: string; code?: string }>`；注册在**新模块** `electron/ipc-uninstall.js`（`registerUninstallIpc(deps)`） |
| 入参 | 无 |
| 出参 | `data: UninstallInfo`（§3.1） |
| 错误码 | `locked`（`请先解锁应用`）／`info-failed`（`读取卸载信息失败：<原因>`，仅在整体抛异常时，正常降级都写进 `data` 字段） |
| 鉴权 | `appUnlocked === true`（`getPassword() !== null`）。危险区不允许锁屏态被本地其它进程驱动 |
| 幂等 / 并发 | 纯读，幂等；并发安全。体积统计有 2000ms 预算（见 §3.4） |
| 限流 | 无（设置页进入危险区时调 1 次，切换 tab 回来再调 1 次） |

示例：
```json

  "supported": true, "mode": "installed",
  "uninstaller": "C:\\Users\\me\\AppData\\Local\\Programs\\测试中台\\Uninstall 测试中台.exe",
  "uninstallerSource": "exe-sibling", "regKey": null,
  "dataDir": "C:\\Users\\me\\AppData\\Roaming\\测试中台",
  "dataSize": 18432011,
  "dataBreakdown": [{ "dir": "backups", "size": 12582912 }, { "dir": "attachments", "size": 5242880 }],
  "productName": "测试中台", "appVersion": "1.36.0",
  "exePath": "C:\\Users\\me\\AppData\\Local\\Programs\\测试中台\\测试中台.exe" } }
```

### 3.3 `app:uninstall`

| 七要素 | 内容 |
|---|---|
| 方法/通道 | `ipcRenderer.invoke('app:uninstall', payload)` → 暴露 `appUninstall: (data) => …` |
| 入参 | `{ removeData: boolean; dataDirAck?: string }` |
| 入参边界 | `removeData` 必填且必须是 `boolean`（`'true'` 字符串视为 `invalid-argument`）。`removeData === true` 时 `dataDirAck` **必填**，且必须 `path.resolve(ack).toLowerCase() === path.resolve(DATA_DIR).toLowerCase()`（Windows 大小写不敏感） |
| 出参 | `data: UninstallResult`（§3.1） |
| 错误码 | 见 §3.5 表 |
| 鉴权 | ①`appUnlocked === true`；②`dataDirAck` 校验（等价于「用户真的看到了这个路径」）——两者都是删数据的硬闸门 |
| 幂等 / 并发 | **不幂等**（spawn 有副作用）。并发用进程内 `uninstallInFlight = true` 守卫：第二次调用直接 `{success:false, code:'busy', error:'卸载已在进行中'}`。数据删除部分自身幂等（文件不存在不报错）。`uninstallInFlight` 在 spawn 成功后**保持 true 直到应用退出**（卸载器起来后不重置，防止二次点击） |
| 限流 | 靠 `busy` 守卫，无需计数 |

### 3.4 mode 分支矩阵（三种情况，一种都不能缺）

| `app.isPackaged` | 找到卸载器 | `mode` | `supported` | `app:uninstall` 行为 |
|---|---|---|---|---|
| `true` | 是 | `installed` | `true` | `removeData` 为真 → 先删受管清单 → `spawn(uninstaller, [], { detached:true, stdio:'ignore' })` → `unref()` → 立即返回 `{launched:true, removedData:true}`。**不** `app.quit()`（交给卸载器） |
| `true` | 否（如 `release/win-unpacked` 直接跑） | `installed` | `false` | `removeData` 为真 → 只删数据；`launched:false` + `message:'未找到卸载程序，请到「设置 → 应用」里卸载；本地数据已按选择处理'`。**不**凭空猜卸载器路径 |
| `false`（源码 / `npm start`） | 不查 | `dev` | `false` | **不 spawn**；`removeData` 为真 → 只删受管清单；`launched:false` + `message:'当前为源码运行，未执行卸载；源码目录请自行删除'` |

卸载器发现顺序（`electron/uninstall.js` 纯函数 + 注入的 `execFileSync` 查询函数）：
1. `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\*` → `DisplayName === '测试中台'` → 取 `UninstallString`；
2. `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall\*`（32 位应用在 64 位系统上还可能是 `WOW6432Node`，一并查）；
3. 回退：`path.join(path.dirname(process.execPath), 'Uninstall 测试中台.exe')`（`nsis.oneClick:false` + `allowToChangeInstallationDirectory:true` 的默认产物名，`package.json:75-81`）。
`UninstallString` 解析规则：去首尾引号、只取第一个 `"..."` 段或第一个空格前的段、必须是 `.exe` 绝对路径、`fs.existsSync` 为真。查询超时 1500ms，超时按「未找到」处理。
**禁止** `shell: true`；`spawn` 参数一律数组传参（防路径注入）。

数据体积统计（`dataSizeOf(dir)`，纯函数，注入 `readdirSync/statSync`）：
- 递归深度 ≤ 6，条目数 ≤ 20000，总耗时预算 2000ms（到预算就用已统计值 + `dataSizeError:'统计超时，体积为下限值'`）。
- `dataBreakdown` 取 `DATA_DIR` 直属子项（文件与目录）体积，降序，最多 8 条。
- 符号链接 / 无权限目录跳过（计入 `dataSizeError` 说明，不中断）。

### 3.5 删数据前必须回显 + 受管清单

**两层确认（UI 契约，frontend 实现）**：
1. 第一层：「卸载软件」→「是否同时删除本地缓存数据？」三选：**仅卸载程序** / **卸载并删除数据** / **取消**。
2. 第二层（仅当选「删除数据」）：**必须回显** `dataDir` 的**绝对路径** + 格式化体积（如 `18.0 MB`）+ `dataBreakdown` 前 3 项，要求用户点击「确认删除」按钮（`confirmText` 输入确认可选，但路径回显**必做**）。回显的绝对路径必须来自 `app:uninstall-info` 的 `data.dataDir`，**不得**在渲染层自己拼路径。
3. 调用 `app:uninstall` 时必须把回显的那个字符串原样作为 `dataDirAck` 传回（防「弹框期间数据目录被迁移」的路径竞态）。

**受管删除清单**（`listManagedDataPaths(dataDir)` 单一函数定义，禁止在 handler 里散写）：

| 类型 | 条目 |
|---|---|
| 文件 | `vault.enc`、`vault.enc.bak`、`trash.enc`、`trash.enc.bak`、`settings.json`、`audit.log`、`window-state.json`、`autologin.json`、`clipboard.enc`、`cases.json` |
| 目录 | `backups/`、`attachments/`、`logs/`、`background/`、`update/` |

- 只删清单内条目；清单外的文件**一律不动**（用户自选数据目录里混放的文件不会被误删）。
- 每个目标删前 `fs.realpathSync` 校验「仍在 `DATA_DIR` 之下」（防目录软链逃逸）；越界跳过并记日志。
- 删除后若 `DATA_DIR` 变空，只尝试 `rmdir`（非递归），失败保留目录。
- **绝对禁止**：递归删除 `DATA_DIR` 整个目录、删除源码目录、删除 `DEFAULT_ATTACH_DIR`（自定义附件目录在数据目录之外时**不在**删除范围，须在弹框里注明「自定义附件目录不会删除」）。

### 3.6 卸载流程的禁止事项

1. 不 `app.quit()` / 不 `app.exit()`（抢先退出会让卸载器拿不到锁）。
2. 卸载流程中不写盘：不调 `settingsSave` / `saveVault` / `appendAudit`（**只**写应用日志）。
3. 不对 `uninstaller` 用 `shell: true`、不拼 `cmd /c`。
4. 不在 `mode === 'dev'` 时 spawn 任何东西。
5. 不把 `dataDir` 之外（含 `USER_DATA_DIR` 在自定义数据目录场景下的那份）算进 `dataSize`。

### 4.2 `glassStrength` 契约

### 4.3 老数据兼容矩阵（缺字段时的默认，逐条可断言）

|---|---|---|---|
| 没有 `glassStrength` 键（v1.36 老库） | `0.6` | 滑块在 60% | 升级后进外观 tab 不报错，保存一次后键被写回 |

| `glassStrength: "0.8"`（字符串） | `0.8`（`Number()` 接受） | 80% | 保存后归一成数字 |

## 7. 架构决定（Deliberate Decisions，评审时按此裁决，不算遗漏）

| # | 决定 | 理由 |
|---|---|---|
| D1 | `SettingsTab` / `LEGACY_TAB_MAP` / `normalizeSettingsTab` 从 `Settings.tsx` 下沉到 `src/utils/settingsTab.ts` | 方案要求「tab 归一化单测覆盖全部历史 id」；`Settings.tsx` 有 2522 行且 import React/Modal/Toast，无法单测。下沉后纯函数可测、可复用（未来深链/命令面板跳设置页） |
| D2 | `autologin` 状态**不进** `AppSettings` | 单一真源 = `autologin.json`。写进 settings 会出现「settings 说 enabled、文件已被失效时机删掉」的双真源漂移，且 `settings.json` 会被 `data:migrate` 复制/被备份带走，语义还错了 |
| D3 | `auth:auto-unlock` 的 `unlocked:false` 返回 `success:true` | 「没自动解锁」是正常态（用户关过 / 锁过 / DPAPI 不可用），不是错误。用 `success:false` 会让启动路径弹错误框，正好违反方案「不得卡在启动态」 |
| D4 | 开启免密要求「已解锁 + 再验一次主密码」，失败计数与登录限速**分开** | 设置页本身在 Dashboard 内（已解锁）；再验一次防「有人趁解锁态走开改开关」。计数分开是因为「设置页输错密码把登录锁 30 秒」是明显的体验事故 |
| D5 | 删数据走**受管清单**，不递归删 `DATA_DIR` | 数据目录可被用户改到任意盘任意目录（`data:migrate`），递归删有误删风险；清单制让 qa 能断言「删除前后只少清单内文件」 |
| D6 | `uninstallInFlight` 守卫 + `dataDirAck` 路径校验 | spawn 无幂等；`dataDirAck` 防「弹框期间把数据目录迁走」导致删错路径（`data:migrate` 与卸载可并发） |
| D7 | `electron/autologin.js` / `electron/uninstall.js` **不 `require('electron')`**，`safeStorage`/`isPackaged`/`execPath`/`execFileSync` 全部注入 | 单测在 vitest 里跑（无 Electron 运行时），这是本项目「纯函数下沉」约定（`docs/agents/code-conventions.md`） |
| D8 | 6 个 channel 一次性由一个分片改完 `preload.js` + `types.ts` | 两个分片各加一半会让 `check-ipc` 在中间态红，且 `types.ts` 是共享热点 |
| D9 | 设置页免密卡 / 卸载卡拆成独立组件文件 | 让 `Settings.tsx`（S2）只做骨架，S3/S4 能并行且 inScope 不重叠 |
