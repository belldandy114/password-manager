## 2. 页面骨架约定（4 页共用）

### 2.1 三层结构（每页同构，评审按同一张图对）

```
src/pages/<Page>.tsx            ← 外层壳：只有 <div.content-area> + <Page> + provider + 结果态（≤60 行）
  └ <ToolShellProvider toolId="page.<pageKey>" onResult={setResultText}>
      └ <PageBody/>           ← 内层体（同文件内或独立文件）：PageHead(tools=ResultActions) + .tabs/.tab2 页签 + 激活面板
          └ <Tab/>            ← 一个页签一个组件文件（src/components/<area>/）
```

为什么必须这层 provider：`useToolState` 的命名空间来自 `ToolShellProvider` 的 `toolId`
（`shell.tsx:43` 的 `NS` + `:50-51` 的 `storageKey = pm.toolbox.<toolId>.<key>`）；**没包 provider 时默认 toolId 是 `'toolbox'`**
（`shell.tsx:19`），4 个页面 + 工具箱会共用 `pm.toolbox.toolbox.*` 这一格 —— 两页用同名 key
（如 `'tab'`）就会互相覆盖，且**不会报错**。这是本批最容易出的静默 bug，故写死：
`toolId` 一律 `page.codeGen` / `page.codeAudit` / `page.assetLedger` / `page.resultHub`。

### 2.2 状态归属决策表

| 状态 | 放哪 | 理由 / 注意 |
|---|---|---|
| 页签 id | `useToolState('tab', <默认>)` | 切页签/切页面不丢；值域用字面量联合类型 |
| 表单草稿（OpenAPI 文本、元素库编辑行、并发参数、筛选条件） | `useToolState` | hook 已做「≤16 KB 同步写、>16 KB 180 ms 去抖」（`shell.tsx:46-47,50-98`） |
| 运行结果（findings / coverage items / allure cases / jtl 指标 / 生成代码） | **局部 `useState`** | 体积大（findings 300 / items 5000），写 sessionStorage 会顶爆 5 MB 配额。**切页签即丢** —— 这是有意的，结果可一键重跑；持久化的部分是 5 个集合里的「运行记录」 |
| 持久集合 | `useCollection('scanRuns')` 等 | `save()` 返回主进程结果，**必须判错**（`useCollection.tsx:21-24`） |
| 运行中标志 / 进度数 / 已取消 | `useRef` + `useState` | 不持久化；`token` 用 `crypto.randomUUID()`（`[C-55]`） |
| 取消 token | `useRef<string>` | 与 `scanCancel({token})` 成对；卸载/完成后清空 |
| 跨页意图（ApiClient → CodeGen 的文本） | store `codegenSeed`（W1 一次性加，§4.6） | 与既有 `apiBodySeed` 同模式（`useStore.ts:212`） |
| 全局设置（主题等） | `useStore` | 不新增 |

**只渲染激活页签**（与 `NotesAttachments.tsx:99` 同模式）→ 面板内的 `useState` 会被卸载清空，
所以**任何需要跨页签保留的输入必须走 `useToolState`**；页面里出现裸 `useState` 存用户输入即评审不通过。

### 2.3 加载 / 错误 / 取消的统一写法（每条新 IPC 调用照抄）

```ts
const r = await callIpc(() => window.electronAPI.scanRun({ root, pack, token }));
if (!r.ok) { if (r.raw?.canceled) return; setErr(r.error); addToast(r.error, 'error'); return; }
```
- `canceled` → **静默**（G1/G3）；
- 失败 → 同时写「页内错误行（`role="alert"`）」+ toast。为什么不只 toast：`src/components/Toast.tsx` **没有任何
  `role`/`aria-live`**（已核），屏读用户听不到；页内 `role="alert"` 是可达性的兜底。

## 7. 10 万条造数的前端分批方案

### 7.1 分批算法（纯函数，`src/utils/tdg/stream.ts`）

```ts
export const STREAM_BATCH_SIZE = 5000;                  // [C-67] 每批 ≤ 5000
export interface ChunkRange { index: number; offset: number; count: number }
export function chunkRanges(total: number, batchSize?: number): ChunkRange[];
export const STREAM_LIMITS = { maxRows: 1_000_000, maxBytes: 512 * 1024 * 1024, maxRowBytes: 64 * 1024 };
export function dedupeAcrossBatch(seen: Set<string>, values: string[]): string[];   // 跨批去重
export type RowFormat = 'csv' | 'json' | 'txt';
export function headerLine(format: RowFormat, columns: string[]): string | null;     // csv 有表头，json/txt 无
export function formatRows(values: string[], format: RowFormat, columns: string[]): string[];
export function assertRowBytes(rows: string[]): { ok: true } | { ok: false; error: string };
```
单测下限（`src/utils/__tests__/tdgStream.test.ts`，≥ 12 条）：`chunkRanges` 对 `0/1/4999/5000/5001/100000`
的批数、`sum(count) === total`、相邻 offset 连续不重不漏；`batchSize` 缺省 5000；`dedupeAcrossBatch` 跨批；
`formatRows` 三种格式（csv 引号翻倍 `""`、json 保持原串、txt 原样）；`assertRowBytes` 恰好 64 KB 通过 / 超 1 字节拒绝。

### 7.2 状态机（页面侧）

```
idle ──点「开始」──> preparing（拿 savePath；canceled → idle）
     ──> writing（循环：生成一批 → 追加一批 → 更新进度）
     ──成功──> finished（toast 成功 + 展示行数/字节/耗时）
     ──用户取消 / 卸载 / 出错──> aborting（writeAbort）──> idle（提示「已取消，未留下半成品」）
```
- `savePath` 先由渲染层取：`dialogSaveFile({defaultName, filters})`（`types.ts:1442`），`canceled` → 回 `idle` 且**不弹错**；
- `tdgWriteStart({savePath, format, columns, bom})` → `writerId`；
- `writerId` 存 `useRef`；**任何退出路径都必须 `tdgWriteAbort`**（含 `useEffect` 卸载清理、出错 catch）；
- 主进程自己也会在下一个 `write-start` 时 abort 旧 writer（`[C-66]`），但渲染层不许依赖这一点（否则「关页面 = 留半成品」）。

### 7.3 进度与取消（交互确定性）

- 进度 = `done / total`（两个整数），每批追加成功后才 +batch（**不要乐观加**：写盘失败时进度不能虚高）；
- 批与批之间必须让出主线程：`await new Promise(r => setTimeout(r, 0))`（生成是同步的，
  不让出的话「取消按钮点不动」，与 `[C-51]` 同一个坑）；
- 取消按钮：点击后立刻 `disabled` + 文案「正在取消…」，等 `writeAbort` 返回再回 `idle`（**不给 0 反馈的二次点击**）；
- 取消后焦点回到「开始」按钮（`ref.current?.focus()`），屏读用户才知道操作结束；
- 失败：`setErr(error)` + `role="alert"` 行 + toast；错误文案直接用主进程的（`[C-69]` 逐条固定），前端不改写。

### 7.4 格式与限制（写死）

| 目标行数 | 允许格式 | 说明 |
|---|---|---|
| ≤ 5000 | `csv/json/txt/sql/md/xlsx` | 走既有 `exportData`（`utils/tdg/export.ts:181`）+ `fileWrite`，行为一行不改 |
| > 5000 | **仅** `csv/json/txt` | 走 `tdg:write-*` 流式；`sql/md/xlsx` 选项 `disabled` 并显示原因（§6.3） |

- 行拼装**在渲染层**（`[C-68]`）：`csv` → 每行一份记录、主进程补 `\r\n` 与表头；`json` → 每行一个 JSON 值，
  主进程补 `[` / `,` / `]`；`txt` → 每行原字符串；
- 单行 > 64 KB → 本地先拦（`assertRowBytes`）：提示 `单行超过 64 KB，已拒绝（当前 <N> KB）` 并中止整次导出
  （不改长度继续写半份，那样用户拿到的是残缺数据）；
- 总行数 > 1,000,000 或预计字节 > 512 MB → 在开始前就拦下，提示降行数（不要等写到一半才报）。

### 7.5 去重与值域不足（R1）

- 勾「去重」时用**跨批共享的 `Set<string>`**（一批一批往里加），不是每批各自去重（`utils/tdg/index.ts` 的
  `deduplicate` 是单数组去重，直接按批调用会出现**跨批重复**）；
- 连续 3 批新增为 0（值域耗尽，如车牌 / 银行卡品牌组合）→ 主动停：
  `该类型可用值不足，实际生成 <N> 条（已停止，未达目标 <total> 条）`，并**照常 finish**（已生成的部分是有效数据，
  不留 `.part`，也不假装成功）；
- 未勾去重时不检测值域（重复是用户要的）。
