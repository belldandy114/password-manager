## 0. 先说三条结论

1. **SQL 片段页到此为止**。第 2 批 5 项交付后冻结，不再加功能（判据见 §1）。
2. **真正的缺口不在「缺功能」，在「证据散」**：执行结果分散在批量运行内存、回归快照（只留最近 20 次）、压测报告目录、用例库文件、禅道五处。一次测试做完，人要在脑子里拼图。这是 P0。
3. **市面上那套「自动化测试」你已经有一半以上**（接口批量运行 + 断言 + 变量提取 + 回归集 + 定时 + 基线比对 + MD 报告）。该补的是**执行记录与去噪**，不是再引一套框架。

## 1. 判据：一个功能值不值得做

三条同时满足才做，缺一条就进 P2：

| 判据 | 说明 | 反例 |
|---|---|---|
| 频次 | 每周至少用 3 次，或每次省 ≥2 分钟 | 「导出 PDF」一年用两次 |
| 出错成本 | 不做会漏测 / 漏缺陷 / 造错数据 | 「深色主题换色」出错只是不好看 |
| 维护债 | 引入后长期能自己维护（无外部服务、无自动升级的重依赖） | 「接一个云同步」= 终身运维 |

配套的**不做判据**：单人工具里「多人协作 / 权限 / 审批流」一律不做；「把手工点一遍的东西全自动化」一律不做（维护成本吃掉收益）。

## 3. 优化清单

### P0（建议下一批做；都是"省时间"，不是"加面板"）

#### P0-1 统一执行记录：一次测试 = 一条可贴进缺陷单的记录

- **问题**：断言结果在批量运行结果弹窗（内存/最近 20 次快照）、压测在报告目录、用例是文件、缺陷在禅道。举证要人工拼。
- **做什么**：
  1. 执行记录集合（进 vault，随库加密）：`{ id, 时间, 来源(接口批量/回归集/压测/手工), 关联用例编号?, 条目明细(请求摘要/断言/响应片段 300 字), 结论, 缺陷编号? }`；
  2. 一个「生成缺陷单文本」按钮：把选中记录转成 md（现象 / 复现步骤 / 期望 / 实际 / 请求响应片段），直接贴禅道；
  3. 用例页可回挂：用例编号 ↔ 最近一次执行记录（与 P1-1 合并）。
- **判据**：你现在每周为"凑一份缺陷证据"花 ≥3 次人工；做完省的是每天 5~10 分钟。
- **改动面**：`useCollection` 新集合 + 3 个页面接线（ApiClient / PerfTest / Cases）+ 一个纯函数 `buildDefectText(record)`（可单测）。
- **成本**：中（2~3 人日）；风险：记录里可能带敏感数据（手机号/token）→ 落盘前必须脱敏（复用 `settings` 的脱敏口径 + 写测试）。
- **状态**：未做。

#### P0-2 造数可回收（生成 → 台账 → 一键清理）

- **问题**：生成器只管造。删数据集时的原文是「只删这份配置，不影响已生成的数据」（`DataGenerator.tsx:838`），所以造完只能手工删。
- **做什么**：生成时按「数据集 / 批次」记一条台账（主键值 + 回滚方式：SQL 模板或接口），支持"本批次全清"；台账同样进 vault。
- **判据**：每次造数后都要手工清场（当前就是）；不清会污染后续用例。
- **改动面**：`DataGenerator.tsx` + 新纯函数 `buildCleanupPlan(fields)` + 台账集合；不接数据库执行（只生成可复制的清理语句，避免"工具直连生产库"的安全边界问题）。
- **成本**：中（1~2 人日）；风险：台账里存主键=存业务数据 → 只存生成规则与主键，不存整行。
- **状态**：未做。

#### P0-3 回归失败去噪

- **问题**：回归失败只进工作台/提醒一条待办；点进去还要自己找是哪条断言、响应长什么样、跟上次差异。
- **做什么**：失败卡片直接带「第 N 条请求 · 断言 X 失败（期望 200，实际 502）· 响应前 300 字」+「只重跑这一条」+「与上次对比」。
- **判据**：每次回归红都要点 3 次以上才能定位。
- **改动面**：`ApiClient.tsx` 回归结果区 + `Home.tsx` 面板文案 + `apiRunner.ts` 已有 `AssertResult`（够用）。
- **成本**：小（0.5~1 人日）；风险：低。
- **状态**：未做。

### P1（有触发条件再做）

#### P1-1 用例库的执行状态（与 P0-1 同源）

- **问题**：`Cases.tsx` 只有文件树与预览，**没有**执行状态字段（已核实）。
- **触发条件**：P0-1 落地后，把「用例编号 ↔ 执行记录」做成用例行的一个小徽标（通过/失败/未跑）。
- **成本**：小；风险：用例是文件驱动，状态要存 vault 并做"文件被改名/删除"的清理。

#### P1-2 修 `scripts/lib/app.js` 的 `navTo()`（qa 已证实，优先级实际是 P0 级）

- **问题**：就绪判据两半失效（`.page-loading` 不存在 + `PageSkeleton` 自己渲染 `.pg`），`navTo` 提前返回，后续 `clickText` 落空且返回值被丢弃 → **所有 `scripts/ui-*.js` 都有假绿风险**。
- **同类第二例（qa t4 实测）**：窗口被遮挡/合成器节流时 **CSS 动画停在起始帧 `opacity:0`**，而扫描器对 `opacity===0` 的容器**整棵子树跳过** → 每页只剩 1 个块、弹窗"永远打不开"，表现为假绿。`document.getAnimations().finish()` 后立刻恢复正常。**凡是断言「可见 / opacity」的脚本都会被这个坑到**，与 navTo 并列。
- **做什么**：按页写死就绪判据 + 让 `clickText` 返回 false 必须失败 + 统一在断言前 `getAnimations().finish()`（或先设 `Animation.setPlaybackRate(0)` 再收尾）；顺带删掉各脚本里的固定 sleep。
- **成本**：小~中；风险：改完全量回归脚本可能一次性变红（那是好事——说明以前是假绿）。
- **状态**：第二批已修掉 `ui-glass-opaque-scan.js` 这一处（含 `settleAnimations()`）；公共库 `scripts/lib/app.js` 与其余 `ui-*.js` 未动。

#### P1-3 环境 / 库词表统一

- **问题**：`environments`（系统 + envType + url）与 SQL 片段的 `dbOrEnv`、接口调试的环境名是**三套手输词表**，拼错就搜不到、统计断。
- **做什么**：抽一份「库 / 环境」候选词表（来自三处已有值的并集，可点选、可新填），先只做 SQL 片段与接口环境两处。
- **成本**：小；风险：词表会膨胀，需要"最近使用 + 上限"。

#### P1-4 压测结果落库并做阈值比对

- **问题**：压测报告在目录里，跨次对比靠人看 HTML。
- **做什么**：跑完把 P95 / 错误率 / TPS 落一条记录（复用 P0-1 的记录集合），下次给"比上次 ↑/↓"。
- **成本**：小~中；风险：JMeter 版本差异导致字段解析失败 → 缺字段就整条跳过，不算失败。

#### P1-5 提醒中心收口

- **问题**：回归/巡检/备份已有提醒，压测与 SQL 执行记录没有；`NoticeCenter` 是否已收口全部来源未核实。
- **做什么**：统一来源枚举 + 一次性清理；不做推送。

## 4. 明确不做（附理由，防止反复讨论）

| 想法 | 为什么不做 |
|---|---|
| **UI 自动化铺开（Selenium/Playwright 给被测系统写脚本）** | 选择器随被测系统改版就红，维护成本 > 收益；最多保留 2~3 条主链路冒烟。你"麻烦、用处不大"的直觉对**这一层**是对的。 |
| **SQL 执行引擎（片段页直接连库跑）** | 无连接管理、无权限模型、误执行生产库风险高；而且和"复制粘贴"的价值重叠。 |
| **云同步 / 多人协作 / 账号体系** | 与本产品定位（本地加密、离线、单人）冲突；引入后要背合规与运维。 |
| **插件市场** | 单人工具的插件生态 = 长期维护税（API 兼容、安全审查）。 |
| **AI 直接生成用例并入库** | 生成质量无法机械判定，评审成本可能高于手写；可作为"离线外挂"（导出给 AI，人工筛）而不是本体功能。 |
| **跨平台（mac/Linux）** | 托盘、单实例、剪贴板、快捷键全是按 Win 写的，迁移成本高且无明确需求。 |
| **再给 SQL 片段加功能** | 它解决「存 → 找 → 复制」，已闭环；执行/分享/版本历史都会进"维护债"区。 |
