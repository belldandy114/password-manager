## 2. 逐文件判定

### 2.1 `shared/locatorModes.js`（173 行）→ **抄思路重写**

上游这个文件的价值不在代码，在**口径**：定位方式的顺序、归一兜底、role 的「角色:名称」拆法、`AriaRole` 的降级策略。它的代码 173 行里有 60 行是 Python 侧映射与预览拼接，本批**全部作废**（`[N-4]`：`lang` 只接受 `java`，界面不得有语种选择器）。

#### 逐符号对照（每个「抄」都指到函数名）

| 上游符号（行号） | 判定 | 本项目落点 | 理由 / 改造点 |

#### 不能照搬的写法（环境差异增量）

1. **「一份 JS 清单随便改」**：上游没有类型、没有第二消费者，所以改清单不会红；本项目清单有 3 个消费者（TS 生成器 / CJS 校验 / `.d.ts` 的 `ElKind`），照抄它的「单文件 Set」会导致 `[A0-5]` 的 parity 单测失去意义。
2. **`ARIA_ROLES` 是 `Set` + 自拼字符串**：本项目契约要求 82 项**可枚举、可计数**（`[A1-1]` 的验收方式是数条数），`Set` 的 `.size` 不够 —— 要 `readonly string[]` 才能被 golden 与单测逐项断言。
3. **`previewLocatorCode` 直接返回拼好的字符串**：TS 严格 + `element-args.js` 的 `ERR` 真源要求「校验与生成分离」，界面拿不到「为什么不能生成」的原因。

#### 最小可用子集（本批要的 / 砍掉的）

- **要**：`LOCATOR_MODES` 顺序、`normalizeLocatorMode`、`splitRoleSelector`、`ariaRoleExpr` 规则、`ARIA_ROLES` 清单（以 Java 为准人工核一次）。
- **砍**：`SEMANTIC_METHOD`、`previewLocatorCode` 的 python 分支、`escapeDoubleQuoted` 的重复实现（本项目已有）。

### 2.2 `electron/sniffer/highlight.js`（788 行）→ **抄思路重写**

这个文件是**重写幅度最大**的一个：它的 788 行里，有 **470 行是 `RUNTIME` 那段常驻注入脚本**（127-698），而本项目的契约 `[A2-7]` 把它的两个核心机制**整块禁掉**了：

- 上游靠 `Page.addScriptToEvaluateOnNewDocument` + `Runtime.evaluate(包一层 IIFE)` 把脚本**常驻**进页面（`browser-session.js:applyHighlight` 1178-1221）→ 契约 [A2-7] **禁止**该 CDP 方法；
